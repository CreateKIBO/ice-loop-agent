## 0. 完成标准

v2.0 不是重写，也不是把文件拆碎凑工作量。完成后，同一套桌面程序必须多出这些能用的能力：

1. 写作节点优先产出可校验的文章中间表示，再渲染成现有 Markdown 契约；校验失败时自动退回现有直写路径，任务不因此整篇失败。
2. 已完成文章沉淀为栏目记忆，新稿能检索最近期次、标题、动手题和下期预告，并把有限摘录注入调研和起草。
3. 正文编辑时能看到与规则引擎一致的结构、品牌和事实诊断。
4. 长任务有进度事件和任务时间线，界面不再只靠一次阻塞调用。
5. 封面只在已有栏目模板上叠加期号和标题，不重绘标识。
6. 本地排版预览接近公众号阅读宽度和行距，仍不自动发布。
7. 命令行评测能用固定样例判断规则是否被放宽。
8. 旧的 1.5.3 数据库能打开，迁移前留有一次性备份；现有测试不删、不放宽。

版本号只在最后一阶段改为 `2.0.0`。中途失败就停在当前阶段，不要带着失败测试继续加功能。

## 2. 必须守住的产品行为

这些是现有程序的正确行为。新代码要接在上面，不能换掉。

1. 审核门仍是 `topic`、`outline`、`final_title`、`asset_plan`。决定和内容哈希绑定。没有决定、关闭窗口、超时，都不算批准。
2. 正文里的运行输出只来自 RunRecord。模型只能写占位符。占位符语法以现有 `integrate_evidence` 为准。
3. 生图、截图和其他外部副作用继续走 `ice_agent/ledger/operations.py`。同一 `operation_key` 不得重复提交。
4. 补图任务（`spec.image_only`）不得进入改写正文的流水线。
5. API Key 只在 Electron `safeStorage` 和主进程内存中出现。渲染进程、SQLite、事件、日志、异常文本里不得出现 Key 或 `Authorization`。
6. SQL 语句保持字符串字面量，值用 `?`。更新列继续走白名单。
7. 工作区、导出、代码运行目录必须是 C 盘以外的绝对路径。沿用 `assert_not_c_drive`。
8. 品牌规则不放宽：禁用词、破折号 0 处、弯引号改为「」、情绪标点禁用、WK 工具文零价格零额度、高风险字段没有已核验断言就不能就绪导出。冒号对 ICE Loop 放行，这是既有裁定，不要改成全面禁冒号。
9. 演示代码仍是每篇 1–3 段、单段不超过 20 行、2–4 行关键注释。篇首承接上篇答案的摘录，以及 `code/` 里的完整源文件，不占这段配额。
10. 桌面主界面继续加载随程序分发的本地页面。不要从 CDN 拉脚本或字体。
11. 微信公众号正式发布、TapNow 点击提交、购买额度，本轮保持人工。

## 6. 桌面协议扩展

现有请求仍是一行 JSON：`{"id": <整数>, "method": "...", "params": {...}}`。  
现有成功响应仍是：`{"id": <同一整数>, "result": ...}`。  
现有失败响应仍是：`{"id": <同一整数>, "error": {"message": "..."}}`。字段名以 `main.cjs` 里现有解析为准；若现有错误形状不同，保持现有形状，不要发明第二套。

新增进度行，没有 `id`：

```json
{"event":"job.progress","job_id":"job-...","payload":{"node":"draft","phase":"model","detail":"正在起草"}}
```

`main.cjs` 读到没有 `id`、且有 `event` 的行时，转发给渲染进程，不得当成未知 RPC 去 `pending` 里报错。没有监听器时，引擎照常把最终结果写回带 `id` 的响应。

心跳：单次模型调用超过 15 秒时，每 15 秒写一条 `job.progress`，`phase` 为 `heartbeat`。这不增加 `model_invocations` 计数。

超时：`main.cjs` 维持默认 135000 毫秒。仅为这些方法单独放到 300000 毫秒：`jobs.resume`、`chat.send`、`articles.semantic_review`、`jobs.create`。其他方法不要一起放宽。心跳存在时，界面显示「仍在生成」，而不是无限转圈且没有说明。

`bootstrap` 的返回里增加 `capabilities: ["job-progress-v1","article-ir-v1","series-memory-v1"]`。旧字段保留。`PROTOCOL_VERSION` 维持 1。

新 RPC 必须同时登记两处，否则桌面能调、引擎没有，或引擎有了、主进程拒绝：

- `ice_agent/desktop_service.py` 的 `dispatch`
- `desktop/main.cjs` 的 `methods`

本轮新增方法只有：

| 方法 | 作用 |
|---|---|
| `articles.lint` | 对一篇 Markdown 跑现有规则，返回诊断 |
| `memory.search` | 检索栏目记忆 |
| `memory.list` | 按栏目列出最近记忆 |
| `jobs.timeline` | 返回步骤、事件和模型调用摘要 |
| `covers.compose` | 在模板上叠加期号和标题 |
| `covers.layouts` | 返回四栏目的叠字区域 |

评测不进桌面 RPC，只留命令行，避免桌面暴露任意执行入口。

## 7. 数据库迁移

当前打开逻辑：`user_version > 9` 直接拒绝；小于 9 且已有 `articles` 时，先备份为 `*-before-v1.0.db`；版本不是 9 才写入 `user_version`。频繁打开不得重复抢写锁。这个行为保留。

v2.0 的迁移从 9 升到 12，每一步一个函数，失败则回滚该事务。第一次从 9 往上升之前，若备份文件还不存在，把整个库复制为：

`<原名>-before-v2.0.db`

备份已存在则不再覆盖。程序不得删除这份备份。

迁移后的 `user_version` 为 12。大于 12 的库仍拒绝用本引擎打开，错误句写明「数据库来自较新版本」。

### 7.1 版本 10：栏目记忆

```sql
CREATE TABLE IF NOT EXISTS series_memory (
    memory_id TEXT PRIMARY KEY,
    account_id TEXT NOT NULL DEFAULT '',
    series TEXT NOT NULL,
    episode INTEGER NOT NULL,
    article_id TEXT NOT NULL,
    title TEXT NOT NULL,
    headings_json TEXT NOT NULL,
    exercise_text TEXT NOT NULL DEFAULT '',
    next_preview TEXT NOT NULL DEFAULT '',
    languages_json TEXT NOT NULL DEFAULT '[]',
    body_excerpt TEXT NOT NULL DEFAULT '',
    content_hash TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE(account_id, series, episode, article_id)
);
CREATE INDEX IF NOT EXISTS idx_series_memory_lookup
    ON series_memory(account_id, series, episode);
```

`account_id` 的填法以决策文档为准。若一库只服务一个工作区，就写入当前公众号 id；找不到时用空字符串，不得丢弃文章。

### 7.2 版本 11：检索

仅当探测确认 trigram 可用时执行。虚拟表不要放进一条必定执行的 `executescript`，以免旧 SQLite 让整个程序无法启动。

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS series_memory_fts USING fts5(
    memory_id UNINDEXED,
    title,
    headings,
    exercise_text,
    next_preview,
    body_excerpt,
    tokenize='trigram'
);
```

内容变更时，同一事务里删除该 `memory_id` 的旧 FTS 行再插入。FTS 不可用时跳过本步，`user_version` 仍可到 12，设置中记录 `search_backend = "like"`。

### 7.3 版本 12：提示词快照

不改 `jobs` 的既有列。快照放在任务状态 JSON（现有 checkpoint / state）的 `prompt_snapshots` 字段。版本 12 只增加一张可选审计表：

```sql
CREATE TABLE IF NOT EXISTS prompt_snapshots (
    snapshot_id TEXT PRIMARY KEY,
    job_id TEXT NOT NULL,
    prompt_id TEXT NOT NULL,
    prompt_version INTEGER NOT NULL,
    content_hash TEXT NOT NULL,
    created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_prompt_snapshots_job
    ON prompt_snapshots(job_id, prompt_id);
```

这里只存哈希和版本，不存 API Key，不存整段用户文章。

测试要求：用只含版本 9 表结构的临时库打开，确认备份文件出现、`user_version` 变为 12、原 `articles` 行还在。再打开一次，确认备份文件大小不变。

## 8. 文章中间表示 IR v1

新模块：`ice_agent/article_ir.py`。  
渲染结果必须能被现有 `rules` 和 `export` 接受。IR 是内部产物，00–03 对外仍是 Markdown。

### 8.1 形状

```json
{
  "ir_version": 1,
  "title": "不超过30字的标题",
  "abstract": "54到120字的摘要",
  "series": "PY",
  "episode": 5,
  "brand_line": "一次循环",
  "blocks": []
}
```

`blocks` 只允许这些 `type`：

| type | 字段 | 渲染结果 |
|---|---|---|
| `paragraph` | `text` | 普通段落 |
| `heading` | `level` 为 2 或 3，`text` | `## ` 或 `### ` |
| `code` | `lang`、`filename`、`source` | 围栏代码块；`filename` 写入 `code/` 的文件名，须是安全文件名 |
| `run_placeholder` | `run_key` | 现有运行输出占位，不得内含伪造 stdout |
| `figure` | `no`、`caption`、`obtain` | 现有图片占位语法 |

`title` 渲染成全文唯一的 `#`。`blocks` 里不得再出现一级标题。`obtain` 只允许 `cover_template`、`run_view`、`generate`、`manual`。

`brand_line` 渲染成结尾段：`**可执行的想象，从<brand_line>开始。**`。`brand_line` 本身不得包含 `可执行的想象`、星号或换行。

`## 写在最后` 必须是一个 `heading`。其后面的段落要能被现有规则认出 ICE 循环回顾、下期预告和关注引导。不要在渲染器里偷偷补一句让违规稿变成合规稿。缺了就让规则报错，再走修复或回退。

### 8.2 校验

`validate_ir(payload, profile) -> list[Issue]`，每条 Issue 含 `code`、`message`。至少检查：

- `ir_version == 1`，`series` 属于 `PY`、`JV`、`AI`、`WK`，`episode` 是 1–9999 的整数。
- 标题不超过档案里的 `title_max_chars`，摘要长度落在 `abstract_chars`。
- 代码块数量与行数、注释行数符合档案。注释行以源码里以 `#` 或 `//` 开头的行为准。
- `run_placeholder.run_key` 匹配 `run-` 加数字，且该块没有 `stdout` 字段。
- 渲染后的 Markdown 调用现有 `run_all_checks`。规则的 `block` 级问题并入 Issue。
- 文件名不得含路径分隔符、盘符或 `..`。

`render_ir(payload) -> str` 是纯函数。同一输入得到同一字符串。

### 8.3 接入起草

只改 `node_draft` 的生成后半段，节点顺序不变。

1. 要求模型输出 IR JSON。提示词里给出 8.1 的字段表和当前档案的数字限制。
2. 解析失败或 `validate_ir` 有 `block` 级问题时，把 Issue 列表再送一次修复。修复次数计入现有 `max_auto_revision_rounds`，不得另外放宽。
3. 仍然无效时，走该节点今天已有的 Markdown 生成路径，在任务状态写 `ir_fallback: true` 和原因码，任务继续。
4. 有效时，把渲染结果当作草稿正文，并在状态写 `ir_fallback: false` 与 IR 哈希。
5. `verify_code` 仍只执行 `code` 块对应的源文件。`integrate_evidence` 仍只回填真实 RunRecord。

`node_topic`、`node_outline`、`node_title_workshop` 本轮不改成 IR。标题工坊继续产出候选标题。

离线 Mock 增加一条 IR 样例，使 `python -m ice_agent demo` 在不配置 Key 时仍能走通 IR 路径。Mock 不得请求网络。

## 9. 栏目记忆与检索

新模块：`ice_agent/series_memory.py`。

在 `node_export` 成功写出文章包之后提取记忆，提取失败只记事件 `memory.extract_failed`，不把已导出的稿打回草稿。

提取来源是渲染后的正文，用现有 Markdown AST：

- 唯一 H1 作为标题。
- H2/H3 文本列表，最多 40 条，写入 `headings_json`。
- 含「动手」或「练习」的小节正文，最多 800 字，写入 `exercise_text`。没有则为空。
- 含「下期预告」的段落，最多 300 字，写入 `next_preview`。
- 代码围栏语言去重后写入 `languages_json`。
- 去掉代码块后的正文前 1200 字写入 `body_excerpt`。

同一 `account_id + series + episode + article_id` 再次导出时更新该行，不插入重复。`content_hash` 用现有 `sha256_text`。

起草和调研的上下文按这个顺序拼接，总长不超过 6000 个字符，超出则从检索命中末尾截断：

1. 当前任务已确认的大纲和标题。有冲突时以人工确认内容为准。
2. 同一栏目、期号小于本期、最近 1 期的记忆：标题、动手题、下期预告。
3. `memory.search` 的最多 5 条命中，去掉本期。每条只带标题和不超过 180 字的片段。

提示词中写明：这些是已有篇目的摘录，用来避免重复和接上期练习；不得把摘录里的仓库地址写进新正文。注入块若含 `github.com/CreateKIBO`，整段丢弃并记一条警告。

`editorial_topics` 仍是选题大纲的来源。不要把大纲表并进 `series_memory`。两边都有下期预告时，已确认大纲优先。

`memory.search` 参数：

```json
{"query":"循环","series":"PY","limit":8}
```

返回：

```json
{"backend":"trigram","hits":[{"memory_id":"...","title":"...","episode":4,"snippet":"..."}]}
```

`limit` 上限 20。查询为空返回空列表，不报错。`LIKE` 回退时对 `%`、`_` 和 `\` 做转义，`backend` 写 `"like"`。

## 11. 规则诊断、时间线、编辑器

### 11.1 `articles.lint`

参数：`markdown`、`series`、`title`、`abstract`。空 Markdown 返回空诊断，不抛异常。

实现直接调用 `run_all_checks` 和标题摘要检查。返回：

```json
{"issues":[{"code":"brand.banned_word","severity":"block","message":"...","line":12}]}
```

行号能从现有规则定位信息映射时就填，映射不到就为 `null`。不要在 JavaScript 里复制品牌词表。

### 11.2 `jobs.timeline`

参数只有 `job_id`。返回该任务的 `steps`、`events`、`model_invocations` 摘要。调用摘要保留模型 id、状态、用量、完成原因和错误码。删除任何看起来像密钥、请求头或完整提示词的字段。任务不属于当前公众号时，沿用现有「公众号已切换」错误。

渲染进程在现有任务区域增加「时间线」：节点名、状态、开始与结束时间、错误中文摘要。不要新建独立窗口。数据来自这个方法，不要轮询整篇正文。

### 11.3 编辑器

新增 `desktop/renderer/editor-entry.js`，打包为 `desktop/renderer/vendor/editor.js`。在现有正文编辑处提供 Markdown 编辑，诊断来自 `articles.lint`，输入停止 400 毫秒后请求一次。保存仍走现有 `articles.save`。

CodeMirror 构造失败时，保留原来的文本框，并显示「代码编辑器未能加载，已使用原来的文本框」。不得让整页空白。

`package.json` 的 `check` 脚本加上对新入口文件的 `node --check`。`build:components` 在打包编辑器的同时复制 CodeMirror 许可证。

编辑器只服务正文。不要把选题、模型设置、网页工作台改成 CodeMirror。

## 12. 封面叠字

新模块：`ice_agent/cover_compose.py`。  
布局：`ice_agent/resources/cover-layouts.json`。

四栏目都要有布局。区域用模板宽高的比例，不用写死像素：

- `title_box`：`[x, y, w, h]`，都在 0 到 1。
- `episode_box`：同样。
- `color`：PY 与 AI 用 `#15191F`，JV 与 WK 用 `#F3F2ED`。这只是叠字颜色，不重画底图。
- `min_font`：标题字号低于这个值就拒绝，错误码 `cover_title_too_long`，提示缩短标题。

`covers.compose` 参数：`job_id`、`figure_no`、`template_path`、`title`、`episode`、`series`。

路径规则：

- `template_path` 解析后必须落在该任务文章目录或决策文档确认的视觉资产目录内。
- 拒绝 C 盘、拒绝包含 `..` 逃逸、拒绝不是 PNG 的文件。
- 先用 Pillow 验证能打开，且尺寸不超过 8000×8000。
- 不修改模板原件。输出写到该文章 `images/` 下的新文件，文件名含期号和短哈希。
- 旁边写同名 `.json`，记录模板哈希、标题、期号、字号、模式 `raster` 或 `metadata_only`。
- 标识和头像像素不得由程序重绘。测试用纯色 PNG 夹具，不用仓库里的正式品牌原图做破坏性测试。

字体可用且标题放得下时输出 `raster`。字体不可用时仍复制模板到输出路径，模式为 `metadata_only`，JSON 里说明「未叠字，因为未找到微软雅黑」。两种模式都返回 `{ok, mode, image_path, meta_path}`。

`covers.layouts` 只返回 JSON，不读用户磁盘。

## 17. 卡住时怎么决定

| 情况 | 决定 |
|---|---|
| 账号和文章的关系读不懂 | 停在 P0，把问题写进决策文档 |
| FTS5 不可用 | 用 `LIKE`，不要加分词库 |

| 某条旧测试因 CSS 或版本号失败 | 只更新这条测试所锁定的那一项期望，并在阶段日志说明 |
| 想新增本说明书没有的依赖 | 不加。用标准库、Pillow、SQLite 或已列出的 CodeMirror 包 |
| 修复需要改动「可改文件」之外的模块 | 先在阶段日志写原因和函数名，再做最小改动。不得借机重构 |
