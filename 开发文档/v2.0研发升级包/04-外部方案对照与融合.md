## 1. 两份方案的关系

对照方案是围绕现有JS/Python的保守增强：IR、记忆、lint、进度、模板叠字、预览和CLI评测，主要控制改动范围；本升级包是完整工作台升级：100项跨层任务、组件化编辑器、Agent工具、可靠队列、知识检索、资源管理和最终打包验收。

可借鉴的是它对单项工程任务的具体描述和降级意识。不能同时把两份完整执行说明发给GLM当同等命令：其中“禁止React”“不打包”“只能加CodeMirror依赖”等与本升级包明确矛盾。采用本包作为唯一实施主线，对照文件只作参考；下面裁定已经融入报告、矩阵和提示词。

## 3. 借鉴并纳入主线的内容

### 3.1 文章生成IR，与编辑文档使用同一规范化链

纳入M3-01/M3-02/M5-05/M6-01。模型可输出受校验的ArticleIR，但它是生成输入格式，不是独立第二份长期正文真相。

IR提供版本、标题/摘要、当前账号栏目/期号、基础blocks及source/slot/run引用。只接纳已注册节点类型，拒绝任意路径、shell和模型声明的“已执行stdout”。转到ArticleDocument再生成规范Markdown；审批和导出仍用同一revision/hash。

IR失败允许一次受预算与既有自动修订上限控制的格式修复，再降级现有Markdown生成。**降级不跳规则、事实、人审、代码真实执行或图位核验。** 原生Markdown输入仍可编辑；未知结构保留raw block。IR栏目与品牌来自当前公众号，不写死四线和ICE句尾。

保留原 `<!--RUN_OUTPUT:run-N-->`约定的兼容转换，首次迁移不要重编号已有run reference。占位符引用不存在的run、伪造来源或执行未批准要阻断相应就绪行为。

### 3.2 提示词注册与版本快照

纳入M4-06/M5-03/M8-05。复用现有prompts字典，先提取有效模板/平台规则/brief/上游内容来源并锁定兼容fixture，之后引入id/version/schema/hash和可回读受限快照。

任务记录模板hash、渲染输入hash、规则/模型版本与ContextPack manifest。不需要把全文prompt铺进时间线/diagnostics；涉及可重现需求可存于账号受限内部产物，保持加密/访问范围及脱敏策略。

占位符字段通过显式列表验证；JSON示例中的花括号不能被误当模板变量。“未知键保留原样”不可成为隐藏缺项的规则：必需变量缺失阻断生成；可选变量有声明默认值；静态JSON花括号按转义/安全模板语法原样保留。

### 3.3 规则共享的编辑诊断和离线评测

纳入M3-02/M6-07/M8-05。后端lint复用现有rules，前端不抄品牌词表。能映射的诊断附block/line/span；映射不到写null，不给错误行号。输入lint防抖、取消和generation token避免旧结果盖新稿。

提供 `eval`命令/脚本和固定小样例：良好稿、结构缺项、品牌禁词、不同公众号差异、WK敏感字段、IR损坏、运行引用缺证据、占位/图位失联。离线不触发真实模型或外部网络。结果JSON与退出码用于回归，新增规则先观察误报并保留负样例。

不能仅凭“出现运行输出小节且没有RUN_OUTPUT”推断伪造：合法integrate后的文章占位已被真实输出替换。应核对来源/RunRecord/revision映射与明确占位契约；普通文章的解释句不能因此被误封。

### 3.4 封面文本模板能力增强

纳入M7-03/M7-04/M7-05/M7-10。复用resources.cover，增加StylePack中可编辑区/保护区/标题字号/期号区域/排版优先/字体能力与输出元信息。

有标题烘焙的模板必须先确认可替换遮盖区域；不得只往原标题上加新字，也不把旧字区当纯色抹掉导致破坏背景。复杂背景不能安全替换则建议TapNow edit_existing提示词，保留原图。

字体不可用或文字容不下时输出“待处理”元信息和下一步；若复制底图，它不能成为“已完成有标题封面”的ready候选。不能以metadata_only的ok=true遮蔽用户实际上没有封面标题。正式品牌模板原件hash保持，保护区域像素不被处理，输出另存并记录源hash。

### 3.5 Markdown源模式可采用CodeMirror

纳入M0-06/M3-02。Tiptap服务结构化编辑，CodeMirror仅作为Markdown源模式选项；同一时刻一个编辑源，切换由规范文档转换协调。加载失败使用现有textarea降级，保留文本与保存能力。

官方GitHub开发仓库当前已标迁移到新的官方托管，不应看到archive就认为项目停止维护，也不应据旧README盲用版本；实施时查看实际npm包/官方文档和LICENSE。[CodeMirror官方开发仓库迁移说明](https://github.com/codemirror/dev)、[view许可](https://github.com/codemirror/view/blob/main/LICENSE)

这不是必须同时引入两套复杂WYSIWYG，CodeMirror最小实验失败可继续安全textarea源模式，但源模式功能验收不能缺失。

### 3.6 移动预览和心跳

纳入M1-05/M2-07/M9-04。手机预览有17px/1.8倍行高的ICE默认，其他公众号可配置；阅读预览最大约480px不限制实际编辑工作台或浏览器宽度。

慢操作心跳说明本地工作者仍活跃，不等于模型新增输出或任务推进，UI明确“仍在等待”。固定15秒/放大RPC超时不是可靠队列替代：重操作返回run/task ID，主线由事件与持久状态推进；保留需要时的request超时区分。

## 4. 不直接采用的建议及理由

| 对照建议 | 本包裁定 | 理由 |
|---|---|---|
| 禁止组件化前端 | 保留增量React/TS，旧页桥接与旗标 | 用户需要大幅提升编辑/交互/协同；旧JS全局状态继续堆更难维护 |
| 不生成安装包，不动release/dist | 不碰真实安装；最终生成本轮正式包和同源审计 | “可用程序”必须验证打包和冻结依赖，不只有源码检查 |
| schema必须9→12 | 用审计后明确编号迁移、checksum与恢复演练 | 本包数据范围更大；固定目标数字不能替代实际schema设计 |
| 原库直接复制一次备份 | 优先SQLite backup API，关闭写入/连接并核验 | 活动WAL场景裸复制.db有遗漏风险。[SQLite Backup API](https://www.sqlite.org/backup.html) |
| IR仅允许PY/JV/AI/WK、固定ICE尾句 | 动态当前公众号profile/column规则 | 产品服务多公众号，不能把示例品牌变成平台硬编码 |
| 新稿只注入最近1篇和若干短摘录 | 继续满足前五正文+全部标题，记忆额外补充 | 用户已明确要求，不能借摘要升级缩水 |
| 缺account_id用空字符串 | 明确账号映射；歧义条目隔离并人工归属 | 空账号不能绕过权限过滤或成为全账号公共数据 |
| trigram成功就可查所有中文短词 | 1/2字单独受限查询/词项策略 | SQLite文档明确少于3字的全文子串不匹配 |
| 所有模型调用前端靠长超时 | 事件+持久任务，取消与轻查询可响应 | 延长超时不能修复卡住、重启恢复或假停止 |
| 任意测试失败就整个长任务停止 | 不跨过失败阶段出口，独立工作可继续 | 阻断依赖与可独立任务区别，避免一项环境问题永久停工 |
| 只凭文章输出小节判定伪造 | 来源/证据映射验证，不靠文字启发式一刀切 | 回填后的真输出和合法教学句会被误报 |
| 用户不补需求就永不问问题 | 普通事项自主推进，必要权限/数据歧义精准澄清 | 不能猜测私有数据归属，也不能擅自付费/发布 |
