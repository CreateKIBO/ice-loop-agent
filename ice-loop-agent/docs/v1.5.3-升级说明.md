# v1.5.3：程序输入隔离、原图查看与运行清理

## 修复内容

1. **演示程序误读内部通信**：空输入原来使用 `input=None`，子程序继承了引擎的 JSON-RPC stdin。现在所有执行阶段都使用独立管道，空输入发送 EOF，编译器及 Docker 辅助命令也不继承通信流。
2. **补图任务的输入准备**：检测到 Python input / Java Scanner 而未填写示例输入时，先提示补充；末行统一补换行。输入不足保留真实错误并说明补充方式。失败尝试不再被永久当作可复用成功结果。
3. **原图查看**：点击文章配图、候选审核图片、资源箱图片、推荐图或品牌参考图打开原图。支持滚轮缩放、拖动、适应窗口、原始大小、双击切换、Esc 关闭。后台按当前公众号及资产归属校验，原图按需读取；缩略图与原图分开。
4. **运行与文件收尾**：Windows 使用独立 Job Object，在程序恢复执行前绑定进程树；正常返回、错误、超时和输出超过 2 MiB 后均终止本次进程树并收回管道。其他平台使用独立进程组。Python 禁止生成字节码；TEMP/TMP 指向本次目录。Java 编译超时也归档真实记录并清理。
5. **清理边界**：只删除本进程创建、所有权标记仍一致、位于 runtime/staging 的独立目录。链接、junction、标记变化或清理失败会保留并记录原因。外部指定目录、原稿、正式配图、旧未标记目录均保留，不扫描删除其他磁盘文件。执行证据包含源码、输入、stdout、stderr 和运行元数据，继续归档，供截图和核验使用。
6. **配图就绪判定**：意外失败、超时及输出截断的运行记录不能直接成为就绪截图；明确的预期教学错误仍可作为素材。选哪条通过记录用于哪个图位，仍需要核对图注。
7. **预览缓存**：切换文章或公众号清掉旧图片缓存，异步返回不会重新灌入旧文章的图片；关闭原图查看器立即移除原图引用。
8. **截图中间文件**：运行截图等待正式图位及资源箱副本归档完成后，清理本次唯一命名的中间 PNG；截取窗口始终关闭，归档失败也收尾，不批量清扫历史截图。
9. **原图交互收尾**：快速关闭后重开不会被旧关闭事件清空新图；切换文章或页面关闭原图，释放引用；相同尺寸的延迟布局通知不再重置正在缩放的图片。

## 如何处理截图中的年龄程序

安装新版后打开原任务，选择「审阅并执行示例」，在示例输入中填写如 `18`，确认当前源码和输入再执行，然后选择新的通过记录截图。旧的失败日志保持原样；程序不会推测年龄或伪造运行结果。

## 关于内存和历史文件

本次 Python/Java 及其子进程退出后，它们的内存由系统回收。Agent 自身、内嵌浏览器及已打开文章仍占用正常工作内存，不能承诺整个应用工作集归零。代码执行目录自动清理；正式图片与执行证据属于项目数据，不自动删除。强制断电等无法执行 finally 的场景可能留下目录；新版不会冒险删除旧目录或不明文件。

本机审阅执行不是完整文件系统沙箱；隔离运行可使用已有 Docker 模式。此版未改动用户真实安装和文章数据，验收使用 G 盘独立测试工作区，不调用付费模型、生图或发布。

验收详情和安装包校验见同目录 `v1.5.3-验收结果.json`。

最终验收：81个不同后端测试、62项Node检查通过；打包程序原生49项预算/配图/执行/原图、85项创作对话、32项内嵌浏览器检查通过，7张品牌原图字节一致。Setup、ZIP、未压缩程序和最新引擎载荷一致。没有对实际用户工作区执行升级安装。
