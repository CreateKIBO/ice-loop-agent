# v1.0 使用、迁移与验收

日期：2026-10-02。面向 Windows x64 的多公众号桌面工作台。程序可本地管理稿件、运行示例、截图、配图审核和导出；调用真实文本/视觉模型需要对应供应商 Key，TapNow 采用手动网站生图。

## 1. 安装与数据

- 安装版：运行 `../release/ICE-Loop-Studio-1.0.0-Setup.exe`，按向导选择安装目录。
- 免安装版：将 `../release/ICE-Loop-Studio-1.0.0-x64.zip` **完整解压**到非 C 盘可写目录，双击 `ICE Loop Studio.exe`，不可只拿走 EXE。
- 自带 Python 引擎与教学 Python 3.12.13，无需开发机器的 Node、uv、虚拟环境。Java 示例需要本机 JDK；Docker 执行需要本机 Docker 和对应的已有镜像。未安装这些可选工具时，其余功能仍可使用。
- 程序将任务、代码、图片、运行证据、会话与日志放在非 C 盘工作区。安装在 C 盘时优先选择已有 G/D/E/F 数据盘；免安装版本通常在程序目录旁创建当前系统用户的独立工作区。C 盘仅保留少量工作区路径偏好与安装快捷方式。
- 「规则与工具 → 选择新工作区」在所选父目录下建立新工作区，重启后切换；旧目录保留。已有目录请通过备份恢复迁移，避免选错、覆盖或把任务路径拆散。
- 新版本会为旧 SQLite 保存升级前备份，拒绝打开比自身更新的数据库。不向安装包复制用户数据库、凭据、原始文章或浏览器会话。

## 2. 原来卡住的文章怎样继续

先关闭旧程序并重新启动更新后的工作台。源码启动入口仍是 `../start-desktop.cmd`；它使用原来的开发工作区。安装版使用独立工作区，如需原任务，先在源码版「备份与恢复」创建 ZIP，再在安装版检查包并恢复到新的非 C 盘目录，重启切换。

打开该文章的「运行证据」页。需要 `input()` / `Scanner` 的片段会出现自己的输入框，例如输入 `小冰` 后换行；空行输入也有效。点击一次「保存输入并确认运行」。已存在的源码授权会保留；提示会明确区分缺输入、未授权、执行失败，而不会用相同的审阅消息循环阻塞。

每段运行立即保存源码、输入、输出、退出码、输出哈希和真实原始证据。后续片段失败时，匹配当前代码、输入、预期报错、执行环境且证据完整的已成功片段会复用，不重复运行。修改任何绑定内容后，相应运行需重新确认。

如果模型给了错误代码，展开「修改待验证源码」，修改后保存，再审阅执行。Python/Java 可以运行，HTML/JS 等说明性片段可明确标为 `text` 保留展示。教学用的报错需勾选「预期报错」，仍保存真实 traceback；普通失败不会被自动当作验证成功。

默认使用「审阅后本机运行」，以本机权限执行；它不是安全沙箱。可在新任务执行策略或当前任务策略中明确选择 Docker。Docker 模式禁网、只读根文件系统、限制 CPU/内存/进程和权限，不自动下载镜像，也不会失败后静默改成本机运行。当前任务切换策略需重新审阅。

## 3. 公众号、历史与标题

在「公众号与品牌」新增或导入公众号，设置读者、栏目、品牌语言、主题色、存稿目录和输出目录。草稿、历史、选题大纲、资源、规则和提醒按公众号隔离，已创建任务使用自己的冻结配置。

在「发布记录与历史」核对已发布记录，默认下一期是该栏目已发布最大期号加一，草稿和预设大纲不自动计入。AI 拟题使用所选期之前最近五期正文和该栏目的全部历史标题；不混入其他栏目，不使用旧的十篇/六十标题截断。

也可打开「栏目选题大纲」，读取 MD/TXT/DOCX 或粘贴示例，识别、修改、确认保存；在新建文章中采用对应期题。题目可继续修改，确认后锁定，后续写作不再重新拟题。模板见 `栏目选题大纲-示例.md`。每栏目支持 1–9999 期，单次导入最多 1000 条，可继续追加。

AI 自动填充默认补空白，可选择改写已填写的写作需求；晚到结果不会覆盖等待期间的手动修改，已确认的大纲/自拟标题受到保护。骨架和配图仍需人工审核。

## 4. 模型设置

支持 Qwen、DeepSeek、Kimi、GLM、火山方舟和 MiniMax 原厂预置；可修改模型 ID、官方服务端点、地域/业务空间，并将写作、策划、审稿等角色分别绑定。改模型或端点后连接/能力状态失效，需要重新测试。模型目录刷新只读取当前账号的目录，不把目录中的模型自动认定为已经支持思考关闭、JSON 或图片输入。

首次使用或旧凭据无法解密时，在程序中重新保存对应供应商 Key，并点击测试连接。**不要在聊天、文章或公共日志里粘贴 Key。** 旧加密文件保留，无法读取不会阻止工作台启动，也不会显示为可用凭据。

视觉模型单独测试；纯文本模型不能代替真实识图。图片的像素主色可本地提取；AI 内容/风格分析和配色建议由点击后调用，审阅色值并修改后才应用到公众号。

本轮尝试只读兼容已有加密凭据，但在隔离测试环境中未能解密。真实供应商请求尚未通过验收；六供应商接口、路由、流式、结构化、回退、预算与能力约束使用回归/合同测试验证。MiniMax 默认端点参考[官方 OpenAI 兼容文档](https://platform.minimax.cn/docs/api-reference/text-openai-api)，预置 ID 不代表每个账号都已开通。

## 5. 配图与截图

- 「配图资源箱」按文章图位准备素材，真实运行记录由 Agent 截图；与源码、RunRecord 和输出哈希关联。输出按 INPUT / STDOUT / STDERR 分开显示，避免伪造交互时序。
- 「规则与工具」列出 Windows 可捕获窗口，选定后截图；记录 HWND、PID、程序、标题指纹、DPI、物理尺寸和时间，目标变化则拒绝。GPU 窗口、黑屏、锁屏或不支持 PrintWindow 的程序需手动截图导入，不自动退回全桌面截图。
- 网页截图仅访问公开 HTTPS 页面；禁用页面脚本、权限和内网请求。可填写 CSS 选择器。截图长边最多 20000 像素，过长页面需选较小元素或分段手动导入；需要登录或脚本渲染的网站使用手动截图。
- 选择已导出的文章，可截取本地阅读页；导出文件哈希发生变化会要求重新导出。页面脚本限制不为截图而放宽，测量在独立环境执行。
- AI 生图：复制该图位完整提示词 → 打开 `https://app.tapnow.media` → 自行登录、粘贴、生成、下载 → 导入资源/图位 → 审阅接受。程序不自动消费 TapNow 额度，不把用户生成步骤记作自动 API 成功。
- 单图「修改提示词 / 只重做此图」仅清空该图位选用，保留其他图位和旧候选，每图最多 5 次。新图仍需导入与审核。
- 原资源裁切/遮挡生成新资源，保留原图和父图哈希。坐标为原图像素；遮挡需填写原因。
- 确定性封面将标题/栏目期号绘制到指定文字区，文字区外保持原像素。使用无字背景或覆盖旧文字所在区域；它不会自动擦除文字区之外的旧字，不会重绘头像或字标。

## 6. 规则、编辑、导出与维护

「规则与工具」导入 MD/TXT/JSON 参考文档，只读原文件，保留文件路径、原文件 SHA、mtime 与导入文本 SHA。参考文档供模型理解；明确填写的规则字段才改变确定性检查。示例 `规则来源-示例.json`。优先级：本次覆盖 → 项目约定 → 品牌 → 排期 → 模板 → article-craft → khazix → 历史；同级冲突需选择来源，新任务才采用新快照。

正文支持保存、版本浏览、任意两个有效版本比较及恢复。AI 语义复审绑定当前正文哈希，不自动改写，不声称已核实事实；离线演示明确标注没有进行真实 AI 审稿。

导出 00–03、代码、已审核图片和本地 HTML 阅读页，缺证据/图片/审核项时保留草稿状态。「复制公众号排版内容」复制内联样式 HTML 与纯文本，内含已接受的本地图片，并读回检查是否实际写入。系统拒绝访问或内容未写入时，显示完整排版内容供手动选择复制，不会只显示成功提示；提示词复制有同样的校验与手动入口。公众号后台是否接收内嵌图片需粘贴后检查，最后手机预览。程序不会自动发布。

已有文章可以只读导入补图，另存新文章包，原正文、源码、期号和文件字节保留。备份包含账号、任务、草稿、资源、规则、提醒和运行证据，排除 Key 与浏览器会话；恢复包先校验，然后还原到新目录并重启。

自检检查数据库、Python、Java、磁盘和可选 Docker；诊断报告只保存版本、检查结果与数量，不包含 Key、端点或文章正文。本地提醒仅在程序打开时检查，关闭后没有后台提醒。

Git 使用当前公众号配置的输出目录，**该目录必须本身是仓库根目录且已有初始提交**。先预览完整文件差异与哈希，再明确提交/推送；预览后内容变化会拒绝，超长差异、重命名和特殊路径交由 Git 客户端。提交和推送不自动执行。应用不修改 TLS 校验，不执行仓库 hooks；需本机 Git 和已有认证。此次只用隔离本地仓库验收提交，没有推送用户仓库。

## 7. 验收记录与边界

结果见 `v1.0-验收结果.json` 与 `screenshots/v1.0/`。回归、桌面全流程、打包目录与重复验证专项按最终运行日志记录，不以接口存在代替测试通过。

最终验证：Python 全量 238 次测试（727.169 秒，含继承用例，不代表 238 个独立业务场景）、前端 25 项；最后配图专项 47 项、图位采用/过期请求专项 1 项通过。打包程序在独立目录、仅保留 System32 的 PATH 下完成桌面流程，不依赖开发 Node/Python。输入缺失专项真实输出“你好，小冰”后继续；完整流程包含四审核门、三段真实 Python、运行截图、公开网页/文章截图、标题/大纲、资源/补图、版本、HTML 和备份恢复。

最终 ASAR 与当前桌面源码一致，ZIP 与交付目录关键二进制一致，引擎与最后一次构建一致；独立测试目录与交付目录的837个应用文件逐文件一致。NSIS步骤附加的elevate.exe安装辅助程序没有在免安装测试中调用。试运行生成的Python缓存已从最终包清除，并加入构建清理和包校验。安装包为 NSIS，ZIP 为免安装版；两者的大小、SHA256 和实际签名状态见验收 JSON。没有代用户执行安装向导或在另一机器安装。23 张实际界面截图和最终日志随文档归档。

真实模型/视觉服务因旧 Key 在当前环境不可解密，未产生成功的付费调用；TapNow 生成按手动方案由用户完成。Docker 本机未安装，因此隔离参数与缺 Docker 的明确失败有测试，实际容器运行未验收。没有另一台 Windows 或另一系统用户，独立目录与清理开发 PATH 的本机测试不能替代跨机器验收。

当前测试进程的 Windows 剪贴板访问返回错误码 5（拒绝访问）；Electron 和独立 Windows Forms 测试都无法写入。此环境验证的是失败检测、完整提示词/富文本的手动复制入口，不是实际系统剪贴板写入成功。成功与异常路径另有接口合同测试。不要把手动入口通过解释成系统权限已经修复；正常用户桌面仍需实际复制、在微信后台粘贴并手机预览。远端 Git 推送未执行。

包为本地开发构建，未配置商业代码签名证书；最终签名状态和 SHA256 见验收结果。保留这些实际边界，不能据离线示例宣布所有外部平台均已成功。
