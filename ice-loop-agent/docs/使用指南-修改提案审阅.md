# 审阅修改提案

在文章编辑页找到「修改提案」，通过「选择修改提案」选中一份提案。提案列表每页最多20份，使用「上一页提案」「下一页提案」查看其他页；选中后才读取该提案正文。页面一次展开一项原文/新内容对比，可用「上一项修改」「下一项修改」或「跳转修改项」查看其他项，减少长文章同时渲染。

每项可接受、拒绝或改后接受。选择和手改文字会自动存为独立的「审阅草稿」，下次进入同一文章、同一提案时恢复；它不等于正文草稿，也不会应用修改或产生文章版本。请留意保存状态，正常离页和切号会先保存；保存失败会保留当前输入并阻止切换。应用突然终止前尚未保存的输入不保证恢复。

「提交决定」先显示整份提案的摘要，分别列出接受、拒绝、改后接受及未决定的数量，不只是当前展示的一项。默认焦点在「继续检查」；点击「确认并应用决定」才提交。未决定项仍按接受处理，摘要会明确提示其数量。若出现“决定已处理，但提案列表刷新失败”，点击「重新读取列表」只更新显示，不会再次提交。全部拒绝不会生成应用修改的正文结果。

很长的差异段会退为整段着色，原文与新文内容仍完整保留；这不是内容被截断。发生人工修改冲突时按系统提示处理，不能靠重试覆盖人工正文。

详情读取失败时，点击「重新读取详情」恢复当前选择，不需要重新提交决定。列表按时间与编号排序；查看期间新建的提案请返回第一页查找。

若提示审阅草稿被其他窗口修改，请先保留所需手改文字，再用「重新读取已保存决定」或「核对已保存审阅」。确认后只替换当前提案的本地审阅输入，其他提案的未保存输入保留；读取失败不会丢弃本地输入。提交期间会暂时阻止离页和切号，避免不确定的提交结果。

成功处理提案后，它的审阅草稿会一并移除，不会在下一次打开时再次自动应用。底层数据库增加独立迁移20；回退到不支持此版本的旧程序需要恢复升级前备份，不能让旧程序直接写入升级后的库。


## 同时修改正文时

正文有尚未保存为版本的编辑，或有待恢复的正文工作草稿时，可以继续选择、手改和自动保存审阅决定；涉及正文变化的确认会暂时禁用。先返回编辑区保存新版本，或恢复/明确丢弃已存在的正文草稿，再应用提案。全部拒绝不改正文，可以直接处理。应用提案期间正文编辑和保存新版本暂时锁定，结束后恢复。

如果提案已被另一个窗口处理，当前页显示只读提示，保留本地审阅文字供核对和复制。有本地记录时不能静默离开；点击「移除已处理提案的本地记录」后需明确确认，取消会继续保留。这个动作只移除当前页面记录，不删除文章、不撤销已处理结果，也不重复提交。需要长期保存这份冲突记录时请先复制。
