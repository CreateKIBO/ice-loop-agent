# v1.5 调研与实现记录

设计方向：暖白纸面、墨黑文字、信号蓝操作，平面编辑工作台。改善信息层级和密度，动效用于解释切换/运行状态，不显示虚构进度。

研究来源和最终取舍见 v1.5-research.md；验收过程持续记录在本文件。

本轮使用 Motion 14.0.0，随本地 renderer 打包，并携带 Motion、Framer Motion、Motion DOM、Motion Utils、tslib 许可证。保留 Shoelace 分栏、页签和 Lucide 图标。没有引入在线 CDN，也没有把现有 Markdown 存储迁移到新的编辑器格式。

实现重点：固定侧栏头尾和独立滚动、可收起导航、当前公众号的 Ctrl K 搜索、实际文章状态的四步提示、输入按账号与会话恢复、快捷写作指令、文章字符与段数、专注阅读、参考内容移除、回到最新消息、密度及减少动效偏好。生成状态仍由后台真实事件驱动，不推算百分比。

回归过程中修复的产品问题：

- 移除顶栏旧头像后，初始化仍直接写头像节点，导致启动报错；改为可选节点检查。
- 从搜索打开草稿后立即再搜索，异步导航可能吞掉打开请求；导航门现在保留请求并在完成后打开，旧关闭事件不会清空已重开的搜索。
- 小窗口与收起侧栏时，原生网页的区域受到旧固定高度影响；改为弹性布局，并核对 DOM 区域与原生 view 的位置及窗口边界。
- 对话轮询重建旧消息节点会丢掉展开状态、选择范围和阅读位置；保留内容未变的旧节点，并让用户滚动优先于自动跟随。
- 账号切换更新全局账号后，列表仍在加载时旧输入框可继续编辑；现在先保存旧输入、卸载旧工作区，输入及快捷指令也检查原账号、会话和 DOM 身份。
- 后续截图复查发现账号返回后的异步窗口：视图已经标记为聊天，工作区仍是加载占位，轮询返回后写入不存在的聊天节点。现在完整挂载节点必须匹配账号与会话，轮询前后都核对；新增确定性回归和运行时错误收集，之前仅功能断言通过的日志保留为修复前记录。
- 内置网页切换依赖动画帧，窗口被其他窗口遮挡时可能停在旧站点；打开站点改为微任务调度并校验打开令牌，动画帧仅用于后续布局更新。
- 首条直接输入没有会话时进入创建流程，确认后衔接原消息；取消保留输入。发送回执只清除已发送内容，保留等待期间新输入。

保留首次失败日志便于追溯。两类失败属于验收脚本：Windows 在 150% DPI 下会对最小窗口尺寸按物理像素取整，检查现在同时要求配置尺寸正确和实际取整误差有界；Electron 无法序列化 Motion controls / 函数，测试设置脚本改为返回可序列化布尔值。最终验收以修复后的完整运行日志为准，不把重复运行累加为更多测试。

公开 TapNow/微信公众号站点只做只读路由观察；测试中的导航、下载、弹窗、登录会话隔离使用本地网页夹具。公开站点 DOM 为空或截图超时的观察不能证明实际登录或云端生图成功。本轮未调用付费模型，也未改动个人文章数据、登录状态或已安装程序。
