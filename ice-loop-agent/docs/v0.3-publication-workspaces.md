# Content Studio v0.3：多公众号、AI 填充、草稿与视觉资产

更新：2026-10-01。本文是本轮实际实现的使用与开发说明；底层桌面、审核、模型凭据和导出机制见 [v0.2 文档](v0.2-desktop-guide.md)。

## 1. 本轮可用功能

| 功能 | 当前行为 |
|---|---|
| 公众号档案 | 本地创建多个账号档案，设置定位、读者、栏目、写作风格、结尾、品牌色、配图风格与存储目录 |
| 导入自己的规范 | Markdown / TXT 品牌说明作为参考文档导入；JSON 可导入工作台导出的结构化配置 |
| 配置导出 | 不含模型 Key，不保留原机器的账号 ID、输出目录和存稿目录；导入时建立新账号与本地目录 |
| AI 自动填充 | 先写一句主题，AI 补全读者收益、学习/内容衔接与待查证素材；可继续逐项编辑 |
| 草稿箱 | 新建、导入、保存、编辑、预览、导出 Markdown；可把草稿作为素材交给文章工作流 |
| 配图资源箱 | 导入 PNG/JPEG/WebP，保存独立副本，预览、展示尺寸与实际像素主色，复用到文章图位 |
| 配图资产分析 | 本地提取主色与占比，调用策划模型提出配色建议；支持单图和最近更新的最多20项资源综合分析 |
| 应用主题色 | 显示建议与依据，允许调整 HEX 色值，再由用户点击应用；新文章配图提示词使用这组颜色 |

这些账号是工作台的本地内容档案，不等同于已绑定微信后台身份。微信登录授权、在线微信草稿箱同步和自动发布尚未实现。

## 2. 如何体验

关闭旧版工作台后，双击项目的 `start-desktop.cmd` 重新启动，加载 v0.3 源码。安装依赖没有变化，无需重新下载 Electron。

### 2.1 配置其他公众号

1. 进入左侧「公众号与品牌」，点击「新增公众号」。
2. 填写名称、目标读者、定位与表达风格。
3. 设置自己的栏目，每行使用 `代码 = 名称`，例如 `LIFE = 生活发现`、`FOOD = 厨房记录`。代码使用大写字母、数字和下划线，以字母开头。
4. 按需设置目标字数、结尾章节标题和品牌句。品牌句可以留空；`{X}` 代表与本篇主题有关的内容。
5. 选择主题色和配图风格，粘贴自己的品牌说明。也可使用右侧「导入配置 / 品牌说明」导入 Markdown、TXT 或已导出的 JSON。
6. 保存并使用。顶部账号选择器可随时切换；任务列表、草稿和配图资源随当前公众号变化。

导入 Markdown/TXT 后会新建档案并保存原文，仍需核对名称、目标读者、栏目等结构化字段。导入文档里的指令不会触发文件上传、外部执行或跳过审核。

通用公众号模板允许零代码文章，不强制 ICE 循环、Python/Java 示例、教学练习或「可执行的想象」品牌句。默认 ICE Loop 继续保留原教学规范。其他账号支持 Markdown 的清晰章节和可配置结尾；当前并非所有任意排版模板都能完全定制。

### 2.2 让 AI 帮你填表，再自行修改

1. 在「模型与设置」保存国内模型 Key，并在角色路由中为「选题与骨架」选择一个已经配置 Key 的模型。这也是「策划」模型。
2. 打开「新建文章」，写一句文章主题，选择栏目和期号。
3. 点击「AI 自动填充」。默认仅补全空白项；勾选「同时改写已填写的内容」可重写已有需求。
4. 生成结果带蓝色标记，可直接编辑。等待期间手动改过的字段也会保留。如果改变栏目或期号，旧建议会整体丢弃。
5. 核对后点击「创建并开始」，才会创建并启动文章任务。

上一篇练习只沿用用户实际提供的内容，缺少时留空。AI 的素材建议以「待查证」标记，不能当作已核验事实；不允许生成未经核验的来源链接。AI 填充不会创建文章任务。

每次点击使用选定的策划模型一次；格式错误时最多增加一次 JSON 修复调用，单次传输超时为40秒。此阶段不自动切换其他供应商，也不回退到离线 Mock。填充请求独立于后续文章预算。生成失败会提示原因并保留表单。

### 2.3 草稿箱

草稿可直接写作，也可导入 Markdown/TXT。保存支持版本冲突检测，避免旧编辑覆盖新版本；Ctrl+S 保存当前草稿。草稿阅读预览沿用已有 Markdown 转义机制。

「交给 AI 继续创作」会先保存草稿，再把标题与正文放入新文章表单。正文作为需求素材传入时最多12000字，较长稿件可先整理关键段落；不会自动开始付费生成。手动草稿与正在制作的文章任务同时展示在草稿箱中。

### 2.4 图片与主题配色

1. 在「配图资源箱」导入封面、插图或视觉参考。单张图片上限32MB，解码像素上限4000万。
2. 导入后立即显示预览、尺寸、主色和近似占比，不调用模型。
3. 点击「AI 分析配色」，或使用页面顶部的「综合分析配色」。综合结果显示在最近一项资源卡片中，并标注参考项数。
4. 检查主色、背景色与强调色建议，按需修改应用色值。
5. 点击「应用到当前公众号」，保存为该账号主题色。已有文章任务继续使用原配色快照。
6. 点击「用于文章配图」，选择当前公众号中已生成配图计划的文章和具体图位。图片会复制到文章的资产目录。

AI 当前接收的是本地统计的色值、占比与账号定位，适用于只有文字接口的国内模型。图片本身不发送给模型。当前没有实现完整视觉语义识别、OCR、构图审美评分或版权判断。

主题色用于公众号内容和新文章的配图提示词，工作台的操作界面继续使用统一的编辑工具样式。应用之前可自由修改颜色；系统不会默默替换主题。

## 3. 开发结构

```text
Electron main / preload
  ├── 受限 JSON Lines RPC
  ├── 本地文件选择与配置、草稿导出
  └── HTML / CSS / JS
       ├── app.js          文章工作流与新文章 AI 填充
       ├── brief.js        保护人工修改的纯表单合并策略
       └── publication.js  账号、草稿、资源与主题配色页面

Python DesktopService
  ├── accounts.py         账号字段校验与规则 profile 适配
  ├── workspace_assets.py 草稿版本管理、图片副本与像素配色
  ├── RoleRouter          国内模型调用、JSON 契约与调用记录
  └── WorkflowEngine      品牌快照、审核、事实/代码校验与文章导出
```

### 3.1 存储与迁移

旧设置没有 `accounts` 时，自动建立 `ice-loop` 档案，将原输出目录和本项目存稿路径接入。旧文章缺少 `account_id` 时归入 ICE Loop。

`settings.json` 保存 `active_account_id` 与 `accounts` 字典；新账号获得独立 ID，默认输出目录为 `.desktop-runtime/articles/<account_id>`。本项目的数据目录保留原有“不落 C 盘”的限制。已有存稿只读，支持子文件夹内 `01-公众号正文-v2.md`、`01-公众号正文.md` 和 `正文.md`。

SQLite 新增：

| 表 | 主要字段 |
|---|---|
| publication_drafts | draft_id、account_id、title、body、content_hash、updated_at |
| publication_resources | resource_id、account_id、metadata_json、updated_at |

资源原文件副本位于 `.desktop-runtime/resources/<account_id>/<sha256>.<扩展名>`；图片元数据包括 MIME、尺寸、摘要、主色、占比和 AI 建议。文件预览会校验归档路径和文件摘要。

账号隔离针对同一用户的本地内容组织，尚未提供多人权限系统。国内模型配置与加密凭据在本机共享。配置导出仅经过账号字段白名单；不导出凭据，也不打包图片或草稿。

### 3.2 动态规则与任务快照

`profile_from_account()` 将账号设置转换为已有规则引擎使用的 profile。通用账号关闭 ICE 专用品牌词、标点限制、章节编号要求和工具周刊附加条款；保留明确的文章结构与事实核验要求。

节点提示词使用账号定位、读者、写作规范与导入品牌文档。任务创建时同时保存账号、规则和模型路由快照；恢复、审校和资产导入使用任务快照，不受当前账号切换影响。生图提示词的名称、色值和风格同样读取快照。

### 3.3 配色算法与 AI 边界

图片处理遵循 EXIF 方向，缩小至不超过160×160，排除透明像素，再以128色量化提取颜色。相近的中性色聚合后取最多8项，降低白底细微色差挤占强调色的问题。占比是采样近似值，不能用于测量印刷色。

综合分析从最近更新的最多20项资源聚合色值，各图片等权；候选色值最多24项。策划模型输出1–6个已有色值及说明；本地校验禁止 AI 编造候选颜色。用户在应用前的手动修改另行按 HEX 格式校验。AI 不修改文件、任务或账号，只有显式应用操作会保存主题。

### 3.4 新增接口

| API | 用途 |
|---|---|
| brief.suggest | 提议可编辑的需求字段，不创建任务 |
| accounts.save / switch / import / export | 档案持久化、切换和便携配置 |
| drafts.list / get / save | 按账号读写草稿，更新需原 content_hash |
| resources.list / import / preview | 归档与预览账号资源 |
| resources.analyze | 单图或 aggregate=true 综合配色建议 |
| resources.apply | 预览后应用，可以提供手动修改的 colors |
| resources.use | 把本账号资源选入本账号文章的具体图位 |

文件读取与写出由受限原生对话框负责，渲染层没有任意文件读写能力。Markdown、模型文本与品牌文档采用转义显示，导入文本只作素材。
