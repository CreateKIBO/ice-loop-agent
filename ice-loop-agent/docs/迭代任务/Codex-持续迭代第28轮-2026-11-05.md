## 设计约束（全部守住）

- 状态过渡 130–260ms；不做卡片悬停缩放/大阴影；阶段反馈不位移（第 20 轮）。
- 减弱动效：系统设置与程序内 `data-reduce-motion` 两条通道都生效。CSS 部分用 `--ice-motion-*`（减弱时为 0ms），JS 部分用 `useActivityReducedMotion()`。
- **pane 宽度必须立即到位**：layout-native 在点击"专注写作"后立刻断言写作区宽 1280，因此动画只作用于 pane 内的岛，从不过渡宽度；收起保持瞬时。
- **消息节点不重建、不重播**：只改入场参数，节点结构与 MotionValue 机制不变。

## 改动

`desktop/ui/src/`：

1. **侧栏滑入**（`styles/island.css`）：宽窗口下左岛/右岛用 `@starting-style` 从 ∓12px、透明度 0 过渡到原位（`--ice-motion-panel`，220ms）。窄窗口单面板切换只淡入。Electron 44（Chromium 14x）支持 `@starting-style`。
2. **顶栏分段**（`app/WorkbenchShell.tsx`、`island.css`）：窄窗口三项互斥，选中项内渲染 `motion.span layoutId="ice-shell-seg-pill"` 滑动底块；宽窗口左右两项是独立开关（可同时按下），不用共享底块，只做底色过渡。按钮文字包进 `.ice-shell-toolbar__label`，`innerText` 仍为原文案（layout-native 按精确文案点击）。
3. **发送**（`features/chat/MessageBubble.tsx`、`features/chat/Composer.tsx`）：
   - 入场改为纵向：用户消息 y 14→0（240ms），助手回复 y 6→0（200ms），x 恒为 0；弹簧改为 `[0.2,0,0,1]` 缓动。message-motion-browser 的断言是"新消息首帧有位移、700ms 内静止、减弱时首帧无位移"，新参数满足。
   - 发送被接受、输入框清空时，textarea 透明度 0.35→1（180ms，WAAPI），减弱动效时跳过。
4. **任务完成时刻**（`features/tasks/RightPane.tsx` JobCard）：
   - 状态徽标文字按状态 key 重挂载并淡入（180ms）；只重挂载徽标内一小段文字，卡片节点不变。
   - 任务从 running/queued 进入其他状态时，整张 `.ice-card` 用 WAAPI 闪一次结果色底（完成=成功底、失败=危险底、其余=信息底，1100ms 渐退）。首次渲染、筛选导致的重挂载、减弱动效都不触发（以 ref 记录上一状态）。不位移、不改 DOM 结构。
5. **命令面板**（`island.css`）：选项底色/文字色过渡；选中指示条用 `@starting-style` 淡入并纵向展开。
