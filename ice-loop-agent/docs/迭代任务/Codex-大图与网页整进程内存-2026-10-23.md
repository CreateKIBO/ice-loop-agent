# 大图与内置网页整进程内存

本轮继续通用 Windows 桌面版研发。源码版本 2.0.0-beta.2，不修改个人运行库，不提交推送、提版或覆盖安装；新增的源代码行为不代表旧安装包已包含。

## 真实基线与处理范围

原图使用 3000×2000 随机 RGB PNG，约 18 MB，避免纯色小文件掩盖二进制体积；网页是本地协议拦截的 HTTPS 测试页，每站点持有 24 MiB 数组与两张 2048×2048 canvas。没有外部请求、模型 Key 或真实 TapNow/微信操作。

改动前 12 轮基线运行 149.120 秒，观测到的私有字节合计最高约 1052 MiB，70 秒自然空闲后回落到约 305 MiB，最后单独强制 GC 后约 303 MiB。因此本轮没有证据将旧行为定性为持续泄漏。问题是原图中间复制、缩略图完整尺寸像素副本，以及另一站点保留时释放入口不够明确。不要把旧基线中强制 GC 后的数值混入自然回收指标。

## 原图与缩略图

新 UI 原图使用专属 preload IPC 取得随机、短期文件读取授权；Python 仅返回经账号/文章归属、类型和摘要检查的私有元信息，主进程独立验证来源与摘要，以流读取。renderer 不获得文件路径，通用 request allowlist 不开放 images.original_source。原图元信息摘要改为流式计算，避免完整压缩文件临时副本。

原图按二进制 fetch→Blob 显示，不再经过 JSON/base64/atob/Uint8Array 链。二进制读取结束即释放主进程文件授权；关闭、切号、卸载后显式撤销显示 Blob。原图文件不删除。最多 8 份打开/正在打开授权，每份最多 2 条读流，15 分钟兜底期限；页面导航和账号变更取消旧授权。32 MiB 限制、图片格式/摘要与只读限制保留。

首次直接用授权 URL 作 img.src 的方案被真实 image-lease 原生回归否决：即使服务器撤销令牌并返回 no-store，Chromium 解码缓存仍可能被新 Image 复用。该实现已替换为上述可撤销 Blob 路径，失败日志 image-lease.log 保留。修复后验证关闭不可重新加载、切图位撤销缩略图、迟到四秒的授权回复不会重建原图且授权释放。

缩略图先按 EXIF 朝向选择目标尺寸并缩放，再转向/复制与转 RGBA，减少大图中间像素副本；8 种朝向的尺寸/角颜色、透明度和原图摘要保持有测试。没有改变正式图片字节。

## 明确释放网页

保留“返回文章”的继续操作语义，新增“释放全部网页（数量）”和确认层。确认前默认聚焦“继续使用网页”，取消保留原 WebContents。确认后关闭当前公众号的全部站点与登录弹窗，取消未完成下载，移除下载监听器；不清 cookies、不删除已保存下载、图片或文章。迟到的旧账号释放操作不能销毁新账号页面。原有“关闭并释放网页”继续只关闭当前站点。

实际原生验证已授权图片被外部站点隔离（测试时主动绕过远程测试页 CSP，以检验会话隔离本身），以及释放全部网页后网站 cookie 保留。此处授权不开放任意本地文件读取；不声称能抵御用户在本机直接恶意改写数据库或文件系统。

## 验证与度量

首轮统一验收 15/15、complete=true、退出码 0、sourceChanged=false：Node 311/311、Python 768/768（768 唯一项，0 跳过，233.047 秒），类型/语法/构建/分块检查，以及四组独立播种串行原生共 210 项（12+9+42+147）全部通过。另用基线同一份 PNG 做最终单轮复查，12 项通过。打包清单补丁后新增守护的完整终轮结果见下文。测量包含所属 Electron、GPU、utility 与 Python 子进程；只跟踪具有本轮 fixture 所有权的树，并排除采样 PowerShell、PID 复用造成的旧进程。working set 合计可能重复计算共享页面，不等同任务管理器唯一物理内存。

循环期间不调用 GC；记录原图 Blob 租约、主进程文件授权、远程 WebContents、DOM、JS 堆、进程私有字节和句柄。最后的强制 GC 只作单独诊断。预先固定温机后的私有字节中位数增长门为 128 MiB，不在观察结果后调整标准。

## 实测结果和解释

20 轮总计 362.4 秒，循环前后都没有强制 GC。每轮包含约 10 秒双站点画布保留；随后 70 秒自然空闲。所有图片与网页释放检查通过。

| 阶段 | 整进程私有字节合计 MiB | 工作集合计 MiB | 主界面 JS 堆 MiB |
|---|---:|---:|---:|
| 启动稳定 | 286.5 | 419.6 | 4.6 |
| 第 1 轮原图打开 | 686.0 | 654.6 | 12.1 |
| 第 1 轮双网页打开 | 788.1 | 900.7 | 12.4 |
| 第 20 轮原图打开 | 852.3 | 671.7 | 8.8 |
| 第 20 轮双网页打开 | 852.3 | 898.4 | 9.1 |
| 70 秒自然空闲后 | 341.6 | 476.0 | 9.9 |
| 最后单独强制 GC 后 | 338.9 | 473.5 | 7.9 |

采样中最大的私有字节合计为 852.3 MiB。温机第 3–6 轮与最后 4 轮的释放后中位数差为 +34.2 MiB，低于预先固定的 128 MiB 门限；这证明本轮负载的有界性，不能证明无限时间无泄漏。自然空闲时原图授权 active=0/opening=0，显示 Blob 租约 0，远程网页 0；句柄合计 2854（启动 2745），不是“整个应用所有句柄变为 0”。

最终还复用了基线的同一 PNG（同 SHA256），各冷启动单轮原图采样 JS 堆为 33.3→约 12 MiB；对应整进程私有字节为约 722→721 MiB，几乎相同。原图二进制化减少的是 JS/IPC 中间复制，不应宣称已让全应用占用下降某个百分比。不同周期、不同缓存状态和强制 GC 后结果也不能拼接成收益百分比；GPU 和像素解码仍占较大部分。

旧 12 轮基线自然空闲约 305 MiB，本轮 20 轮自然空闲约 342 MiB；负载时长、实现和观测时机不同，不作为严格性能 A/B 或整体占用下降的证据。后续需要按真实网站和硬件重复长期测量。

## 打包依赖与剩余边界

发现 main.cjs 已 require 新原图模块，但显式安装文件清单遗漏 original-images.cjs。新增 runtime-package.test.cjs 通过 esbuild 解析真实 main/preload 的 17 份静态本地依赖、不执行 Electron，先明确失败报出遗漏，再补入清单后通过。修复后的终轮统一 quick 6/6、complete=true、退出码 0、sourceChanged=false；Node 312/312、类型/语法/构建/分块检查通过。Python 没有在这个 quick 再跑一次：采用此前本轮真实 768 项结果，期间 Python 与运行实现均未变化。不能将源 Electron 成功当成冻结 EXE 成功。

本轮限定负载的多轮回归不等于真实网站数小时、各种 GPU/物理 DPI 或整个应用无泄漏。后续仍需真实模型/TapNow/微信、历史库与恢复点管理、正式身份/UAC/签名、包含本轮改动的冻结发行候选。未通过清理用户资料来压低内存，也不按 Python/Electron 进程名批量结束程序。

设计依据：[Electron protocol 官方文档](https://www.electronjs.org/docs/latest/api/protocol)；协议按 session 注册，外部网页使用隔离会话。页面来源辅助检查不是唯一权限边界。
