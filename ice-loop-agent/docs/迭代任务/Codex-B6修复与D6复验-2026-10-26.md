## 根因与产品修改

`CandidateHistory` 的 `CandidateCard` 已位于组件模块顶层，并使用稳定 `candidate.id` 作 key；仅替换 latest 对象不会重挂载。真正可复现的卸载点在 `ChatPane.tsx`：

```tsx
if (messages.error && !position && !readingSnapshot) return <ErrorPanel ... />;
```

TanStack Query 的后台请求失败时仍保留上次成功的 data，但这个分支直接用整页错误替换会话树。这里的 position 是**消息页**，无法保护 CandidateHistory 内部独立的**候选页**。所以最近候选和历史候选都会失去组件状态。

现在仅在没有可显示 data 时显示初次加载错误；后台失败在现有会话内显示“会话刷新失败，已保留当前内容”和重试按钮。保留候选组件、分页、展开、原文模式及正常轮询，恢复成功后错误提示消失。没有修改发送、后端和缓存隔离语义。

D6 源码复核：配图开关由 ArticleEditor 的 assetFigure 持有，不属于任务列表的行；RightPane 复位只重设本账号显示偏好。已有复位定时器按生命周期清理，焦点在复位操作内立即返回本地 ref，超时回调只清提示。现有路径没有显示出定时器关闭 AssetWorkspace 的证据，因此保留实现。
