# 前端状态动效与反馈（2026-10-25）

本轮响应用户“开发同时持续打磨前端交互动效”的要求，沿用当前React/Motion14/Radix与视觉token，未引入新依赖、未重做全套视觉风格。保留已有后端/迁移/安装/数据逻辑；自动恢复点管理仍为后续工作。

## 用户可见变化

1. **按钮加载不撑宽**：公共Button不再把Spinner插入文字前，而使用绝对定位的Motion不定活动条。保留按钮文字、原DOM按钮、原尺寸与disabled/aria-busy语义；动作仍由原有业务锁保护。
2. **创作阶段更明确**：进度区域有独立容器、当前阶段、真实耗时和阶段轨迹。完成/失败/停止/等待回答使用明确终态；结束事件优先于滞后的streaming元数据，避免持续转圈。没有估算百分比。
3. **后台与结束停止刷新**：结束后取消一秒计时；document进入hidden时停止计时及活动条、打字点/当前步骤的循环动画。恢复可见后按真实起始时间继续显示，不漏算后台时间。终态缺少可信结束时间时不编造总时长。
4. **减少动态效果即时生效**：活动条在系统减少动态效果、现有data-reduce-motion标记或父级MotionConfig always下保持静态。设置变化能影响已显示的活动条，不必关闭再打开。
5. **备份页反馈**：操作说明与活动条同区显示，保存/预览/恢复结果用短淡入呈现。只做透明度，不移动可点击目标、不延后按钮可用状态，不改业务确认或备份契约。
6. **辅助访问**：仅阶段文字进入polite状态播报，耗时每秒更新不进入播报区域；视觉活动条对辅助技术隐藏，原按钮名称保留。

## 动效准则与参考

- 状态变化短过渡约160ms，循环活动条1.4s，只在实际进行中的操作存在。
- 使用Motion动画驱动，不添加另一套动效库；优先透明度/transform，避免长正文或整个编辑器做布局动画。
- 备份结果仅淡入，不让交互目标移动；保持Radix焦点与Esc/Tab契约。
- 服从系统与现有手动减少动态标记；终态/不可见时停止循环，不使用装饰性无限动画。

官方参考：[Motion无障碍动效](https://motion.dev/docs/react-accessibility)、[Motion状态动画](https://motion.dev/docs/react-animation)、[Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog)。核对本机固定依赖实现后才采用API，未直接套用新版库未安装的组件。

## 验证过程与失败保留

初版组件验收在隐藏的Electron窗口中比较动画位置，因不可见窗口缺少真实帧推进而失败；这是测试判据环境问题，未把静态截图当动画运行证据。改为实际显示的隔离测试窗口。
