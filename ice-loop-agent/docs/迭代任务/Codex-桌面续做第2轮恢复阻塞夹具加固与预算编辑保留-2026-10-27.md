## 独立复验与 blocker 加固

原样 codex3 在修改其脚本/产品前用新种子执行，38/38、81 次请求全部完成、renderer 异常 0，产品指纹前后一致。不能因旧脚本通过就推断“卡片存在”的前提也已被断言。

新增 `desktop/tests/reading-resume-blocker.cjs`，由 codex3 调用；codex4 顺序执行 round3、加固后的 codex3、预算重复入口检查。两种 scope 都不启用生产消费者，HTTP 桥继续禁止 renderer 使用 `test.*`，原隔离目录及 `.test-owner.json` 守卫保留。

blocker 最短序列及界限：

1. 在已有工作台打开的同一 `job-kb-done/art-kb-done` 上真实 `jobs.get`，另读 `job-kb-paused`。必须满足当前账号归属、completed、无租约/停止中、已有图位、真实 paused 对照，且 scope 的消费者关闭；不满足则断言中止，不能继续发 resume。
2. 核对 completed 与 paused **两张实际连接在 DOM 的卡片**及“已完成/已暂停”徽标，completed 恰有一个编辑入口，paused 没有。旧的“缺卡也可通过”判定已移除。
3. 保存工作台 tabs/dialog/editor 与焦点节点，启动独立 trace，动作声明为无导航、预期移除为空。真实调用一次 `jobs.resume`，要求 source=harness、非注入、存在 dispatch/receive/finish 时序，并收到“该任务不能继续”。
4. 再真实读取同 job，比较 job/article/account/state/current_node、lease/stopping/updated_at、正文 hash、slot ID/hash/有效性、pending approval、完整 events/invocations；经过两个渲染帧并等待观察器至少一个后续样本（上限 2 秒）后结束 trace。要求原节点/焦点保留且无移除。RPC 沿用现有每次 30 秒超时，夹具没有无限等待。

现有入口限制仍成立：任务卡/命令面板/审阅弹窗只为 completed 开放编辑；completed 的 jobs.resume 和引擎 run 不恢复生产；审批 RPC 在决定后启动独立 executor。以上只是核对过的恢复入口限制，没有证明所有历史窗口场景都不可能恢复。没有设置 editorStore、改任务终态、人工挪 checkpoint 或绕过审批 executor 来制造同篇消费者证据。
