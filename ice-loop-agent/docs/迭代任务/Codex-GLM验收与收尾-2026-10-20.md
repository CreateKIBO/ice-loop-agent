GLM保留了已有后端和审核契约，交付了错误/状态显示工具、帮助和消息窗口查找；其205项Node和类型检查可复现通过。但新增交互不能仅凭通用ui-smoke或旧原生测试判定完成。独立2000消息夹具复现了6个失败检查，本轮已修复并扩大回归。

## 实际发现与修复

| 问题 | 原因与处理 | 验证 |
|---|---|---|
| 输入关键字不定位首个命中 | 原代码只设高亮，没有定位；改为基于命中ID触发真实虚拟列表定位 | 2000消息首次命中可见 |
| 下一处跳回底部、新回复重置查找 | 程序滚动未暂停追尾；命中数组变化即重置索引。查找现在显式固定阅读窗口，按消息ID保持选择 | 下一命中、后台新增回复后定位与计数保持 |
| 关闭查找丢焦点、缺少明确清除 | 增加清除，Esc不冒泡触发外层布局动作；关闭回到查找按钮 | IME Enter不跳转、清除仍聚焦、Esc恢复焦点 |
| 帮助把预算0规则混用 | 只有会话允许0不限制；文章/补图必须1–100。纠正文案并区分已有任务快照 | 与model_budgets.py实际校验核对、原生帮助文本断言 |
| 帮助分类只有tablist外观 | 原按钮没有tab/tabpanel语义；改用已有Radix Tabs | 实际DOM语义检查及键盘支持 |
| 原生网页可能遮挡新帮助 | BrowserWorkspace未订阅帮助开关；加入帮助及备份/排期弹窗让位条件 | 实际WebContentsView拆下后恢复同一ID [2] |
| 诊断对普通RPC对象显示[object Object] | 原代码只认识Error实例；改为读取受控message并解析包裹的稳定码 | 独立Node行为断言 |
| 缺少MODEL_TIMEOUT等真实错误映射 | 补超时、窗口、能力、参数和拒绝码；未知写入结果不建议盲目重试 | 真实错误形状回归 |
| 常见JSON凭据字段未正确脱敏 | 补带引号字段、非sk令牌、URL凭据的遮盖；截断前脱敏，不序列化整个RPC对象 | JSON、Bearer、查询参数、URL四类行为断言 |
| awaiting_user显示回退成英文 | 统一状态工具遗漏旧枚举；补回，并防止constructor/toString原型键被当标签 | Node未知状态和既有状态回归 |

错误脱敏不是任意服务端文本的绝对安全保证，帮助里已避免“Key绝不会进日志”等未经验证的承诺。网络失败不表示远端未处理，未知状态不能盲目重复写请求。
