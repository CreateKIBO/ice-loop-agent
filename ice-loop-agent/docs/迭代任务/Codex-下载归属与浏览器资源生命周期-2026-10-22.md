# Codex：下载归属、保存路径与浏览器资源生命周期修复

日期：2026-10-22。实际目录 E:\Ice-agent\gonzhonhao\wechat_agent\ice-loop-agent；保留所有既有 GLM/Codex 未提交改动。源码仍为 2.0.0-beta.2，未提版、提交、推送或打包。本报告覆盖本次改动，不将局部通过等同于可发布。

## 修复的用户问题

1. **下载完成却无法归档。** 真实 Chromium 下载发现：原代码在异步保存框返回后再次 setSavePath，68B 图片实际留在 `.pending-*.download`，选择的目标文件不存在。现在在 will-download 同步设置 setSaveDialogOptions，由 Chromium 管理原生保存流程；完成时读取 getSavePath，再归档用户真实保存的文件。[Electron 官方 DownloadItem 契约](https://www.electronjs.org/docs/latest/api/download-item)明确保存路径/选项应在该回调内设置。
2. **切换公众号后下载归错号。** 原 stage handler 在完成时读取当前号。现在下载捕获来源 account_id，后端校验已配置账号并固定归属；没有该参数的旧调用仍归当前号，显式传入空值/错误类型/未知账号一律拒绝，禁止静默回落。旧账号回执不会携带文件路径显示到新账号。
3. **关闭网页后的下载与监听器残留。** 每个下载登记生命周期；切号、reset、关闭并释放网页会取消尚未完成项，并只移除本模块安装的 session 下载监听器。普通隐藏（为弹窗让位）保留原页面与下载。最多同时处理 4 项，达到上限给出可见反馈；完成/取消释放名额。登录 Cookie 不清除，已完成用户文件不删除。
4. **旧关闭命令误操作新网页。** 命令等待 bootstrap 前绑定目标 page；返回时若当前 page 已变更，旧动作取消，避免晚到的 A 号关闭动作操作 B 号。
5. **归档内存随文件大小增长。** 移除两次完整 read_bytes；单个打开句柄先检查 32MiB 上限，以 1MiB 块计算 SHA256，检查前后文件大小/修改时间，变化时拒绝登记。PNG/JPEG/WebP magic 与账号内去重语义保留。超过上限只拒绝归档，不删除用户保存文件。

## 资源测量的实际含义

原生脚本采集 Electron app.getAppMetrics，并使用已有 sample-owned-memory.ps1采集完整自有进程树（含Python）。本轮修正采样器把自身PowerShell排除，避免测量开销计入应用。PID/创建时间链仍限制在本实例。

16次循环后只剩宿主 WebContents、session 下载监听器回到基线、已完成图片与登录Cookie仍在；全部自有测试目录没有 `.pending-*` 或 `.crdownload`。工作集/Private Bytes的原始快照保留于result.json。它是轻量本地fixture的短测，未加载真实TapNow画布，**不推导长期RSS无增长、普遍内存减少比例或真实站点占用**。

## 失败记录与范围约束

- 修复前四项Node回归全部失败；后端新增首五项出现10个失败（含参数子例），日志 before-node.log、before-python.log保留。
- 首个原生脚本曾因GUI退出早于证据写入返回0，无证据时未计通过；runner已禁止这种假绿。
- 原生测试最初读取已销毁View的 getter 导致测试错误，改持有旧WebContents引用验证销毁；随后真实找不到目标文件，定位为产品异步setSavePath缺陷。失败JSON分别保留在对应独立运行目录。
- 现存完整回归有 Starlette/httpx TestClient 弃用提示，不影响通过；本轮未擅自更换依赖。
- 操作系统保存位置在 will-download **同步注入**，测试未实际点击 Windows 原生保存框。实际下载、文件写入、账号切换与后端登记均真实。
- 没有使用真实Key、生成TapNow图片、登录微信发布、验证真机DPI、数小时RSS或冻结安装器；本轮未改React界面，未重复前端构建，也未声称新的ASAR/安装器可用。
