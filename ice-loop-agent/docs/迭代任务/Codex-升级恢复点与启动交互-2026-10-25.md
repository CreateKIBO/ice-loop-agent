# 升级前完整恢复点与交互（2026-10-25）

本轮继续可分发Windows桌面版的资料保护与交互优化。沿用项目已有Motion与Radix，不增加运行时依赖。当前为开发工作区，不替换个人安装、不提版或推送。

## 行为

- 打开需要迁移的旧工作区时，先以只读SQLite在线快照保存完整受管资料，校验清单、托管图片、文章及数据库，再进入原有迁移。数据库或资料不满足条件时保留原库，转入独立恢复入口。
- 恢复点只属于当前runtime/recovery-points，所有权标记绑定工作目录。备份排除其自身，避免递归增长。数据库版本不变时不每次启动重复创建；迁移失败重试仅在配置、DB与每份源文件均一致且包摘要通过时复用已有点。
- 启动耗时超过短等待后显示独立等待页，沿用Motion活动条，显示真实阶段及处理字节/数据库页。只允许升级写入前取消；取消清理本次临时文件并退出，原资料不迁移。开始写入数据库后禁用取消。
- 备份与恢复增加恢复点管理：立即保存、占用查看、校验预览、恢复到新目录、打开/复制目录、显式删除。恢复需要预览授权、确认及系统目录选择。删除需要系统确认与当前记录摘要，且只删除已归属、内容未变化、无未知文件的完整点。
- 不自动删除历史点。未知文件、未完成目录、联接和已变化文件保留，明确提示检查。
- 正常引擎无法启动时，独立恢复菜单也能选择原工作区的升级恢复点，无需先打开损坏数据库。

## 容量与边界

普通外部ZIP保持单文件128MB/总1GB/10000文件的原规则。内部有所有权验证的恢复点使用显式有界策略：单文件4GB、总32GB、100000文件、清单32MB。大文件流式复制/摘要，ZIP64按实际大小启用；不从渲染器或包清单读取所谓“放宽限制”。创建前估算最坏压缩、DB快照、检查副本与迁移空间，不足先拒绝。

完整指受管工作资料，排除API Key、网页登录、缓存日志和外部只读文章目录。历史正文快照仍在数据库。恢复后重新配置模型、检查暂停任务。恢复点与原库同盘，不替代异盘灾备。支持完整恢复的数据库最低基线为schema 9；更旧资料需旧版整理导出，未声称自动覆盖所有历史版本。
