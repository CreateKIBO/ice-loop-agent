## 证据收紧

### round3 的停止与轮询

`seed_interaction_lists_native.py` 对 done 以外的两个任务均在审批门后写成 paused。因此 `fixture.jobs.running` 只是沿用名称，原 `jobs.stop` 序列实际为 **paused→paused 的幂等写入**，不能证明运行中的任务被停下。本轮保留这项覆盖，新增 stop 前真实 `jobs.get` 状态断言并记录 `r3.stopBefore`，改正测试命名与注释。历史 GLM 报告中的 running→paused 表述以本次核对为准。

原 `count('jobs.list')` 同时统计 renderer 和 harness，停止后服务状态确认本身就会增加计数，不能独立证明页面轮询。本轮所有请求记录 `source`；round3 必须在停止提交之后、显式切号之前观察到 **renderer 发出的 jobs.list**，再核对任务卡“已暂停”。新增消费者任务则要求 renderer 的真实列表响应包含新 job 的 awaiting_approval，并核对 UI“等待审批”。未通过暂停轮询、伪造列表或延迟挂载刷绿。

另保留慢快照中真实 slot 有效性摘要，断言第二次写入前持有的是 **2/4** 旧计划，再刷新后为 **3/4**；B6 失败和恢复均核对同一展开节点与完整原文，恢复还等待错误提示实际消失。

### 原生新增断言与环境定性

源码复核支持 `loading="lazy"` 的视口前提；先 scrollIntoView 再等图符合用户滚动语义。发现 native 只等 `img.complete`，破图也可能满足，已最小收紧为 `complete && naturalWidth > 0`，与浏览器一致。**该 native 测试修改仅做语法检查，因无 Electron 未执行，需 Windows 接续。**

本地 TanStack Query 的 interval 实现默认要求 focusManager.isFocused，focusManager 依据 `visibilityState !== 'hidden'`；产品没有启用后台 interval。故“hidden 暂停轮询”与源码机制一致，但 GLM 通过轮的 compareEnv 快照不能反证前一失败轮原因，本 Linux 轮没有重现窗口遮挡。维持环境因素的合理解释，不将其升级为已独立证实的 Windows 根因。

full 复验 CR/CRLF 原文、复制、目录、断点和关闭焦点；round2 补入 CR 原文视觉 br、CR 阅读模式真实目录滚动、Escape 关闭焦点断言。Chrome 结果仅对应生产 renderer + loopback 桥，不等于 preload/main IPC、OS 剪贴板或真机验收。

## 消费者线程边界与 D6

新增 `ICE_LIFECYCLE_SCOPE=codex1`，先运行收紧后的 round3，再在同一新夹具运行消费者与资源库序列。只有此 scope 启用消费者，round3 执行期间没有 queued 任务；full/round2/round3 默认仍关闭消费者。

测试控制仅在 Python 测试进程内提供，浏览器 HTTP 桥拒绝 `test.*`。路径必须位于本工程 `.test-tmp/release-interaction-lists` 且带 `.test-owner.json`；只允许入队一次、最大尝试一次、demo 模型、禁止本机执行授权，推进到首门即停。观察包装只调用原生产 `_run_claimed`，记录真实线程、认领时 running/租约/attempt、结束时刻和真实结果，锁保护快照读取。

断言包含：初始 queued/attempt=0 → 实际消费者 running/有效租约/attempt=1 → waiting_user；task↔job 绑定、account A、job awaiting_approval、topic 待审批、租约释放；慢响应交付前完成写入，跨页面真实任务轮询后仍只认领一次，工作台 tabs 原节点/焦点保留，无未授权审批或模型 RPC。DOM trace 继续按具体节点与用户动作窗口记账。

固定终版实测：入队后约 **391ms** 消费者开始、**441ms** 完成首门写入，桥在约 **5929ms** 才交付旧详情；新任务 `task-0f3fa0a46b3f4d559ea7` 绑定 `job-8341d1365e6f`，attempt=1。codex1 四段 trace 共 **467** 个样本（4/45/217/201）；仅 A→B 显式导航按节点移除 dialog/tabs/editor 各一次，其余无移除，unexpected/missingOrRepeated 均为 0。单独消费者段 **201 样本、0 移除**。94 次 RPC 全部完成，renderer 异常 0。

这补上了“无 queued production、消费者从未驱动”的缺口，覆盖的是 **production 队列与消费者控制流 + 离线 demo 首门**。尚不能代表真实供应商、生成正文后的同篇图位变化、消费者执行中途停止、真实 IPC 时序或长期现场。downloads.bind 计划变化仍是 harness 驱动的真实服务写入；旧快照之后通过显式刷新收敛，不能称为全过程从不短暂回退。
