# 修改审阅与差异内存优化（2026-10-23）

## 本轮结果

修复真实提案列表导致界面崩溃的问题；逐项审阅支持提案选择、上/下一项及直接跳转，切换保留决定和手改文本。差异算法避免整段字符数组展开。最终统一8步complete=true、exit0，Node293/293；Python编辑器集成9/9；相关原生28项分轮通过（11+8+9），不冒称同一次全绿链。

## 缺陷与改动

1. `editorial/storage.py:list_edit_proposals`原先只解析ops，仍返回base_document_json；单提案接口则返回base_document。PatchReview按声明读取后者，真实存在提案时触发ErrorBoundary。列表现在同样解码基线并移除原始JSON字段。新增真实RPC断言先以KeyError稳定复现，再通过集成测试与原生界面。未改SQL、迁移、账号过滤或提案决定规则。
2. 原先所有提案/所有修改项同时生成差异视图。现在只挂载一个提案的一项差异，保留上/下一项、直接跳转、已决定提示和各提案位置。其余修改项仍可访问，切换不丢本页决定；后端仍一次返回所有快照，尚未实现数据分页。
3. 提交增加同步防重与账号/作用域检查，晚到读结果不更新其他作用域。确认写成功后立即移除旧提案，重新读取失败单独说明“决定已处理”；恢复入口只读列表。用WeakSet记录已确认的对象，避免退出动画旧按钮重提且不长期强引用对象。没有自动重试写请求。
4. 全部拒绝/无应用结果不再误称全部修改已应用。未明确决定的项目仍沿用既有“按接受”语义，界面显示数量；后续应评估提交前的决定摘要确认。本轮不改变该策略。
5. inlineDiff先对UTF-16字符串剥离公共前后缀，保护代理对边界，只对小范围差异创建code-point数组与LCS表。超过字符/单元格预算时降级显示完整差异段，不裁掉原文。单侧极长新增/删除也受预算保护。新增大公共段、非对称输入和包含孤立代理单元的组合重构回归。

独立Node子进程，基准为Git提交4513985的inlineDiff源码；同一Node、输入、输出重构校验，每种情况每版本运行3次，取中位数。记录`.test-tmp/codex-diff-20261023/diff-memory.json`，脚本和编译快照在同目录bench.cjs/baseline.cjs/current.cjs。
