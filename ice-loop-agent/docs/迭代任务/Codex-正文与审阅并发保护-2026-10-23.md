# 正文与审阅并发保护

本轮继续推进通用Windows桌面版的实际可用性，源码仍为2.0.0-beta.2，保留既有未提交工作，不迁移个人数据、不提版或生成安装包。

## 问题和修复

真实RPC先红后绿：有独立正文工作草稿时，旧articles.proposal_decide仍应用提案并无条件clear_editor_draft。新的回归先要求拒绝应用，修复前明确失败；证据draft-loss-before.log。

现在由revisions.save_body的protect_editor_draft选项在同一BEGIN IMMEDIATE写事务内读取工作草稿，只有草稿内容与当前正文完全相同或不存在时才允许提案改正文；正文版本保存/回滚调用保持原有契约。已保存正文的恢复副本只在该事务中按账号、文章和完整原文匹配删除。提案处理完成后新到达的草稿不会再被清掉。拒绝所有项及没有可应用修改的冲突结果不改正文，仍可处理且不清正文草稿。

编辑器新增明确提示：有未保存为正文版本的编辑/待恢复草稿时，仍可审阅和自动保存决定，涉及正文修改的确认按钮禁用；全部拒绝仍可执行。同步beginApply守卫与版本保存互斥，应用期间Tiptap不可编辑、正文区域inert，Ctrl+S也不会穿透触发写版本。原生旅程实际验证保存人工新增段落→应用提案→人工段落保留→解锁。

另一窗口已处理的提案改为只读提示，不再挂载差异编辑和提交控件。本地审阅选择和手改文字保留，可复制完整JSON记录；有本地文字时离页受dirty保护。明确确认移除只清当前本地记录，不重放RPC、不撤销处理结果、不改正文。取消移除保留文字，其他提案的未保存决定仍可继续保存。
