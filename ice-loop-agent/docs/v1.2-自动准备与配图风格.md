# v1.2 使用说明与实现范围

这次升级围绕“自动准备文章与配图，完成后统一审阅”。保留多公众号隔离、旧数据与安装升级关闭机制。

## 如何使用

1. 在公众号档案中确认定位、栏目、主题色、配图风格和新增的“生图视觉规范”。ICE Loop 默认规范来自已确认品牌手册及正式资源，其他公众号填写自己的规范。
2. 在配图资源箱点击“导入 ICE Loop 风格包”，导入正式头像、透明字标、四栏目封面和品牌总览，共7张原图副本。重复点击不会重复建资源。该按钮仅在 ICE Loop 档案显示。
3. 对自己的参考图，在“编辑说明”中勾选“用作当前公众号的生图风格参考”。最多8张；可以取消。先用视觉模型分析内容、构图，再修改说明和标签。AI分析不会覆盖已填写的人工说明。
4. 新建文章选择“自动准备”。AI拟题模式可以不填题目，系统读取所选栏目的前五个期号正文和全部标题，自动采用推荐方向。选择大纲/人工题目时，仍保留用户已选定的标题。
5. 自动准备模式依次完成编辑决策、写作、审校、标题和配图策划。原“逐步审阅”模式仍可选。自动决定写入原审核记录，标明 `auto:preparation`；候选缓存后恢复不会再次请求。
6. 图位中的“拟写 / 编辑提示词”可以查看并修改提示词；“根据文章与风格 AI 重拟”使用策划角色，结合正文、图位说明、当前视觉规范及已标记参考的描述/识图记录。返回候选后点击保存生效。等待期间的新手写内容不会被覆盖。保存提示词保留已选图片和最近10份提示词快照；需要换图时另行导入新图片。
7. 复制提示词，打开程序内 TapNow 中国站 `https://app.tapnow.media/home`，手动上传对应参考图并生图；下载/导入生成结果。程序不会把“存在资源参考”等同于“已经向TapNow上传了参考图”。正式头像/字标作为原资产使用，不要求生图模型重绘。
8. 完成后统一审阅正文、事实来源与图片，点击“已统一审阅，复检并导出”。导出仍为 `文本/` 与 `图片/` 两个目录；手动在公众号后台排版与发布。

## 自动化边界

| 环节 | 自动准备模式 |
| --- | --- |
| 历史分析、拟题、大纲、撰写、审校、最终标题 | 自动运行及选定，人工可在完成后修改 |
| 生图提示词 | AI自动策划构图，再由程序组装比例、品牌色、逐字文字与禁止项；截图图位不生成生图提示词 |
| Python/Java真实执行 | 默认本机模式需要先审阅代码；用户选择Docker隔离执行模式后可自动准备缺失输入及批准隔离运行 |
| 运行记录截图 | 桌面程序在后台渲染真实记录并capturePage截图，导入图位与资源箱；程序需要保持运行 |
| 截图内容对应 | 自动截图包含本篇全部运行记录，避免猜测图位与某段代码的对应关系；统一审阅时核对，必要时手动选单条记录重截 |
| 操作系统/第三方页面截图 | 保留原网页及窗口截图工具；不会通过模型伪造 |
| TapNow生图 | 按用户此前选择，仍手动粘贴提示词、上传参考并生成 |
| 高风险事实、最终交付及公众号发布 | 保留人工确认；自动中间审核不代表已经核验事实或已经发布 |

Docker需已安装、可用且有合适的执行镜像，程序不会自动安装Docker或改变为本机无审阅执行。自动截图失败会显示具体原因，同一组运行记录本次启动不反复重试；可改选更短记录手动截图。没有代码运行记录的图位需使用现有网页/窗口截图工具或手动导入。

自动中间步骤不会直接标记可发布。最终确认绑定正文、标题及当前图片候选；正文/标题/所选图片变化后需重新统一审阅。图片完整性、来源规则与事实检查仍会参与就绪判定。

## DeepSeek识图

视觉模型供应商新增DeepSeek，并保留通义、Kimi、智谱、方舟及MiniMax。视觉模型ID独立于写作模型；使用供应商已配置Key。

官方当前文档标明 `deepseek-flash` 支持图片输入，`deepseek-v4-pro` 不支持。保存视觉配置后先点击“测试识图”，通过图像样例才可分析资源。程序发送真实本地压缩图片的 `image_url` Data URI，限制大小并去除元数据；不使用纯文字描述冒充识图。供应商端点改变后需重新测试。

来源（2026-10-03核对）：[DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)、[Chat Completions图片输入契约](https://api-docs.deepseek.com/api/create-chat-completion/)、[模型能力表](https://api-docs.deepseek.com/quick_start/pricing/?tab=case-studies)。正式调用以服务商实际权限及当日文档为准。

## 开发改动

- `accounts.py`：每公众号独立视觉规范，旧ICE档案补充缺失默认值，通用档案不绑定ICE专属约束。
- `workspace_assets.py`、`style_presets.py`：参考标记、受控原图资源导入、去重和风格摘要。
- `image_prompts.py`、`genprompt.py`：文章语义构图策划、固定品牌约束、逐字文字与比例、编辑快照，以及账号/正文/图位并发校验。
- `workflow/nodes.py`：生图策划缓存后进入审核；Docker模式自动输入准备；保留本机执行审阅。
- `automation.py`、`workflow/engine.py`：仅自动处理四种编辑审核；最终统一审阅内容摘要。
- `desktop/automation.cjs`、`main.cjs`：原生运行截图队列，已选图片保护、失败提示、防止每轮轮询重复截图；沿用沙箱浏览器与IPC白名单。
- `desktop_service.py`、`llm/adapters.py`：DeepSeek视觉配置、旧文本模型拒绝、图片输入契约与端点绑定。
- 安装器继续使用v1.1.1关闭产品进程树、同卷暂存恢复工作区、ZIP解压检查；未更改为按通用进程名结束程序。
- 内嵌浏览器的网页挂载与位置更新分开排队，避免滚动/尺寸事件取消挂载；进入网页工作台重置滚动位置。TapNow默认入口、站点首页与资源入口统一为中国站 `/home`。
