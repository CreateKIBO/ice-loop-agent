## 批次 A：真正连通队列与制作任务（优先阻断项）

范围集中在 `ice_agent/tasks/worker.py`、`tasks/__init__.py`、`desktop_service.py`、任务 RPC、`RightPane.tsx` 和队列测试。不要重写引擎。

目前 `drain()` 仅由测试直接调用，没有桌面生产入口。worker 无条件完成队列，即使引擎 failed；waiting_user 未持久化 job_id，重启/重排会重新建 job；认领时缺少账户约束，不能直接加一个定时器就上线。

按顺序实现：

1. 明确任务的账户执行上下文。只从任务持久化 account_id 获取配置，拒绝 payload 中冲突的账号，不能借用“当前选中公众号”。认领支持 account/kind 限制，服务切号不改变已有任务归属。
2. 首次认领时把 queue task 与 engine job 的绑定持久化，创建/写绑定解决并发竞争。重启、失租、人工继续使用已有 job，不能重新创建文章或重复扣模型费用。
3. 状态映射表集中定义：engine completed 才能 task succeeded；failed 映射 failed，人工门映射 waiting_user；paused/cancelled 映射对应状态；单次推进到上限仍未结束不能标 succeeded。未知 kind/payload 非重试错误，直接终止。
4. 所有状态提交携带有效 lease_token，waiting_user 的转换不能先释放租约再无条件 UPDATE。持久化结果包含 job_id、等待门及可读错误，不只返回瞬时 Python dict。
5. 对长操作保持心跳，取消/失租要通知实际 job；不能仅在 for 循环开头检查。沿用现有 worker/执行取消边界，不启动无法回收的线程、浏览器或子进程。
6. 连接桌面服务生命周期：启动唯一消费者，关闭后停止调度并退出自有子进程；不因 UI 每次刷新重复启动。不在 stdin 读循环同步跑生产任务；轻查询/取消保持响应。
7. UI 入队返回 task_id 后展示真实任务；刷新、重启和切账号后能看见正确状态。等待人工门时按钮跳到对应审阅位置，继续后不会新建重复 job。

验收：真实离线引擎完成任务；审批等待→重启→批准→继续；引擎失败绝不 succeeded；双消费者仅一个生效；失租/取消不重复 job；A/B 账号交错；坏 payload 无无限重试。现有 `test_v2_queue_consumer.py` 允许 succeeded 对应 failed，是弱断言，必须替换为严格业务结果断言，不能把它当验收证据。

## 批次 B：统一审阅与编辑数据闭环（范围较大、模块明确）

沿用 `automation.delivery_hash` 和已有 `articles.finalize(confirm_delivery=...)`，只补服务与 UI 的完整流程，不另造不兼容的审阅哈希。

1. 文章编辑器中加入最终交付审阅视图：标题/正文版本/当前配图/真实运行证据/规则和事实问题。显示每条阻断的具体原因和修复入口。
2. 用户明确确认后，服务针对当前 body/title/slot selection 写 delivery_review；请求带期望摘要并做账号及任务归属检查。请求期间内容或图片变化，必须拒绝旧确认。
3. 重新修改正文、标题或图片后旧审阅失效；ready 导出拒绝。draft 导出允许带缺项，并清楚显示警告。不能自动盖章绕过人审。
4. 图位展示缩略图/放大/来源/采纳状态/提示词。选图与正式版本同步，不用 preview 假装已采纳。代码样例里的占位符不能被当正文图位。
5. 同一编辑器处理恢复草稿与正式版本：未保存内容离开时先恢复性写盘；失败不跳页。刷新/切账号/命令面板/归档/删除/窗口关闭都使用一致策略。
6. 专门处理清空全文（当前 flush 对空串提前 return）、中文 IME、连续快速修改、保存请求在途继续编辑、工作草稿与正式正文冲突。使用 editor snapshot/version 判定，旧响应不能覆盖更新内容或误标 clean。
7. 保存新版本后重新读取审批/运行证据失效状态；避免“按钮显示保存成功但实际恢复草稿覆盖新正文”。冲突时保留用户内容并提供比较/重载/另存选项。
8. 草稿库和会话列表分页或游标加载，取消 `.slice(0,10)`、`.slice(0,50)` 的不可见上限；搜索全部本账户内容，不只第一页。任务列表补归档与回收站明确视图、恢复操作与空态。

验收：从候选→保存草稿→提交审阅→采纳→制作任务→最终审阅→ready 导出走一次真实 UI；正文或图改动后旧确认拒绝；清空/IME/快速编辑/磁盘失败/重启恢复不丢内容；60 个会话和25 篇草稿能够查到最后一项；保存、批准、发布语义始终分开。
