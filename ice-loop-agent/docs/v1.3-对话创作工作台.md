# v1.3 对话创作工作台

更新日期：2026-10-04。

新增类似 Codex 的创作对话界面，专门用于公众号观点讨论、历史拟题、写稿、改稿和配图提示词。候选内容通过独立的文章审批送入共享草稿或已有文章任务；文章区继续负责人工编辑、审阅和配图交付。

## 使用步骤

1. 在「公众号与品牌」选择或创建公众号，设置栏目、存稿目录、品牌规范和已发布进度。在「模型与设置」配置并测试国内模型；对话默认使用现有写作模型，也可临时选择其他已配置模型。
2. 点击「新建对话」，输入会话名称并选择栏目。自由讨论可以不选栏目。讨论不会自动创建文章，也不会推进已发布期号。
3. 输入想法或修改要求。模式分为「讨论」「改稿」「配图」：讨论返回观点；改稿生成完整 Markdown 候选稿；配图生成正文候选与英文生图提示词。
4. 在右侧查看文章、修改对比或配图。可以拖动中间分隔线，收起预览；1040px 窄窗口优先显示对话，右上预览按钮切换文章面板。
5. 可手动修改候选的标题、正文和提示词，点击「保存新版本」。旧版本仍可选择。选中文段后点击「修改选中文段」，再在输入框补充要求。
6. 点击「同步至文章审批」。进入「文章审批」查看待审批稿、对比原文，并在审批时继续手动修改。可以采用保存，或附上意见退回；结果会出现在原对话中。
7. 采用的新稿进入共享「草稿箱」。审批记录里的「准备配图与发布包」会把已采用正文交给现有补图流程，不再重新调用模型生成文章。已有普通任务的改稿则保存到原任务，并重新要求正文审核。
8. 配图提示词可以复制；「打开 TapNow」进入程序内网页工作台的中国站 `https://app.tapnow.media/home`。手动生图后导入并审核图片，导出仍为「文本/」「图片/」两目录，手动进入微信公众号后台发布。

建议第一条消息：

> 根据本栏目前五篇正文、全部已有标题、对应期大纲和上篇预告，讨论下一期应该写什么。先比较几个方向，再给我标题候选，避免重复。

接下来可以要求：

> 用第二个方向写完整文章。保留品牌结尾，缺乏依据的事实标记待核验，示例运行输出不能编造。

## 文章、历史与引用

- 「文章存稿」支持 `PY/005-标题/01-公众号正文.md` 这样的栏目子目录，也兼容旧的平铺文章目录。只扫描配置的存稿根目录及一层栏目目录，避免遍历整块硬盘。
- 新对话选定栏目后自动带入该栏目的最近五篇实际正文、全部已知标题、对应期选题大纲、品牌信息及视觉参考。正文不足五篇时以实际篇数为准。
- 下一期期号依据已发布记录/进度计算，不把草稿、文件夹序号或审批采用当成已经发布。
- 从旧期文章继续编辑时，优先参考该期以前的正文；栏目所有标题仍用于发现重复。
- 点击附件按钮可以额外引用最多八篇历史文章；文档按钮支持 Markdown、TXT、DOCX，单份最多三万字符，每次最多三份。总资料超过上限会要求减少引用，不会悄悄截断全部历史标题。
- 已保存草稿、文章任务与本地存稿都提供「在创作对话中修改」。采用草稿后会保留栏目和期号，再次进入对话时自动继承栏目。
- 配图上下文复用该公众号资源箱里的视觉分析、颜色和品牌风格；主题色使用已确认的公众号颜色。图片识别仍由资源箱统一的模型设置负责。

## 会话与版本

消息、候选稿、审批反馈存在现有工作区数据库里。支持流式讨论、停止生成、失败后重新生成、会话重命名/搜索/归档/恢复，以及从完成的消息分支继续讨论。

候选版本独立保存。手改候选不直接修改原稿；提交审批也不直接发布。每个候选 ID 是同步的幂等标识，重复点击不会重复创建审批。采用新稿后会话关联改为已采用草稿，继续对话会读取最新正文。

右侧候选保留提交时的版本；审批时手改的结果在审批记录和草稿箱查看。后续请求读取实际采用稿，不把候选预览里的旧文字当成当前原稿。

同步和采用都会比较原稿版本；原稿被其他入口修改时会阻止覆盖。点击「基于最新稿继续」重新生成候选，旧候选仍可查看。会话已经采用其他候选时，旧待审批版本也不能再建立重复新稿；可退回该版本，或继续对话生成更新稿。

候选编辑和审批弹窗都保护未保存修改。切换公众号会清空当前引用、文档、选区和会话；新会话不会携带上一会话的附件。

历史存稿原文件及已有只读补图原稿不会被改稿覆盖；采用后生成新草稿。普通文章任务更新正文后会失效旧的最终检查结果，需要重新审核。文章审批采用仅代表接受这份文稿，不代表事实、图片或代码已经验证。

## 国内模型与能力边界

继续复用原有统一模型路由、国内服务端点、Key 存储、流式接口及结构化输出校验，没有第二套凭据。对话专用节点支持多轮消息和文档上下文，不向编辑助手暴露任意终端或文件执行工具。

模型可能无法理解某项要求，需要继续对话修正；结构化候选格式错误会显示失败，不会把半截回复保存成文章。停止会丢弃后到的结果；服务商已经开始处理的请求可能仍计费。

原有代码审阅、真实运行截图、资源选择、备份恢复和导出功能继续使用。新对话入口不会自动运行模型生成的代码。TapNow 登录、生图和微信公众号发布由用户在内嵌网页中完成。

## 组件与开发结构

界面采用 [Shoelace 2.20.1](https://shoelace.style/) 的分栏和标签组件（MIT），配合 [Lucide 0.468.0](https://lucide.dev/guide/lucide) 图标（ISC）。Lit 和 Localize 的依赖许可证一并保留在 `desktop/renderer/vendor/`。组件、主题和图标随程序本地打包；不依赖 CDN。

主要文件：

| 文件 | 用途 |
| --- | --- |
| `ice_agent/creative_chat.py` | 会话、上下文、模型调用、候选、审批及配图交接 |
| `ice_agent/article_library.py` | 统一受限目录扫描及正文读取 |
| `ice_agent/llm/router.py` | 复用模型路由，增加多轮消息 |
| `desktop/renderer/creative-chat.js` / `.css` | 三栏界面、版本对比和审批 |
| `desktop/build-components.cjs` | 编译本地组件并保留许可证 |
| `tests/test_creative_chat.py` | 会话、版本、账户、停止和交接回归 |
| `desktop/chat-smoke.cjs` | 实际 Electron 窗口功能及截图验收 |

`creative_*` 新表采用增量创建。首次升级会在原数据库旁保留 `app-before-v1.3.db`；既有文章、资源和设置不重建。升级前仍建议保存正在编辑的内容，并使用原有备份工具备份工作区。

本地开发：运行 `desktop` 内的 `npm ci`，再执行 `npm run build:components` 和 `npm start`。开发 Python 使用项目现有虚拟环境。完整构建运行 `build/build-release.ps1`；安装程序仍使用已有的自动关闭本产品进程、保存/恢复旧工作区的升级机制。
