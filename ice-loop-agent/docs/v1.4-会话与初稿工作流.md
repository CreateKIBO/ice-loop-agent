# v1.4 会话与初稿工作流

本版修复普通续聊、重复打开文章导致的会话混淆，并补齐初稿生成、资料澄清、确认保存和实时状态。桌面程序保留原有文章审批、配图资源箱及内嵌网页工作台。

## 连续讨论与分支

同一会话直接在输入框发送消息，所有轮次都留在同一条会话记录。重复进入同一篇文章的“在创作对话中修改”，优先回到最近的未归档关联会话。新建对话的重复提交有独立请求标识保护，侧栏按照会话 ID 展示。

只有消息的“更多 → 以此消息新建分支会话”会另建会话。窗口明确说明会复制截至该消息的内容，允许命名，点击“确认新建分支”才创建。关闭窗口继续留在原会话。

旧版已经建立的分支仍保留全部内容。不同会话即使同名也不会被删除或合并，可在查找会话中打开、改名或归档。相同名称不是判断重复数据的依据。

## 生成初稿与保存

1. 在创作对话讨论观点或填写主题，关联栏目可带入前五篇正文、全部历史标题与对应期大纲。
2. 点击输入框上方“生成初稿”，或在模式菜单选择“生成初稿”后发送要求。按钮优先使用当前输入；输入为空时根据本会话内容准备初稿。
3. 如果缺少会影响方向、读者定位或关键结论的资料，助手先列出最多三个问题。可以选择建议答案，再修改文本，也可以自己填写。点击“补充并继续生成”仍在原会话中继续。
4. 初稿完成后，正文在右侧文章预览展开，显示“是否保存到草稿箱”。可以先手动修改、查看对比，再选“保存初稿”或“暂不保存”。暂不保存时，候选仍留在会话中，之后可以再保存。
5. 已保存草稿出现在左侧“最近草稿”，并进入同一公众号的草稿箱。侧栏显示未审批/已采用状态，点击可继续编辑。重复保存同一候选不会产生第二篇草稿。
6. 需要正式采用时，另行点击“同步至文章审批”。审批时可以再次修改；采用后更新关联稿件。保存本身不自动采用、不推进发布期号、不发布文章。

关联已有草稿时，保存会更新该关联草稿，并检查它有没有被其他编辑修改；已有存稿及只读配图任务不会被直接覆盖。旧候选保留，可以通过版本菜单查看。再次打开已保存文章，优先展示当前保存正文，包含审批阶段的人工作品修改。

## 生成反馈

左侧输入框上方显示由实际事件驱动的阶段：读取资料、排队、等待模型、接收内容、校验、完成，或者等待补充、停止、失败。显示等待耗时、接收字符数及引用数量；没有模拟百分比。

接收字符数包含模型返回的结构化内容，并不等于成稿字数或模型 token 数。较快的阶段可能一闪而过，后台保存阶段记录；流式返回暂时没有内容时保持“等待模型”，不会假装已经写完。

旋转状态图标、阶段呼吸提示、消息出现与按钮交互提供轻量反馈。系统启用“减少动画”时停止动效，文字状态继续更新。长时间生成可点击“停止”，不完整回复不会成为草稿；失败后可以重新生成。

## 数据迁移与边界

使用现有 `app.db`，新增会话请求与候选保存映射表；首次升级已有 v1.3 数据时自动保留 `app-before-v1.4.db`。会话、草稿、引用与审批继续按公众号隔离。版本冲突时拒绝覆盖，允许重新基于最新正文继续。

澄清问题会保存原始写作要求、文档及引用信息，重新打开会话后仍可回答；正文、引用、品牌及历史重新读取，变动会提供给模型，不能用旧候选覆盖新的人工修改。

模型继续使用“模型与设置”的写作配置或本次选择的模型。需要真实配置才能正式创作。验收采用隔离的离线模型测试多轮、流式、保存和澄清交互，不代表已实测你的付费模型账号。

TapNow 和微信公众号平台继续通过内嵌浏览器使用；生图、最终发布由你完成，导出仍按“文本 / 图片”两个目录组织。
