## 必须修复与已同步的发现

### P1：新顶栏删除头像后，原有公众号同步逻辑仍直接赋值

- 位置：`desktop/renderer/publication.js:16`，关联 `index.html:60`。
- 新 index 已无 `.avatar`。`syncPublication()` 执行 `document.querySelector('.avatar').textContent = ...` 会因 null 抛 TypeError。
- 影响：首次 bootstrap 与切换公众号都会经过该函数，工作台初始化可能直接失败。
- 修复建议：删除失效的头像同步，或使用存在性判断；原生验收必须先验证正常启动和切换公众号。

### P2：旧会话或旧公众号的慢响应能覆盖全局创作数据

- 位置：`desktop/renderer/creative-chat.js:26`，关联 `writing-ux.js:225` 与 lifecycle render wrapper。
- 当前先执行 `creative.data = await chatApi('chat.get', ...)`，然后才检查 token、视图和公众号。旧 A 请求若在 B 页面完成后返回，会先把全局数据改回 A，虽然本轮渲染随后被丢弃，外层 wrapper 仍会增强当前聊天页面。
- 影响：B 页面的只读状态、文章字数等可能按 A 的数据更新，直到下一轮刷新纠正。后端账号检查不能防止这类前端混用。
- 修复建议：把请求结果先存在局部变量，并在 token、公众号、会话 ID、当前视图都匹配后才赋值。
- 同类位置：`creative-chat.js:156` 的 `creative.sources = await ...` 也在公众号检查前赋值，建议同样修复。

### P2：文章引用清除按钮缺少 renderer 标记

- 原位置：`creative-chat.js:46`；消费方：`writing-ux.js:155`。
- 写作增强仅寻找 `[data-writing-reference]`，原文章引用 span 没有该 attribute，所以移除按钮永远不会出现。
- 审阅中主任务已补入 `data-writing-reference="..."`，静态复读确认存在。仍应在原生界面点击一次引用与移除，并确认下一次模型 payload 不带已移除的引用。

### P2：手动减少动效偏好没有传递到“回到最新”

- 原位置：`writing-ux.js:266`，关联 `motion-entry.js:51`。
- 原判断读取 `data-motion === 'reduced'`，控制器实际写入 `off/on`。系统未减少动效时，用户手动选择减少动效后仍会触发 JS smooth scroll。
- 主任务已安排修改为共享 reduced 判断。原生验收应覆盖“系统正常 + 用户关闭动效”这个组合，而不只模拟系统媒体查询。

## 集成检查结论

1. Motion 14.0.0 实际安装源码 `motion-dom/dist/es/animation/GroupAnimation.mjs` 提供 `finished` getter，故 `controls.finished.then(...)` 有效。不能仅根据官网示例偏重 `.then()` 就误判 API 不兼容。
2. 动画控制器按节点登记，取消后恢复自己持有的 style，未调用全局 `getAnimations().cancel()`；有限入场与无限循环分开清理。隐藏/卸载节点检查已加入 `effect()` 与 `scan()`，不会为 detached 元素新建动画。
3. 进度卡现已按消息 ID、phase 与 busy 等 signature 更新结构，同阶段只更新字符数和用时，避免每轮重新旋转与闪入。
4. 输入草稿按公众号 ID + 会话 ID 分离，挂载旧输入记录其原账号，导航过程中不使用新账号给旧文本贴标签。发送成功先 flush，再仅删除与发送内容匹配的输入；能保留等待 `chat.send` 时新输入的下一句话。仍需原生异步验收确保基础 renderer 的成功回调也遵守这项规则。
5. 读旧消息时保留 scrollTop，下一帧有 revision 检查，避免旧 callback 拉回新页面。消息仍然全量重建，展开的 details 和原生文本选择仍可能丢失；这是本轮可追踪的体验限制，不能宣称实现了完整的增量消息渲染。
6. 快捷搜索请求冻结公众号 ID，load token 丢弃旧响应；结果按 identity 去重而非标题去重。弹窗使用原生 dialog，支持 Esc、上下键、Enter、组合输入保护，关闭时恢复可用的原焦点。
7. `browser.js:44` 观察 dialog 的 open 状态并隐藏 WebContentsView；main browser epoch 取消旧 show 请求，因此新增搜索与显示偏好弹窗沿用原有盖层机制。仍需原生验收在 TapNow/公众号网页工作台打开弹窗，确认原生网页不盖住弹窗，关闭后恢复。
8. 窄窗口原有 preview-toggle 是“对话/文章”切换，新增专注布局用 `::part(start/end)` 的 important 规则覆盖隐藏；顶部仍保留 preview-toggle，所以未发现静态上彻底丢失预览入口。最终应实际检查紧凑窗口，不只看 CSS。

## 可选后续改善

- `navigation-ux.js:154` 的 Ctrl/Cmd + K 仅在主 renderer DOM 注册。鼠标点进远程 WebContentsView 后，键盘事件不会跨 webContents 冒泡，`desktop/browser.cjs` 当前也没有 `before-input-event` 转发。因此快捷搜索在内嵌网页拥有焦点时无效；点击侧栏搜索仍可用。若对用户宣称快捷键在整个程序通用，应在 main 安全处理该固定组合并转发给本地工作台，不向远程网页暴露通用 IPC。
- 自定义公众号主题色已有 `--blue/--chat-accent`，部分新增 CSS 仍写死 `#2448db`。这不造成账号数据混用，但弱化了别的公众号配置。若本轮继续收尾，可将主交互色统一为已有变量，淡色背景保持足够对比度。
- 草稿恢复目前仅恢复未发送文字，不恢复创作模式。若用户经常切换“生成初稿/改稿/讨论”，将来可按会话同时保存模式，避免恢复文字后忘了检查下拉框。存储上限和有效期仍应保留。

## 账号过渡问题复审：已解决（Resolved）

本节在主任务与写作子任务落盘修复后再次读取当前源码形成，覆盖上一节的待修复状态。

- `publication.js:18–35` 在更换全局账号前调用 `iceWriting.persist()`，保存使用原 mounted 的账号和会话；随后卸载内置网页，将视图置为 loading、清除当前任务/草稿/detail，并立即用切换提示替换旧 workspace。列表请求等待期间已没有 A 账号的旧输入框或模板按钮。
- `creative-chat.js:34–35` 的输入监听冻结挂载时的账号、会话和 input 元素；只有它们仍与当前上下文及当前 DOM 一致时才写入 `creative.text`。迟到的旧 input 事件不会改写新账号输入状态。
- `writing-ux.js:66–80` 增加 `contextMatches()` 和 `canEditMounted()`，同时检查账号、会话、当前输入 DOM、connected、disabled、视图和只读状态。`writing-ux.js:109–126` 的持久化调度与 capture input listener 使用该检查，失效的输入事件会在写回全局状态前停止传播。

因此前面 P2 所述“账号 B 已激活而账号 A 模板仍可写入”的窗口已从源码上消除；原账号文字在切换前保存，返回原会话仍可恢复。本次复审未发现新的具体必须修复项。首条消息取消设置时保留原输入、确认后按新会话 ID 保存并只发送一次的逻辑，以及普通发送确认时保留等待期间的新输入，仍保持一致。模型请求的账号 + 会话校验与远程页面无通用模型 IPC 的边界未被本次修复改变。
