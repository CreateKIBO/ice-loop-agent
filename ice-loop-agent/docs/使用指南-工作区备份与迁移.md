# 工作区备份与迁移

## 创建完整备份

从侧栏或命令面板打开“备份与恢复”，选择“创建完整备份”。程序先保存当前未落盘的工作草稿，再让你选择 ZIP 的保存位置。正在运行的制作任务需先暂停。

备份包括本地工作台中的所有公众号、文章、草稿和托管图片。API Key、网页登录、日志和浏览器缓存不进入备份；外部只读文章目录不复制，已导入的历史正文快照保留。备份完成后显示保存路径、文件数量、解压大小和校验摘要。

手动选择外部ZIP文件的备份上限为：单文件 128 MB、总量 1 GB、10000 份文件。超过上限时操作会明确失败并保留原资料，不会生成一个声称完整却缺少内容的备份。

## 恢复到新目录

1. 点击“选择备份并校验”，检查公众号、日期和数据库版本。
2. 若显示 `schema 19 → 20（恢复时迁移）`，表示恢复过程中会先在新目录的暂存区完成迁移。
3. 勾选确认，再选择一个父目录。程序会在其中创建新的工作目录，原工作目录保留。
4. 成功后核对“资料已恢复到新目录”和数据库版本，再选择何时重启。当前窗口会继续使用原工作目录，重启后才使用恢复的数据。

若目录选择文件写入失败，已恢复的资料仍保留，界面提供“重试切换目录”。它会复用已恢复的目录，避免再次解压出第二份。程序不会为了恢复而覆盖当前工作区。

预览有效期为 10 分钟。源 ZIP 在预览或恢复期间发生变化时，需要重新选择并校验。实际解压的每一份文件也会核对清单中的大小和 SHA256；校验或迁移失败时不发布新的工作区。

## 早期迁移记录提示

部分早期版本采用的迁移校验算法未覆盖完整 SQL。遇到这类记录时，预览会显示“早期迁移记录的校验范围”，并保留原记录。这个提示说明历史校验的范围，不会自动替换旧 checksum。文件完整性与当前迁移流程仍会检查。

较新版本数据库、未知迁移记录、缺失记录或当前校验不一致会被拒绝。遇到启动错误时，请保留原工作区和错误信息，使用下述启动恢复入口或匹配版本处理。自行改写版本号或迁移 checksum 会破坏后续核对依据。

## 恢复任务与模型

恢复后的待执行任务暂停等待确认。重新配置并测试模型后，可以从“恢复后暂停的任务”逐项继续；继续可能调用模型。已完成任务保持原状态，不会因为恢复自动重跑。

早期队列使用数字格式的任务指纹；对相同账号、任务类型、幂等键和原负载的重试，程序会转换为稳定指纹并复用原任务。不同输入仍会提示冲突，需核对需求或创建新任务。


## 打不开工作台时恢复（2026-10-24）

启动恢复窗口提供以下操作：

1. **选择已有工作区**：选择含app.db和settings.json的文件夹；先检查只读副本、展示公众号及版本，确认后重启加载。
2. **新建空白工作区**：选择父目录并确认，程序在其中新建独立子目录。原文章和配置仍在原工作区。
3. **从备份恢复**：选择ZIP并检查摘要，确认后选择恢复位置。即使原数据库打不开，也能用独立工具恢复到新目录。

取消不会切换资料。切换记录写入失败时，界面保留已恢复的目录位置，可选择“重试切换已恢复的目录”，避免重新解压。选择“暂不启动”会退出本次程序，下次启动使用确认过的目录。

所有工作区必须在C盘之外。恢复本身不运行模型，恢复后的待执行任务暂停等待审阅；API Key和网页登录需重新配置。没有有效备份时，启动恢复不会自动修补未知版本或校验不一致的数据库，请保留原目录。


## 升级恢复点（2026-10-25）

程序发现数据库需要升级时，先在当前工作区的 `recovery-points` 目录保存文章、草稿和托管配图的完整恢复点，校验通过后再升级。待执行工作不会在这一步调用模型。恢复点排除自身目录、API Key、网页登录、缓存和日志；同一磁盘故障仍可能同时影响原资料和恢复点，重要文章可另存异盘备份。

启动较慢时会显示等待页，展示实际处理阶段和已处理大小。升级写入开始前可点击“取消启动”，原数据库保留；进入写入阶段后请等待完成。磁盘余量不够、托管资源缺失或校验失败时先拒绝升级，启动恢复窗口显示原因。

从“备份与恢复 → 升级恢复点”可以：

1. 点击“立即创建恢复点”保存当前所有公众号。先保存未落盘的编辑内容，正在运行的任务需暂停。
2. 查看已识别的备份占用、时间和数据库版本；点击“校验并预览”核对内容。
3. 勾选确认并选择父目录，在新目录完成还原；原工作区保留，重启才切换。
4. 删除无需再保留的点时，需在系统确认窗口再次确认。程序只处理有归属标记、记录和内容一致的点；未知文件、未完成目录和联接不会被清理。可复制或打开目录检查。

启动失败时还可选择“从升级恢复点恢复”，选择原工作区目录，从最近完整点中选择并校验后还原。此路径无需原数据库能启动，不会重放原工作队列。

内部恢复点的容量上限为单文件4GB、解压总量32GB、100000份文件，与普通外部ZIP的限制区分。创建前检查空间，超限明确失败；不自动删除旧点。重试迁移时，仅当数据库、配置和所有源文件仍相同且已有包校验通过，才复用已有恢复点。
