# v0.5 截图、TapNow 与视觉资产

日期：2026-10-02。项目：Content Studio / ICE Loop Agent。

本版将配图资源箱扩展为文章配图工作台：查看图位、准备真实运行截图、复制完整生图提示词、打开 TapNow、导入结果、编辑与复用资源。根据用户最后的选择，本版优先使用手动 TapNow 生图，不需要配置 MCP 授权。

## 1. 启动与操作

关闭已有工作台窗口，再双击项目根目录的 `start-desktop.cmd`。已有公众号配置、模型 Key、草稿和文章任务继续使用原数据。

### 1.1 准备真实运行截图

1. 在文章流程中完成代码审阅与执行、配图计划审核。
2. 打开文章的「配图素材」页，或到「配图资源箱」顶部选择该文章。
3. 在实截图位点击「Agent 截图」。核对图位说明，在窗口中选择对应脚本，或选择本篇全部运行记录。
4. 点击「截图、归档并选用」。程序将源码、输入、标准输出、报错、退出码和记录摘要显示在独立窗口，截成 PNG，保存为文章候选并复制到当前公众号的资源箱。
5. 预览图片，核对它是否对应本图位。全部配图准备好后，在文章页重新执行发布检查与导出。

这是**程序内真实运行记录的截图**。输出取自实际执行的 RunRecord，截图过程不重新运行代码，也不调用生图模型。它适用于程序输出与报错说明。IDE 安装步骤、浏览器页面和其他桌面软件操作界面，仍通过手动截图与导入准备；当前版本没有自动控制这些外部应用。

每一段源码、输出最多显示前75行，超出时在图中注明截断；完整记录保留在文章的「运行与事实」页。截图布局高度上限7000 CSS像素，长记录请分开选择脚本。正文源码或运行输出发生变化后，需要重新执行与回填，不能用过期记录生成新截图。

### 1.2 使用 TapNow 手动生图

1. 审核文章配图计划。
2. 到资源箱顶部选择文章，在封面或正文生图图位点击「查看完整生图提示词」。封面提示词与正文插图提示词分别对应各自图位。
3. 点击「复制提示词」，再点「打开 TapNow」。程序用本机默认浏览器打开 [app.tapnow.media](https://app.tapnow.media)，方便复用你已有的登录状态。
4. 在 TapNow 粘贴提示词，自行选择模型、画布或参考图，生成并下载图片。
5. 回到该图位，点击「导入并选用」。程序验证 PNG/JPEG/WebP 的实际内容，存入文章候选，同时归档到公众号资源箱。

也可以在资源箱右上角「导入图片」只归档资源，再点击「用于文章」选择任务和图位。图片导入不代表已经核验图片内文字或完成事实审核。

本版不自动提交 TapNow 生成任务，不读取其账号 Cookie，不自动下载结果，不使用 TapNow MCP。打开网站与复制提示词分别由按钮触发。实际登录、生成质量与下载流程由用户在浏览器中完成。

### 1.3 管理与识别图片

资源卡片提供：

- **编辑说明**：修改标题、内容说明、检索标签、用途。支持封面、插图、截图、视觉参考四类用途。
- **搜索与筛选**：按标题、说明、标签和识图内容检索，按主要用途筛选。
- **AI 识图分析**：把图片的压缩预览真正发送到视觉模型，分析可见内容、风格、构图、文字、建议用途与配色。
- **分析色值**：保留原来的轻量配色分析，仅将本地提取的色值、占比与公众号定位发送给文本模型。
- **应用配色**：先修改建议色值，再应用到当前公众号；新文章将使用更新后的主题色。
- **推荐已有资源**：在图位按内容、用途、比例、颜色排序，展示理由；由你预览后选择。

AI 识图会补充空白说明和标签，保留已经填好的内容。可见文字属于模型转录，仍需人工核对。分析结果不会自动修改公众号配色，也不负责确认图片的身份、版权或事实真实性。

### 1.4 配置视觉模型

「模型与设置」页底部新增独立视觉模型配置：

1. 选择通义千问、智谱、Kimi 或火山方舟的供应商；先在上方保存该供应商 Key。
2. 填写控制台当前可用、支持图片输入的模型 ID。正文模型 ID 和角色路由无需调整。
3. 点击「测试识图」。程序发送小图片并核对颜色和形状，可能产生供应商调用费用。
4. 测试通过后，在资源箱点击「AI 识图分析」。

视觉模型使用供应商现有的 Key 和地址，但有独立模型 ID 与验证状态。更换视觉模型后需要重新测试。识图不回退到纯文本模型，不将“只分析色值”标记为“已经识图”。

图片最长边缩至1280像素，转换为JPEG并去除EXIF等元数据；透明区域合成暖白背景。发送前检查归档路径与SHA256，防止资源被外部修改。主题建议仅可选自本地提色表，不能凭模型估计添加新的色值。

## 2. 开发结构

```text
Electron 主进程
  ├─ 原生剪贴板：复制用户查看的完整提示词
  ├─ 系统浏览器：打开固定的 TapNow 地址
  ├─ 隐藏截图窗口：capture.html → capturePage → PNG
  └─ 本地 JSON Lines API → Python / SQLite
       ├─ assets.capture_context / capture_finish：运行证据校验、图位归档
       ├─ resources.update：图片说明与标签的版本校验保存
       ├─ vision.save / probe：独立视觉配置及识图验证
       ├─ resources.vision：图片输入与结构化视觉分析
       ├─ resources.recommend / use：资源推荐、确认后复制到文章
       └─ assets.import：手动生成图片的验证、文章候选与资源箱归档
```

关键源文件：

| 文件 | 作用 |
|---|---|
| `ice_agent/visual_assets.py` | 图片压缩、识图测试、内容分析、资源排序 |
| `ice_agent/llm/router.py` | 图片消息、视觉能力过滤、JSON修复时保留图片 |
| `ice_agent/workspace_assets.py` | 资源哈希、说明保存、路径与文件完整性检查 |
| `ice_agent/desktop_service.py` | 视觉与截图API、候选归档、公众号隔离 |
| `desktop/main.cjs` / `preload.cjs` | 剪贴板、默认浏览器、原生截图与IPC边界 |
| `desktop/renderer/visual.js` / `visual.css` | 资源工作台、说明编辑、识图配置、候选推荐 |
| `desktop/renderer/capture.*` | 实际运行记录截图页面 |

## 3. 数据与一致性

资源保存在原有 `publication_resources.metadata_json`，新增字段保持向后兼容：`description`、`tags`、`usage`、`visual_analysis`、`metadata_source`、截图的`capture_hash`。读取时计算`content_hash`，修改与识图落盘前再次校验版本。

截图候选标注`source=run_capture`，截图事件记录`run_id`、`code_sha256`和`output_sha256`。候选文件与资源箱都使用归档副本；截图不会改变原始运行记录。完成截图前再次校验图位、正文、运行记录是否与开始时一致。

推荐采用可解释的本地规则：内容关联最多55分、用途20分、比例15分、配色10分。评分用于相对排序，未匹配到内容时明确提醒人工核对；截图只从标注为截图的资源中推荐。不能以资源推荐替代本篇代码执行证明。

用户选择推荐资源前，程序再次校验资源版本、文件哈希、图位版本和公众号归属。选用只复制归档图片；发布就绪仍需最终检查。手动图片先成为待审候选，资源箱归档与提色成功后才登记选用；全透明图片等归档失败时保留原有选图。

渲染进程不能指定任意截图落盘路径，不能直接调用`assets.capture_finish`；由主进程生成PNG并将限定目录内的路径交给侧车。截图页用`textContent`展示源码和输出，防止运行记录被解释成HTML或脚本。

## 4. 验证与边界

本轮测试使用隔离运行目录、离线示例和假模型传输，没有调用用户付费模型或TapNow生图。

全量139项Python回归通过；最后的手动图片归档调整与透明图边界由15项视觉专项验证，共覆盖140项独立Python用例。Node20项、源码编译和语法检查通过。Electron验收还确认资源箱能实际加载4个图位，画面完成绘制后才保存验收截图。

覆盖真实图片消息、能力过滤、JSON修复、图像压缩、独立模型设置、识图验证失败、编辑版本冲突、手动说明保留、图片篡改、实测色值约束、运行证据校验、跨账号和过期截图拒绝。实际Electron测试执行示例代码后调用原生`capturePage`，核对PNG候选、资源归档、提示词复制与新页面交互。

模型真实识图效果须在用户配置供应商后，通过「测试识图」及实际资源验证。TapNow网站真实登录、生成与下载没有在离线验收中调用。官方MCP自动生成、外部应用自动操作、公众号在线同步和自动发布仍属于后续范围。
