# 工作流审阅与运行取消迭代

交付目标：通用 Windows 桌面版。此次更新源码与验收材料，未覆盖旧安装包，未操作用户文章或进行真实付费模型调用。长期“可上线”目标仍在进行。

## 实际使用变化

新工作台右侧制作任务可直接进入“文章制作与审阅”，沿用已有后端审批与执行接口。

- 选题：修改候选标题和核心角度，选择任一方向；提交真实选择序号，避免始终采用AI默认方向。
- 大纲：修改工作标题、章节标题和目标，保留小节、要点、代码及配图信息。
- 最终标题：修改或改选候选；单独保存不推进任务，确认才继续。
- 配图计划：显示图位、用途、位置和获取方式；确认后继续。此处不支持改写方案，TapNow生图及公众号发布仍由用户手动完成。
- 程序执行：显示实际源码及唯一输入键，每段填写示例输入，可标记预期报错。需明确勾选审阅后才批准；改输入会重置本地确认。服务器仍校验内容hash，前端不会绕过批准门。
- 运行结果：可展开和复制真实标准输出/错误，显示通过、超时、报错或已停止等中文状态。
- 暂停：制作过程中可在面板暂停；有后台执行占用时显示“正在停止当前程序”，释放后显示暂停。已暂停任务也能再次进入审阅，确认后继续。

## 编辑与状态保护

修改方案时关闭弹窗会提示继续编辑或放弃；切会话、账号及编辑器导航继续使用已有flush保护。操作期间禁止重复提交；失败保留当前输入。其他窗口已更新方案时，旧hash被后端拒绝；可复制修改、关闭后重开读取新版本。

轮询只在任务运行、等待后续步骤或尚未释放执行占用时加速；静止后停止面板轮询。页面以真实节点状态和Spinner反馈，不显示编造的进度百分比。使用现有Radix Dialog、Motion及设计tokens，没有新增UI依赖；审阅面板按需加载。

修复本轮发现的两个前端状态问题：保存候选后内容hash更新不再导致组件重建、丢失选中的方向；本地刚保存的新hash不会被旧Query缓存反写覆盖。

## 真正停止教学程序

`execute_bounded`增加可选停止回调，在启动前与运行等待中检查。只终止本次独立进程树；Windows继续通过创建时挂起、加入私有Job再恢复的方式约束子进程，避免后台子程序逃过正常回收。

CodeRunner覆盖Python执行、Java编译/运行、Docker准备与运行客户端。Docker在停止后仍执行专属容器清理，不让取消信号取消清理动作。真实Docker引擎尚未实测，本轮只验证其命令与清理契约；没有自动下载镜像。

引擎将任务暂停/取消/失租/关闭的停止条件接到Runner，退出后恢复旧回调，避免留下上一任务的闭包。已停止的运行保留真实部分输出、取消标记及清理记录；`verdict=cancelled`独立于超时和预期报错，不采纳为成功，不推进到证据整合。启动前即被取消的程序明确记`process_started=false`，不误报已回收进程；未向Docker发送run请求时不删除不存在的容器。只移除本次具有所有权标记的运行目录，文章、历史运行证据与其他文件保留。

这不是对任意不可信源码的完整安全沙箱：本机执行仍需要代码审阅；已有静态扫描及进程边界继续保留。发布前还需验证旧队列/旧文章中宽泛批准标志的升级处理。
