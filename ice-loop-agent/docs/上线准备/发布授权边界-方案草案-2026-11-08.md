# 发布授权边界：方案草案（2026-11-08）

> 状态：**草案，待决定**。本文只界定边界和需要作者/产品决定的事项，**没有实现任何发布、群发或定时功能**，代码里也没有调用发布接口。开发报告规定“自动发布另立需求与授权边界”，本文是这份需求的起点；未经明确授权，不进入实现。

## 1. 现在做到哪一步

| 能力 | 状态 | 说明 |
|---|---|---|
| 复制 / 导出图文包 / 长图 | 已有 | 人工到后台粘贴、发布 |
| 同步到草稿箱（单篇、多图文） | v3.22–v3.24 | 只用素材与草稿接口；写入前记日志、后台改动冲突、结果未知先核对 |
| 留言、封面裁切 | v3.23 | 随草稿写入 |

| 提交发布 / 群发 / 定时 | **没有** | 本文讨论范围 |

## 2. 需要区分的四个动作

“发布”在公众号里不是一件事，界面和记录必须分开，不能用前一个推断后一个：

1. **草稿已同步**：草稿箱里有这篇；读者看不到。（已有）
2. **发布已提交**：接口受理了发布请求，结果异步产生，可能被审核拦下或失败。
3. **已发布**：拿到可验证的终态和文章链接。发布与群发的区别（是否推送给粉丝、是否出现在消息列表）以官方文档为准，见第 5 节待核实项。
4. **群发已完成**：推送给粉丝，有次数额度、接收范围，**不可撤回**到“没发生过”。

建议：如进入实现，**第一期只做 2→3（提交发布 + 结果对账）**，不做群发和定时。群发影响面最大且受额度限制，单独立项。

## 3. 建议的授权模型（供决定）

**账号级开关（默认关闭）**
- “公众号接口”设置里单独一项“允许从本应用提交发布”，默认关。打开时说明会调用哪些接口、会产生什么后果、怎样关闭。
- 只对已通过“测试连接”且具备相应接口权限的公众号可开；权限不足时显示原因，退回“到后台发布”。
- 关掉开关立即生效；正在进行的对账不受影响，但不再提交新的发布。

**每次发布的确认（不可跳过）**
- 确认框列出：目标公众号名称与 AppID 尾号、标题、封面、交付版本时间、草稿 ID、多图文的篇目与顺序。
- 确认绑定 **冻结版本 + 草稿 ID + 后台正文指纹**。确认后到提交前，任何一项变化（正文改了、后台草稿被改、换了公众号）都使确认失效，必须重新确认。
- 提交前再回读一次草稿，与确认时的指纹比对；不一致就停下。
- 不提供“以后不再询问”。批量发布、按规则自动发布不在第一期。

**对账**
- 提交前记操作日志；拿到发布任务标识后轮询状态，取得终态与链接才标记“已发布”，并自动生成一条发布登记（标注“接口核验”，与“作者登记”区分）。
- 超时或结果未知：进入“待核对”，不重复提交；作者到后台确认后再处理。
- 审核拦截、失败：如实显示原因，草稿保留。

## 4. 需要作者决定的事项

1. 第一期是否只做“提交发布 + 对账”，群发、定时都不做？（建议：是）
2. 账号级开关是否需要二次验证（例如再输入一次 AppSecret，或系统登录确认）？
3. 多图文是否允许发布？（建议：允许，确认框逐篇列出）
4. 发布成功后是否自动生成发布登记？（建议：自动生成，标注“接口核验”，作者可补充）
5. 是否要“撤回/删除已发布文章”？（建议：不做；影响已读者，留在后台人工处理）
6. 应用关闭时的对账：下次打开时继续查询即可，还是需要常驻？（建议：下次打开继续，不做常驻）

## 5. 实现前必须核实（不凭记忆写死）

- 发布接口的当前字段、返回的任务标识、状态查询方式与终态取值；发布后文章链接的获取方式。
- 哪些主体类型、认证状态的公众号具备发布接口权限；个人订阅号的限制。
- 发布是否占用群发额度、是否推送、是否出现在历史消息里；审核拦截时的返回。
- 频率限制与错误码；IP 白名单要求是否与草稿接口相同。

核实结果写进本文第 5 节，并给出接口能力表后，才进入开发。

## 6. 验收（进入实现后）

- 开关关闭时界面上没有任何发布入口；接口层也拒绝发布调用（不只是隐藏按钮）。
- 确认后修改正文 / 后台改草稿 / 切换公众号：提交被拒绝并要求重新确认。
- 网络中断在提交后：进入待核对，不重复提交；重复点击只产生一次提交。
- 审核拦截、权限被撤销、令牌过期：如实显示，不标记为已发布。
- 真实测试账号走完：同步草稿 → 确认 → 提交 → 拿到链接 → 自动登记，链接可打开且与交付版本一致。
