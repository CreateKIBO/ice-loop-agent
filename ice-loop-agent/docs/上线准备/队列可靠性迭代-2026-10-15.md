# 队列可靠性与 Agent 任务入口迭代

本轮针对任务卡住、重复建稿、状态误报与模型任务参数边界做了实际修复。完整上线目标仍在进行，未生成或覆盖安装包。

## 行为改进

- 暂停是可恢复且可见的状态。`awaiting_user`不再被误判为推进失败而重试；引擎取消、失败、人工等待与持久化队列一致。
- 取消请求不被晚到的成功覆盖。旧租约不暂停新持有者的job，状态提交失败也不再假报成功。暂停检查与写入在同一事务，异常跨账号绑定拒绝操作其他公众号文章。
- 长步骤有独立连接持续心跳。取消、关闭和失租信号传到引擎、节点与模型回调；协作节点在执行中停止，不进入下一步。监控线程结束后回收，不使用循环创建新引擎来续租。
- 文章、job、数据库检查点、事件与队列绑定一次提交。绑定故障全部回滚；提交后state文件镜像写失败仍可复用原job，避免重试重复建稿。
- 程序重启后，有绑定的中断任务可见地暂停，尚未启动引擎的无绑定任务重排。直接记录审批决定后也能复用原job推进到下一道真实审核门。
- 空闲队列轮询只读数据库元数据，不再每3秒加载当前账号品牌、资源与模型路由。新建任务采用全局模型调用预算。
- Agent工具只接受当前可执行的`production`类型。缺失spec、无效栏目/期号/主题或跨账号请求会立即报错；旧无消费者类型显式失败，不永远排队。
- 模型提交的目录、账号、字数、执行策略和历史不作为授权。服务端按公众号配置填充这些字段，剔除伪造的确认与锁定标题；新工具入口强制未批准本机代码执行。保留episode>10的合法生产需求与幂等能力。
- `prepare_execution`的第二条数据库连接在成功/异常路径都关闭。任务查询补充真实job、节点与原因。
- 新工作台显示中文审阅/处理状态，暂停或中断原因可以展开、复制。引擎退出增加不含请求正文或Key的退出码诊断。
