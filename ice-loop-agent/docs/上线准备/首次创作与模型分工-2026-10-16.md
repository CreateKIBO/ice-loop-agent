# 首次创作与模型分工验收

本轮解决新用户虽然保存模型Key，却没有把模型接入写作流程的问题，并把公众号资料、历史文章到第一份初稿连接起来。所有操作在E盘当前工作区完成，个人运行副本未改。

## 产品变化

1. 模型就绪状态与实际请求一致：只检查writer的主模型和回退链。已配Key但未进入写作链时，明确提示设置模型分工；链内未测试与已验证分别显示。
2. 新界面支持创作/正文、选题/大纲、素材、审校、标题、代码六个文字环节的模型选择，也能统一分配。分工适用于所有公众号的后续创作，已有任务保留原快照；视觉配置和思考策略不自动改变。
3. 开始指南显示当前公众号，可直接新增/导入自己的品牌，打开历史目录页。选择栏目，写下要求后带入对话输入框，并选择初稿或讨论模式；用户检查后发送。左栏和命令面板可返回指南。
4. 创作要求按账号恢复，换号不会串入旧账号文本。单槽输入交接有长度限制，支持React StrictMode重复初始化；即使本地存储被禁用，已输入要求仍能带入新会话，不自动发送。

## 保存与边界

新增`models.routes_save`接受显式`account_id`、`routes_hash`与`routes`。路由仅允许六个文字角色，每个角色包含primary、fallbacks、thinking_policy；整批校验后原子写入。旧配置版本、切号、未知模型、无效思考策略、重复回退、视觉角色等输入被拒绝。只改路由，不回写模型ID、预算、品牌或已有任务。

界面保留脏选择，旧响应不覆盖正在编辑的分工；关闭和重新载入有确认。保存/重新载入响应校验账号后才能安装到当前缓存。原来新建会话在请求途中切号可能继续选择旧账号会话，也补上返回前的账号检查。
