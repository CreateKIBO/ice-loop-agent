# 图片内存与旧任务兼容迭代

本轮面向用户已确认的通用 Windows 桌面版：本地保存、多公众号各自配置，TapNow 生图与公众号发布仍由用户操作。当前为源码迭代与验证进展，尚未生成新安装包，不能据此认定完整上线验收结束。

## 已实现

### 图片查看与内存

- 新工作台的缩略图、原图经过同一队列，一次只发起一个真实图片 RPC；原图优先于尚未开始的缩略图。离开页面或切换账号时撤销排队任务，活动 RPC 真正返回前仍占用容量，避免“界面取消”造成后台并发失控。
- 缩略图使用组件拥有的短生命周期 Blob URL，不再把图片 base64 保存在 Query 缓存。原图与缩略图卸载都撤销 URL，晚返回的图片不会挂回已关闭页面。
- Pillow 的校验、预览、导入调色板与视觉参考编码共用可重入解码门；只覆盖像素处理，不跨越数据库写入、模型调用或网络请求。真实写事务与并发预览测试覆盖了锁顺序问题。
- 提前检查图片响应长度，再解析 MIME/base64；保留原始文件 hash 校验、账户归属与真实尺寸查看。

测量使用两个新 Python 进程，同样同时读取六张 2400×1800（4.32MP）图片，采样间隔约 5ms，输出 PNG 字节 SHA256 全部一致：

| 指标 | 原实现 | 有界实现 |
|---|---:|---:|
| 峰值进程私有提交量 | 381,943,808 B，约 364.25 MiB | 76,972,032 B，约 73.41 MiB |
| 峰值工作集 | 380,211,200 B | 86,503,424 B |
| 六张图全部完成 | 234 ms | 485 ms |

该样本的私有提交峰值下降约 80%，代价是这组请求整体多约 251ms。私有提交量与物理内存工作集含义不同，指标口径见 [Microsoft PROCESS_MEMORY_COUNTERS_EX](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex)。这不是整个 Electron 应用 RAM，也不是 40MP 图片最坏情况或长时间稳定性结论。可重入锁语义见 [Python threading.RLock](https://docs.python.org/3.12/library/threading.html#rlock-objects)。原始测量：`image-memory-bench.json`，脚本：`image_memory_bench.py`。

仍需另验裁剪/封面合成持有大像素对象的生命周期，不能把所有图片转换的峰值都写成已经解决。

### 未绑定旧队列

- `production_spec` 统一校验主题、栏目、期数、账号与生产模式。账号快照、输出目录、字数、执行模式、容器映像、真实文章历史均由服务端填写。
- 旧 raw payload 的宽泛执行批准、伪造历史/标题确认/输出目录不会成为权限来源。任务尚未建稿时，清除 `approve_local_exec`。
- 原始任务 payload 和幂等 hash 保留；归一化结果用于新 job，而非重写重放输入。既有明确的离线 demo 标记保留，不能升级时意外变成付费请求。

### 已绑定旧任务与目录冻结

- 在现有持久化 job 事件中新增版本化 `job.desktop_context`，记录服务端选定的账号、输出目录与受控离线演示许可；用户或模型提交的 spec/account_snapshot 不能充当该记录。无新 SQL schema，也没有改动历史迁移函数或 checksum。
- 新建桌面任务、生产队列、补图任务均在创建 job 的原事务内记入上下文；绑定失败时任务、文章、检查点和记录一起回滚。
- 已有记录的任务继续使用创建时目录，之后修改公众号目录不会重定向已有任务；后台队列也经同一 `_job_app` 恢复入口，不能再绕过目录冻结。
- 缺少记录的旧任务第一次接入桌面时，用所属公众号当前设置作为**未来输出目录**，补图仍进入 `补图候选`。原有导出文件、版本和运行证据不移动、不删除。文章 spec、数据库 checkpoint、兼容审计事件在同一事务更新。
- 旧宽泛 boolean 清除；与当前正文/输入/执行环境完全匹配的 `execution_approval` hash 保留。未获得有效审批的旧执行环境改用当前配置；已有有效逐次审批的环境保持原样，以免篡改审批对象。
- 正在持有引擎 lease 的旧检查点不会被读取请求改写，应先暂停再恢复。账号冲突、检查点损坏会明确拒绝。仅有旧 state.json 的任务会建立数据库检查点，此后由现有 hash 校验读取。
- 已接入的日常轮询走只读元数据路径，不重新解码整篇正文、不申请额外写锁。CLI 的显式执行开关语义没有被重定义；桌面代码运行提示改为引导进入审阅面板。

边界：旧任务没有可信目录记录时，无法凭 raw spec 证明历史目录确由用户指定，因此未来输出采用当前账号设置，并留下审计说明；不会声称恢复了无法验证的旧目录批准。该机制也不试图对抗用户直接编辑数据库。
