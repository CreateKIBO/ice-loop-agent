# 可插拔技能系统：产品与迁移方案

日期：2026-11-05。源码核对基线 main@480e83a。本文为一体化公众号 Agent 路线的完整设计。

首期进展：已实现按公众号选择/停用一个主写作技能，修改指令与规则、新建/移除、并发保护、生成与审阅接入、任务/重试快照。见[第30轮实施与验收](../迭代任务/Codex-持续迭代第30轮-2026-11-05.md)。下文的多技能组合、技能包导入导出、栏目/文章作用域与云端共享等仍为后续目标。

## 1. 用户要求与产品行为

用户自己的写作方法作为默认预装技能；使用者可以查看、修改、复制、启用、停用、卸载、导入和导出技能。文章、审阅、配图、排版与发布准备都可使用适用技能。技能修改不要求改源码或重新打包。

- 首次初始化安装默认写作技能，并明确展示来源与启用状态。用户修改时保存自己的版本；原版可作为可选恢复来源，不覆盖用户修改。
- 用户停用或卸载后，重启、升级、新建公众号都不偷偷重新启用。记录初始化状态及卸载标记；“恢复默认技能”由用户主动触发。
- 默认写作方法与 ICE Loop 品牌配置分开：方法可作为产品预装项，ICE 的读者、人设、口号、栏目和配色只绑定到对应公众号，不强加给其他账号。
- 没有额外写作技能时仍能进行普通创作。导出只检查当前有效的写作规则及平台实际约束，不继续要求已卸载技能的固定结尾、教学练习或标点习惯。

## 2. 当前源码与迁移依据

| 位置 | 当前情况 | 迁移要求 |
| --- | --- | --- |
| `ice_agent/rules/sources.py` | 来源、优先级、六类结构化规则、同优先级冲突裁定、来源 hash | 复用来源与冲突思想，扩展为技能安装/绑定/版本解析；不重复造另一套规则真相 |
| `profiles/ice-loop.json` | 默认品牌与文章规范 | 分拆写作方法、品牌档案、执行/存储配置，避免全部塞进写作技能 |
| `ice_agent/accounts.py` | 公众号配置转换，generic 账号已有规则放宽 | 接入技能解析后的配置；支持“未启用固定结尾”等显式空值/关闭状态 |
| `ice_agent/prompts/__init__.py` | ICE 分支含固定教学结构、语气、标点、结尾；general 分支已较通用 | 将个人方法移入技能，保留节点职责和输出契约；平台 guard 中混入的品牌内容拆出 |
| `ice_agent/rules/structural.py`、`brand.py` | 最终检查由配置与部分固定逻辑驱动 | 约束和对应提示必须同源；停用技能后相关风格阻断一并停用 |
| `ice_agent/creative_chat.py` | 对话用 profile_from_account 构造上下文 | 与生产工作流、审阅工具统一调用同一技能解析器，不能只改生产链 |
| `ice_agent/agent/registry.py` | 工具能力和参数/权限注册表固定 | 技能声明要用哪些既有能力，但不能凭文本注册可执行工具或改变权限 |

旧的 RuleSources 优先级是现有规则，不等于新技能层级已实现；迁移需保留原来源与裁定，提供实际生效预览。

## 3. 设置界面

设置 → 技能：按“写作 / 审阅 / 配图 / 排版 / 发布准备”筛选。

技能卡显示名称、作者/来源、类型、版本、启用范围和当前状态。操作：编辑、复制、启停、卸载、导出、版本历史；页面提供导入和新建入口。

技能详情包括：用途与触发阶段、指令正文、示例/参考文件、结构化参数、依赖的既有工具、版本差异、测试运行与生效预览。

适用范围：个人默认 → 公众号 → 栏目 → 单篇文章/会话。组织共享为后续能力，团队管理员约束与个人偏好分别展示。公众号可单独保存技能组合，例如技术教程、品牌新闻、生活随笔。

文章页面显示“本篇使用：基础写作 v1 / 教程方法 v2 / 品牌规范 v3”，可以查看具体来源。当前模式不适用的技能不会全部拼入提示词。

## 4. 技能包格式与导入

建议自有包结构：

```text
my-writing-skill/
  skill.json
  SKILL.md
  references/
  examples/
```

`skill.json` 声明 schema_version、id、name、version、description、阶段/用途、语言、指令入口、引用清单、结构化参数和需要的已注册工具。包 ID 不是信任证明，导入时分配安装身份并保存来源、hash、原始 ID 与所属用户。

首期支持单个 Markdown 文件，以及上述目录/ZIP。Markdown 可从简单文本导入，缺少元信息时由界面补齐；不要求普通用户写 JSON。外部 SKILL.md 可导入为说明型技能，但前置格式不同、引用缺失、脚本/外部连接等不能自动宣称完全兼容。

导入过程：读取 → 校验/限制大小 → 展示内容与来源 → 提示缺失引用、冲突和所需能力 → 确认安装范围 → 试运行。ZIP 拒绝路径穿越、链接和过度解压；只导入被声明且位于包内的文件。首期技能由文本、参数、示例、模板引用组成，不自动安装依赖或运行导入包里的脚本。

用户若需要自定义可执行能力，后续通过独立插件机制注册、校验和授权；可插拔写作方法不要求开放任意代码执行。

## 5. 技能内容与执行边界

技能适合表达：写作步骤、选题方法、语气、结构、标题策略、示例、审阅清单、品牌排版方法，以及经 schema 校验的规则参数。

区分两类要求：

- 可配置方法与风格：固定结尾、段落长度、禁用词、编号习惯、是否需要代码等，可随技能关闭或被用户修改。
- 应用执行边界：账号归属、工具参数、已批准动作与版本、预算授权、凭据访问和发布权限，由程序执行。安装技能本身不代表授权发布、文件访问或收费调用。

技能文本里的“忽略权限”“上传密钥”等内容不变成工具授权。引用文章、网页和参考文件仍是资料，不因放进技能包就升级为系统级权限。

## 6. 解析与冲突

建议由 `SkillResolver` 对阶段、目标账号、任务和用户选择产生唯一的有效技能集合、规则配置与来源说明。调用方只消费解析结果。

- 默认选择顺序：本次明确选择 → 本篇绑定 → 栏目绑定 → 公众号绑定 → 个人默认。先按适用阶段筛选，不默认启用所有已安装技能。
- 基础写作方法、主要文风与辅助能力可以组合；两个互相排斥的主要文风应提示选择。
- 结构化字段按明确作用域解析，同层冲突展示来源/值供用户裁定；不能仅按导入时间最后一项覆盖。
- 自由文本冲突无法保证自动完全识别。首期采用主技能选择、结构化参数检查和生效预览；语义冲突诊断可辅助，不能冒充确定性保证。
- 用户当前需求与品牌必需规则相矛盾时展示冲突并允许修改配置/选择，避免模型凭猜测同时满足。
- 只加载当前阶段必要的指令和引用，设置上下文预算；被省略的必需内容明确提示，不静默截断。

适用场景：对话、选题、骨架、初稿、改稿、审阅、配图提示词、排版建议和发布预检。生成提示与程序化检查使用同一个规则快照。

## 7. 存储、版本与删除

拟议实体：skill_packages、skill_versions、skill_bindings、skill_install_state、skill_resolution_snapshots。沿用现有迁移框架，所有记录有用户/工作区边界；跨用户分享通过显式共享/导出，不共享私有引用或凭据。

编辑产生新版本并记录来源关系。内置技能的个人修改版本可直接在界面编辑；应用升级提供新版与差异，不自动覆盖。升级时检查参数 schema 与依赖能力，失败保留原可用版本。

生成/任务开始时冻结 skill ID、版本、内容 hash、作用域与规则解析结果，并与文章候选或正文版本关联。在途任务和失败重试默认使用原快照；用户显式切换技能后新建运行身份，不让重试悄悄换文风。

卸载移除可用安装与未来绑定；历史文章保留必要的使用记录/快照，便于解释原稿为何这样生成。彻底清理用户资料是单独的数据删除操作，不能借卸载技能连带删除稿件或资产。

## 8. 实施顺序与验收

1. 抽离现有个人写作方法，定义默认技能包和无个性化技能的通用配置。列出每条提示与对应校验器，建立迁移映射。
2. 新增包存储、版本、安装状态、绑定、解析与快照；先用已有规则来源覆盖冲突案例。
3. 接通真实对话、生产生成、审阅和导出检查，完成启停端到端行为，再加设置面板与 Markdown/包导入导出。
4. 接入设计/排版技能和后续微信发布准备技能；复用同一安装机制。

首批必须验证：

- 默认技能开时保持原写作预期；关/卸载后，生成与审阅都不再强制 ICE 固定结尾、口号、教学结构或标点风格。
- 关闭全部额外写作技能仍可完成普通文章；旧任务与旧稿仍可读取，不丢证据与图片。
- 导入新技能可见来源、范围与实际生效内容；改版、重启、应用升级不会复活已卸载技能或覆盖个人修改。
- 对话与生产链使用相同组合时解析结果一致；同层冲突可重现、可裁定，跨账号/用户不串技能。
- 在途任务/重试的快照稳定；切换当前公众号不影响后台任务所属技能与账号。
- 导入恶意路径/超大包/缺失引用时明确失败；技能不能增加发布授权或读取凭据。

建议将本模块放入一体化产品路线早期，与设计文档契约一起完成，避免后续把个人写作与排版风格再次写死。
