# 通用 Windows 桌面版：阶段研发与验收进展

目标是可分发的通用本地桌面软件，用户导入自己的公众号、设置模型后使用。本报告记录本阶段完成的源码修复和测量证据；**完整上线目标仍在进行，当前不是正式发行通过声明**。

## 已完成的实际修复

1. 审批后队列恢复：修复`now_iso`未定义导致的运行异常；按账号筛选对账，不误重排其他公众号的等待任务。
2. 后台账号与品牌：引擎按任务持久化归属创建，恢复时读取原账号、文章目录与冻结规则快照，前台切号不再改变后台内容上下文。
3. 任务资源回收：已完成Future移出映射，旧回调不移除新任务；处理`Future.cancel()`同步回调的锁重入，修复扩大测试时实际捕获的取消死锁。
4. 内存：事件缓存限制20流、估算5MiB、闲置15分钟，每流最多400项/512KiB尾部；账号切换清引用、选择与事件缓存。将会话轮询策略移到模块级函数，避免Query保留组件闭包及旧事件数组。
5. 编辑可靠性：自动草稿与正文保存按顺序写入；保存期间继续输入不会被返回结果覆盖或误标已保存；新版本成功才更新基线，后续保存不会误报旧哈希冲突；恢复草稿与保存版本同步，避免反复提示恢复旧稿。
6. 空稿恢复：允许保存和恢复空工作草稿，导航前正常落盘；正式正文继续拒绝空字符串。相同草稿内容换基线时也更新恢复记录。
7. 编辑界面：CodeMirror外部恢复/刷新可见内容同步，异步回调使用最新值；恢复读取失败明确显示，丢弃失败不伪装成功；刷新前保留草稿。保存固定在主操作行右侧，次操作分组，显示字符数，三种窗口宽度验证通过。

## 内存测量应怎样理解

相同负载下，仅加缓存限制时，渲染进程JS堆在40会话后约25.08MiB。修复Query闭包保留后约11.10MiB；热身后第20到40会话增长约0.40MiB，DOM节点704、监听器293稳定。

该次源码Electron的全进程树工作集之和约405.27→438.75MiB，私有提交字节约269.62→315.73MiB。工作集求和可能重复统计共享页，私有提交量不等于物理RAM；**11.10MiB只是渲染器JS堆，不能声称整个程序仅占11MiB内存**。这也不替代冻结版、长会话或大量图片的内存验收。
