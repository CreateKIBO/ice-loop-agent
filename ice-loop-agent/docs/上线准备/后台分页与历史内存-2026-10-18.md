# 后台分页、历史搜索与内存优化（2026-10-18）

继续使用 E 盘。该批次修复“页面只显示十条，后台却传回全部”“为选出五篇正文先把所有正文读进内存”的实际路径。完整可分发桌面 Agent 目标仍在进行。

## 现在的行为

- 新界面大纲、历史记录使用真正的 SQLite 分页，每次10条，不再把全部元数据送到前端再切片。支持标题/期号搜索、历史发布状态筛选、空结果反馈及页面读取状态；搜索有200ms合并窗口，读取期间不能误选旧结果。
- 选择任意期题时精确读取对应行和本栏目下一期，不依赖已经加载的那一页。新建创作页不再先加载整个大纲或历史列表。
- 历史记录新增“查看原文”，只读单篇索引/发布快照；不在列表传输所有正文。未登记为发布的内容仍标为草稿。
- 翻历史页不反复扫描外部资料目录；打开时由历史上下文完成同步，用户点击“刷新历史与题目”时先同步再读取页面。登记发布后也会读取最新记录。
- 默认下一期期号回填不再触发一次相同的全历史读取；用户手选期号后仍按所选期号更新参考内容。
- 旧客户端未传 `page_size` 时继续得到原列表形状；旧版 `outlines.match` 的选择清单保留，新界面显式关闭它，只读取目标与下一期。

## 内部修复与保持的契约

`EditorialTopics.get/match/update` 直接按账号、栏目/期号或身份查询，不再为了读取一条而调用完整 `list()`。预览与保存只查涉及的原期题；新界面保存使用 `return_rows:false`，不在确认导入后又收到整张表。

大纲 `base_hash` 按行流式编码，保持原 `sha256_json({columns,rows})` 的**完全相同字节与哈希**，不为哈希而保留所有长备注。旧确认与并发冲突检查不绕过。

`PublicationHistory.records(bodies=False)`、外部资料索引、草稿/文章索引按行读取。上下文只保留同栏目的元数据与确认哈希，再精确取回选中的五篇完整正文，发布快照优先、不同期号去重、已选期之前的范围与原行为相同。全部历史标题默认仍交给模型，没有截断。

新界面不需要标题全表，仅显式请求 `include_titles:false`，仍取得真实标题数量、相同确认哈希和五篇全文；模型请求默认不使用该选项。单篇 `history.get` 与创作会话的历史引用也改为精确查询。

分页参数校验大小1–100、页码范围、当前公众号栏目、搜索词与状态，使用字面量SQL和绑定参数。计数、页码夹取与取行在同一事务内完成，数据缩减时不会返回一个越界空页。每次翻页读取最新数据，不宣称整个多页浏览过程是冻结快照；编辑保存仍用记录哈希拒绝过期覆盖。
