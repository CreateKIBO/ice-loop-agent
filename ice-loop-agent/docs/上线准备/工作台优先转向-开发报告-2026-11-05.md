## 1. 定位、范围与文档关系

产品定位：**这个公众号自己的、有记忆的写作台。**

主流程是已有稿件的管理、编辑、图文排版与交付；Agent 复用公众号历史、技能和品牌上下文，提供可追溯、可撤销的辅助。保留整篇生成作为内容入口，不要求所有文章经过生成流水线。

首批目标用户建议为：已有稿件、持续运营一个或多个公众号的个人或小团队。该目标仍需通过真实用户验证，不能把“普通公众号作者”视为已经证实的统一市场。

本次明确的需求边界：

- 面向普通公众号；系列、期号、教学结构与“前五篇文章”策略可选。
- 移除新任务中的代码执行、终端输出回填与终端截图能力。
- 浏览器支持普通网页访问与收藏，TapNow、微信后台是默认收藏项。
- 文章工作台为首页，助手有独立入口；手动、粘贴和 AI 产出使用共同编辑体系。
- 支持已有文章的文字、图片、基础样式编辑；Agent 可读取授权稿件并提出修改。
- 保留整篇 AI 生成、模型路由、预算、账号隔离、版本和备份。
- Windows/Electron、本地存储优先，当前交付通过微信后台人工完成。

本地优先的准确含义是文章库、资源、配置和收藏主要保存在本机。使用云端模型时，被选择的上下文会发送至对应服务；访问网页也产生网络请求。不得宣传“所有内容从不离开本机”。

文档优先关系：本报告规定当前实施范围；[首轮评审](工作台优先转向-产品架构评审与实施建议-2026-11-05.md)保留为讨论过程。此前[一体化产品与云端发布路线](一体化公众号Agent-产品与技术路线-2026-11-05.md)是历史探索，其中云端授权、自动发布、群发与云端多租户服务不列入本次转向验收。[v2.0 实施状态](../v2.0/IMPLEMENTATION_STATUS.md)记录旧架构下的实现，不能直接作为新工作台完成证据。

## 4. 信息架构与操作规则

### 4.1 首页与文章编辑

文章首页包含当前公众号切换、搜索/筛选、“继续编辑”和文章列表。新建默认“空白文章”，菜单提供“粘贴已有文章”和“AI 起草”。模型未配置不阻断这些手动入口。

列表显示标题、编辑时间、保存/生成/交付相关标记；来源、生命周期、生成状态和发布记录分别建模，不把“AI 初稿”“草稿”“已发布”混成无法组合的单个状态。

文章编辑器顶部显示标题、保存状态、手机宽预览和交付。样式、图片、历史放在可收起面板；文章内助手于 P1 完善。手机宽预览只是本地近似，不称为微信真实手机预览。

素材先通过文章首页标签和编辑器图片抽屉管理；发布登记在文章详情及列表筛选中完成。独立素材库页、发布记录页在跨文章需求被验证后再评估。

### 4.2 无 AI 主流程

新建/粘贴 → 检查导入报告 → 编辑文字与图片 → 调整基础排版 → 保存/预览 → 复制或导出图片包 → 微信后台保存/手机预览/发布 → 登记链接与交付版本。

验收指标：上述流程中必须进入 AI 页面、必须等待模型或必须填写栏目/期号的步骤为零。

### 4.3 生成与修改

整篇生成作为后台任务，用户可以继续编辑另一篇文章。生成运行拥有独立结果缓冲；成功后创建新文章和第一版，不向当前编辑缓冲区持续写入正文。失败、取消或不完整输出明确标记，不能冒充完整初稿。

新稿保留来源、模型、参考资料、技能、耗时和可获得的用量记录。人工编辑后仍保留来源历史，不能据此自动标记“已人工核验”。

对既有文章的 AI 修改以段落/内容块形成提案；文字显示内部差异，样式显示属性差异，图片显示替换或位置变化。用户可部分接受，一次应用作为一个可撤销动作并保存版本。

提案绑定基础版本与工作副本 hash。冲突时保留提案与当前稿，不模糊覆盖；过期提案可查看、复制或重新生成，不直接消失。

不绑定全局 Enter 为“接受全部”。输入框、中文 IME 和正常换行优先；接受按钮获得焦点时使用正常按钮键盘行为。其他快捷键须独立评估并验证 composition 状态。

### 4.4 上下文与授权

默认范围为当前文章、明确选区、用户钉选稿件、当前公众号检索结果、启用的技能/品牌。调用时显示上下文范围；新增参考资料会改变实际发送范围。

“同供应商不再提示”只减少重复提示，不能解释为授权发送整个资料库。跨公众号读取、批量写入与删除须有明确范围；删除进入回收站，永久删除由用户直接操作。

## 5. 文档与数据架构决策门

### DOC-00：先验证词汇表，再冻结格式

状态：本期采用结构化 JSON（ADR-018），Markdown 只作投影。已有比较仅覆盖未扩展的旧 Markdown 转换器和 JSON 保存，不是两套完整原型的全面比较；复杂粘贴/真实来源及长文样本仍待补验，见[DOC-00 边界](../v3.0/DOC-00-两路线样本对比.md)。

首期共同词汇表至少包括段落、标题、列表、引用、加粗/斜体/链接、分隔线、真实图片和图注；同时验证字号、颜色、行距、段距、对齐与图片尺寸等正式版本必需属性。

用相同样本比较两条路线：

| 路线 | 验证内容 | 主要代价 |
| --- | --- | --- |
| Markdown 规范值＋受控扩展 | 样式/图片属性、稳定引用、未知模块能否保存和往返 | 新语法及版本、解析/校验、源码模式可理解性、Opaque 块的 AI 可编辑范围 |
| 结构化文档规范值＋Markdown 投影 | 现有生成/提案/规则如何适配，旧稿是否能按需接入 | 领域模型调整、迁移和兼容层、稳定节点 ID 与投影策略 |

选择门槛：完成粘贴、编辑、保存、重开、撤销、源模式/投影及交付的样本比较；列出丢失内容、实现成本和限制，形成 ADR 后进入正式格式开发。不同时维护两份可独立修改的正文。

结构化文档不要求模型直接重写整份 JSON；模型可产生针对稳定块的文本操作。Markdown 加属性/directive/HTML 块也属于需维护的格式扩展，不作为“无需文档改造”的捷径。

### 5.1 文章独立与适配层

- 普通文章拥有稳定 document/article ID，不依赖 jobId。
- 普通草稿、新稿和旧任务文章统一索引，通过来源映射适配已有数据。
- 不为打开手动编辑器制造假生产任务。
- 工作草稿自动保存与稳定版本分离；缺模型、缺栏目或无生成记录不影响手动保存。
- 旧 job_id RPC 保留兼容入口；新编辑操作按文章身份及公众号权限校验。

### 5.2 建议实体与依赖

| 实体/领域 | 主要职责 |
| --- | --- |
| 文章索引/来源映射 | document ID、公众号归属、legacy job/draft来源、可选系列信息 |
| 工作副本/文章版本 | 当前编辑内容、schema版本、base/hash、正文/样式/图片引用快照 |
| 资源与文章资源引用 | 原图、hash、来源；文章内顺序/裁切/图注/排列单独保存 |
| 生成运行与输出关联 | 状态、模型/技能/上下文快照、成本、独立新稿/变体关联 |
| 修改提案与决定 | 基础版本、操作范围、部分接受、冲突、撤销身份 |
| 收藏与会话元数据 | URL、标题、作用域；不将 Cookie 复制进普通收藏记录 |
| 人工发布记录 | 用户登记身份、链接、时间、交付版本；明确“用户登记”与自动核验的区别 |

表名和 schema 在 DOC-00/适配 ADR 后定稿，复用现有版本、提案和资源模块，不在报告阶段创建平行数据真相。

最小浏览器采用当前公众号的隔离会话，普通外部网页不能获得本地 IPC、preload 或文件访问能力。弹窗/登录需明确处理；无法内嵌的网站可在系统浏览器打开。下载暂存记录原始来源，切号不改变下载归属。

首期收藏按公众号保存。全局收藏、标签页分组、历史与完整会话恢复后置；全局收藏即便加入，也只共享地址，不共享登录态。

### P1：Agent 深入编辑

- 当前公众号历史检索与可选系列上下文；全文索引先复用/评估已有检索，不默认重建。

- 模型初次配置先提供一个供应商、一个模型/Key的简单路径，角色路由保留高级入口。托管模型服务不作为本地优先版本的默认前提。

若 P0 仅作为受限验证版，可以暂不完成文章内助手；首个承诺“工作台＋Agent”的正式版本必须包含已有文章的可用局部辅助链路，不能只保留整篇生成按钮。

## 7. 导入、未知模块和交付兼容策略

粘贴默认提供“适配当前样式”和“仅保留文字”。导入报告说明段落/图片数量、无法获取的图片、被映射或未支持的结构；转换到仅文字作为一个可撤销动作。

复杂 HTML 必须在被编辑器过滤前捕获必要原文。原始副本、可编辑内容和隔离预览分别管理；RawBlock 目前仅保留文本，不作为现成的可渲染 HTML 岛。任何增强均需处理脚本、外链资源、图片引用和输出清洗，并验证实际交付。

保留原始 HTML、Word 文件或原公众号模块，不代表其视觉与交互能够原样粘贴回微信。不支持的模块提供只读原件查看、明确的降级或替换选项；转静态图也必须由用户知晓。

DOCX 文件导入与从 Word 复制粘贴分别验收。Tiptap 所引用的 DOCX 转换扩展涉及订阅、JWT 和转换服务，不能默认当作纯本地导入；本地实现方案先以样本评估结构、图片与样式损失。

图片/导入资料保存来源 URL、原始文件信息及用户提供的权利说明；来源记录不自动等于使用许可。禁止因浏览器下载自动替换正文图片。

## 8. 历史迁移与代码功能退场

1. 备份与恢复点：先验证副本、hash和可恢复性，迁移使用版本化步骤及 dry-run。
2. 索引适配优先：旧任务文章和手动草稿通过映射出现在统一索引，不批量重写正文。
3. 旧图位：有有效选用资源时解析为实际图片；缺失时显示占位和待处理项，不伪造图片。
4. 历史执行：RunOutput、代码引用、运行记录与截图作为只读历史证据保留。旧代码任务停止接续执行，提供“复制为新文章”继续写作的路径。
5. 执行关闭须覆盖 UI、工具注册、RPC、队列和恢复入口；隐藏按钮不能作为验收完成。
6. 审批保留基础版本和hash。新编辑产生新版本，旧结论标记为针对旧版，不迁移为新版已批准。
7. ICE 账号保留自身品牌/技能、系列和期号；普通新文章不伪造默认教学栏目，不强制ICE固定结构。
8. 原浏览器会话保留或明确提示重新登录；不得为统一会话模型跨公众号复制 Cookie。
9. 用户实际发布过的版本只读关联；后续改稿不回写历史发布快照。

删除旧表、清理旧文件和取消历史字段不是本次退场的默认步骤；只有在引用审计、备份与单独清理需求明确后另行设计。
