# v0.6：正文版本、HTML 预览与工作台备份

日期：2026-10-02。依据上一级 `开发文档/ICE-Loop-Agent-开发设计文档.md` v1.1 的 T08、T15、T16 本地维护部分，以及用户后续明确的多公众号与手动 TapNow 工作方式。

## 使用入口

双击项目 `start-desktop.cmd`。如果正在运行旧版，请保存内容后关闭并重新启动。

### 正文版本

完成写作的文章进入「版本历史」，可以查看 AI 初稿、回填证据后的正文、已确认标题稿、手动编辑与恢复记录。列表每项显示时间、字符数和与当前正文是否一致。

选一个版本，下面显示「历史版本 → 当前正文」逐行差异；红色 `−` 是历史稿的行，绿色 `+` 是当前稿的行。可以展开历史全文，再点「恢复这份正文」。历史列表单独滚动，便于同时阅读差异。

恢复会新增记录、保留恢复前正文；不会删除配图、旧运行记录、模型调用或原审核记录。恢复后的文章标记为待复检，点击「复检与导出」重新检查结构、标题、事实门禁、代码/输出证据和图位完整性。这里没有重新调用付费模型做语义审稿。若恢复的早期标题与已确认标题不同，复检阻断；可以在 Markdown 编辑器恢复已确认标题，再保存复检。若源码或真实输出变化，运行证据检查也会阻断，不能沿用旧记录宣称验证通过。

保存和恢复都带当前正文 SHA256，其他窗口/请求更新正文后，旧请求被拒绝并保留当前数据。其他公众号、其他文章和损坏版本无法恢复。未完成审核或持有执行租约的任务不能编辑/恢复。

### HTML 阅读与排版预览

文章工作区新增「HTML 排版预览」，文章包新增 `04-阅读与排版预览.html`，与原有 00–03、`code/`、`images/` 同时导出。

HTML 离线读取文章包内已审核图片，缺图保留明确占位，草稿包顶部显示待办提示。标题、段落、标题层级、引用、列表、强调和代码可阅读；支持普通 HTTP/HTTPS 来源链接，禁原始 HTML 脚本与任意远程图片。品牌色取当前文章冻结的规则快照；不把正文和代码中的颜色字符串替换为主题色。

点击入口会在系统默认浏览器打开文件。它用于阅读和人工排版参考，尚未提供微信富文本剪贴板导出，也不替代公众号后台排版/手机预览。当前 Markdown 渲染器不支持全部扩展语法；复杂表格等格式请以 Markdown 和正式排版工具为准。

外部修改 HTML 后，再导出会触发原有文件哈希冲突保护；打开入口也检查预览文件是否与清单一致。普通编辑或恢复后的预览在「复检与导出」后刷新，打开已有文章包不会自动覆盖你的外部修改。

### 全公众号备份

侧边栏「备份与恢复」→「选择位置并备份」。先等待任务停止，保存位置须在工作数据/文章输出目录之外，使用 C 盘之外的数据盘。默认建议项目 `backups/`。

包含所有公众号的配置、业务数据库、正文版本、草稿、已索引历史/发布进度、托管图片、任务/运行证据、截图及导出文章目录。历史任务冻结的旧输出目录也列入备份。SQLite 用一致性备份 API 生成独立快照，不直接复制正在使用的数据库文件。

排除 OS 加密的 `credentials.json`、API Key 值、登录会话、Electron/浏览器缓存和日志；外部只读存稿目录不复制，其已索引正文快照和发布记录保留在数据库。备份是本地 ZIP 文件，包含你自己的文章和素材，不自动上传到任何平台。

文件清单逐项记录 SHA256 与大小。读取上限为 10000 文件、单文件 128MB、总数据约 1GB；超过上限会报错，不保存不完整备份。拒绝链接/目录联接、路径穿越、重复文件、Windows 特殊路径与不符合清单的内容。

### 恢复与切换

1. 「选择备份包」：检查文件完整性，查看日期、应用版本、公众号列表、文件数。
2. 「恢复到新工作目录」：选一个数据盘父文件夹，程序新建 `ice-restored-…` 子目录；不覆盖当前数据。
3. 校验通过才提交恢复目录。数据库和配置中的托管路径迁移到新目录，正文/运行输出文本不改写；每项登记资产和运行 artifact 再校验。
4. 原目录继续保留；界面提示恢复完成后，保存当前工作，关闭并重新打开程序。下次启动使用恢复目录中的 `runtime/`。
5. 重新配置模型 Key、测试模型/识图连接；在「公众号与品牌」重新关联外部只读存稿目录。TapNow 登录仍由用户在网站完成。

切换记录位于项目 `.desktop-data-path.json`，只保存新的运行目录路径，无凭据。显式设置 `ICE_DESKTOP_RUNTIME` 的开发/测试启动优先使用环境变量，恢复不会自动覆盖该变量。若需回到旧工作台，可关闭程序后把此文件移到旁边保留，再启动；默认使用原 `.desktop-runtime/`。旧目录与恢复目录彼此独立。

被查看之后更换/修改的 ZIP 会因整体哈希不一致被拒绝；所有验证/迁移在旁边临时目录执行，成功才切换。恢复保留 operations 的提交/未知状态，不自动重发生图；执行中的任务变成暂停状态。缺失或损坏的托管资产/证据会阻断恢复，而不是得到一个看似成功的残缺工作台。

此版本实现数据备份迁移，不等于已完成另一台干净 Windows 机器的安装包验收。当前恢复支持本应用备份 schema 1；没有声明任意未来版本都能向旧版回迁。

## 实现与验证

- `ice_agent/revisions.py`：版本范围、哈希、逐行 diff、事务保存/恢复。
- `ice_agent/export/html_preview.py`：无脚本的离线 HTML；`exporter.py` 纳入原导出清单。
- `ice_agent/backup.py`：SQLite backup、ZIP 清单、包校验、路径迁移、托管绑定校验、原子恢复。
- `desktop/renderer/maintenance.js`：版本和备份页面；主进程负责原生选文件、选目录和下次启动路径。
- `tests/test_maintenance*.py`：并发/范围/损坏保护、HTML 与完整文章运行/图片的恢复回归。
- Electron 原生隐藏窗口：四审核门、三段真实运行、截图、版本对比/恢复、HTML 实际加载、双公众号 ZIP 与恢复后的独立 sidecar 启动。

本轮验证结果与截图见 `desktop-v0.6-validation.json` 和 `screenshots/v0.6/`；全量测试记录在 `.test-tmp/v0.6-python-regression.log`。验证使用隔离测试目录和明确的离线模型，不使用用户的模型 Key，也没有提交 TapNow 生图。

全量 154 项 Python 回归通过（159.338 秒）；最后增加「托管资源缺失不能保存不完整备份」与包内引用校验后，15 项维护专项通过（32.949 秒），总计覆盖 155 项独立 Python 用例。Node 20 项通过，Python 编译与本轮 JS 语法检查通过。原生文件选择对话框未自动操作；备份与恢复通过主进程请求真实 sidecar 验证，恢复后的 sidecar 独立进程已启动。
