# ICE Loop Agent 优化记录

开发基准：《ICE-Loop-Agent-开发设计文档》v1.1（2026-10-01）。
本文记录初始开发完成后按用户要求执行的两轮优化，每轮均以全量回归测试收口。

---

## 初始开发（v0.1.0）

**范围**：设计文档 §19 引擎侧核心——规则引擎、国内模型适配层、代码执行
worker、操作账本、14 节点工作流（三个人工审核门）、00-03 文件契约导出、
CLI 与离线 Mock 通道。

**收口状态**：
- 离线端到端 demo（PY/005《for 和 while：让电脑替你重复干活》）全流程跑通；
- 三段演示代码（for_demo / guess_while / multiplication_table）在本机
  Python 3.12 真实执行，exit=0，输出经 integrate_evidence 回填正文；
- 初版测试 66 个全部通过。

**开发中修复的主要缺陷**（均发生在初版收口前）：
1. `subprocess` 超时分支向 bytes 字面量写入中文导致 SyntaxError；
2. 路由层引用 `adapter.adapter`（实为 `adapter_id`）属性错误；
3. 审核阶段摘要尚未生成被误判为「摘要 0 字」阻断 → 摘要在标题工坊后
   生成，改为 info 级提示；
4. Mock 修订节点回显占位文本污染正文 → 改为回显待审原文；
5. **asset_plan 审核门死循环**：审批 payload 内含每次重入新生成的
   `slot_id`，内容 hash 永不匹配，审核门无限重建。修复为「审批 payload
   确定性（不含易变 ID），slot_id 批准后物化」，并在引擎层加
   `_MAX_GATE_RETRIES=5` 熔断（GATE_LOOP）防御同类问题。

## 第二轮优化（就绪闭环与发布链路补全）

| # | 优化项 | 内容 | 动机 |
|---|---|---|---|
| 1 | `import-asset` 命令 | 按图号导入实截/生图文件：魔数校验（PNG/JPEG/WebP，HTML 错误页被拒）→ 登记候选 → 采纳并绑定 slot | 2026-09-29 用户分工：用户自行截图/生图，程序负责校验与登记 |
| 2 | `finalize` 命令 + `engine.refinalize` | 手动资产导入后重跑 final_check 与 export（绕过步骤复用），readiness 可从 assets_pending → ready_for_publish | §21.2 草稿包/就绪包的真实分界 |
| 3 | 正文占位符→图片引用映射 | 就绪导出时 `![图N：说明](待配图：…)` 替换为 `![图N：说明](images/figure-0N.png)`，未就绪图位保留占位符；图片复制入包 | 发布可用性 |
| 4 | 00-阅读入口图片状态 | 显示已就绪图片数量，待办只列未就绪图位 | 验收可读性 |
| 5 | 新增 3 个闭环测试 | 全导入→ready；非图片文件导入被拒；部分导入保持草稿（正文仍含占位符） | 闭环行为锁定 |

**回归**：69/69 通过。

**CLI 闭环实测**（真实命令序列，非测试桩）：
`demo → import-asset ×4 → finalize`：
复检阻断 0 项，readiness=ready_for_publish，4 张图入包，
正文 4 处占位符全部替换为 images/ 引用，articles 列表显示
`1 PY/005 [ready_for_publish] for 和 while：让电脑替你重复干活`。
