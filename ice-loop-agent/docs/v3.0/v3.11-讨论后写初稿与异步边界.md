# v3.11 讨论后一键写初稿；异步操作的文章/公众号边界（2026-11-08）

## 讨论 → 写初稿（用户建议）

在助手里讨论选题、角度和结构后，**最新一条讨论回复下方**会出现“写初稿”卡片：

- 点 **写初稿**：自动以“初稿”模式发送一条说明，让助手根据以上讨论结果写完整初稿。说明里要求：讨论中确定的内容直接采用，不再重复提问；不确定处按合理默认处理，并简要说明取舍。
- 点 **加点要求** 可补充篇幅、小标题数量、结尾形式等（500 字内，Ctrl+Enter 发送）。
- 生成后和平常一样出现候选稿，由你决定“存为文章”。
- 显示条件：最新一条、已完成、讨论模式、没有待回答问题的助手回复。不在初稿回复、失败回复或历史翻页里显示，生成中按钮不可点。
- 发送走原有的投递通道（防重复、可恢复、失败保留），会话历史照常作为上下文，没有新增后端接口或改发送契约。

文件：`features/chat/DraftFromDiscussion.tsx`、`features/chat/draftRequest.ts`（显示条件与发送文字）、`ChatPane.tsx`、`conversation.css`。测试：`desktop/tests/draft-from-discussion.test.cjs`。

## 异步操作边界（开发报告 §10 第 2 项）

第32轮修复了“粘贴/拖入图片”批次的归属问题。本轮把同样的规则推广到其余异步链：

> 记下发起时的公众号和编辑器；等待（选文件、渲染、转换、RPC）结束后，仍是同一篇文章、同一个公众号才写回正文或跳转页面。已发出的请求不伪称取消：资源仍保存在原公众号，只是不再写进已离开的正文。

| 链路 | 处理 |
|---|---|
| 插入图片（系统选择框） | 请求显式带发起时的公众号；选择期间离开文章或切号，不插回正文；切号后不弹旧错误 |
| 多图（连续选两张） | 每次选择后检查；中途离开即停止 |
| SVG 转图 | 显式带原公众号；渲染完成时已离开则不插入 |
| 网页/Word 粘贴转换、“仅保留文字”重转 | 显式带原公众号；返回时已离开则不插入、不弹错误 |
| 替换图片、多图“添加图片”、裁切/压缩替换 | 编辑器已销毁时不再更新节点 |
| 另选封面 | 选择期间离开文章或切号，不写入封面 |
| AI 助手采纳/撤销 | 请求返回时已离开这篇或切号：服务端已保存，重新打开可见，不写入其他正文 |
| Word 导入 | 导入归属发起时的公众号；期间切号只提示“已导入到原公众号”；期间打开了别的文章则不抢页面，提示里给“打开” |
| AI 起草（快速/引导） | 显式带原公众号；引导式在切号后不在新公众号里打开会话；起草完成提示里的“打开”会核对公众号 |

未改后端。导出图文包和导出长图沿用主进程的目录授权：切号时授权会被清空，迟到的导出请求会被拒绝。

## 本地验收

1. 助手中用“讨论”模式聊几轮 → 最新回复下出现“写初稿”→ 点击后生成候选稿 → “存为文章”。
2. 再试“加点要求”：填“1200 字、3 个小标题”后写初稿。
3. 有待回答的提问框时，不出现“写初稿”；答完后的讨论回复下出现。
4. 异步：点“插入图片”打开选择框，在选择框打开期间（或选好后立刻）切到另一篇文章 → 图片不应出现在新文章里。
5. 异步：导入一个较大的 .docx，导入期间切换公众号 → 提示“已导入到原公众号”，当前页面不变。
