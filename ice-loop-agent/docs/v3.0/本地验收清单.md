# v3.0 本地验收清单

当前联调分支：`codex/v3-workspace-first-2026-11-05`，已保留 Claude 和此前 Skills/规划改动。不要再从旧基线覆盖文件。最新自动检查见[联调记录](联调验收与修复-2026-11-05.md)，以下原生/真实平台步骤仍需执行。

## 1. 构建与自动测试

```powershell
cd desktop\ui;  npm run typecheck;  npm run build        # 当前 Linux 已通过，Windows 仍需复验
cd ..;          npm test                                  # node --test tests/*.test.cjs
cd ..;          python -m unittest discover -s tests       # 期望与基线一致；tests/test_v3_documents.py 全部通过
```

历史执行回归在 `tests/__init__.py` 中显式打开 `ICE_LEGACY_CODE_EXECUTION=1`；v3 退场用例单独关闭。不要在正常启动环境设置此测试开关。缺 Electron/Windows PowerShell 的专项不可用浏览器测试替代。

## 2. 手动流程（不配置模型也能完成）

1. 启动后默认进入「文章」页。左侧导航为「文章 / 助手 / 网页」三个入口，设置在底部。
2. 新建空白文章：输入标题和正文。顶部状态应依次显示“即将自动保存”“已保存”。关闭再打开应用，内容仍在。
3. 工具栏逐项检查：标题级别、加粗、斜体、下划线、删除线、颜色、局部字号、四种对齐、列表、引用、代码块、分隔线、链接、撤销和重做。
4. 插入图片三种方式：工具栏「图片」、粘贴截图、拖入文件。检查图注、宽度（100/80/60/40%）、对齐、替换和删除。
5. 「排版」：修改品牌色、字号、行距、段距，编辑区应立即变化。
6. 「版本」：保存一个版本，继续修改后恢复到它。确认恢复前的内容被自动保存为一个版本，可以再恢复回来。
7. 冲突：用两个窗口（或开发者工具中两个标签）编辑同一篇文章，后保存的一方应看到冲突横幅。分别测试“覆盖”和“另存为新文章”两个选项。
8. 粘贴导入：分别从公众号文章网页、普通网页和 Word 复制，用首页「粘贴导入」新建文章。核对导入报告（缺图、原件、已移除项），再测试“改为仅保留文字 / 恢复适配样式”。
   - 重开后从「版本 → 导入报告与原件」查看完整原件（作为文本展示，不执行）。从原件重建须确认，转换前的内容保留为版本。
   - 复杂模块内的图片也应列为缺图；不自动加载外链图片，不把未归档图片算成完整图文包。
9. 旧稿：首页的「旧稿件」中，打开一篇旧草稿和一篇旧任务。确认原草稿、原任务内容不变，同一篇旧稿再次打开不会重复生成新文章。

## 3. 交付与发布（含 B-05）

1. 「交付与发布」：预览应与编辑区一致，问题清单中点击某条会定位到对应的块。
2. **B-05**：点击「复制到公众号」后粘贴到公众号后台编辑器。逐项记录：
   - 标题与小标题的样式、颜色、局部字号、对齐、引用、列表、代码块、表格（按 HTML 交付时）、链接
   - **图片是否随粘贴进入**；大图使用的是缩小副本
   - 手机预览效果
3. 「导出图文包」：检查目录中的 `图片/01-…`（应为原图）、`正文预览.html`、`正文.txt`、`正文.md`、`manifest.json`。按编号手动上传图片，记录后台对图片格式、大小、像素的实际限制。
4. 发布后「登记一次发布」，填写链接和时间。继续改稿，确认版本列表中已登记的版本仍标为“已登记发布”，其他版本不受影响。

## 4. 网页与收藏

- 「网页」入口：默认收藏为微信公众平台和 TapNow。
  - 在地址栏输入任意 https 网址应能打开。
  - 测试“收藏此页”、删除收藏、恢复默认收藏、在系统浏览器打开。
- 切换公众号后：收藏列表和登录状态都应独立，不共享 Cookie。
- 远程页面不能访问本地文件或应用功能（沿用 v1.1 的边界测试）。

## 5. 代码执行退场

- 打开一个含代码块的旧任务继续运行，应失败，并提示改用“复制为新文章”。
- 历史运行记录和截图仍可查看。
- 新工作台「查看原任务」是只读页，不出现正文保存、提案应用或运行按钮；旧编辑器未成版的工作草稿仍可查看、另存为文章。
- 已完成旧任务也不能通过自动队列生成新的终端截图或触发重新终检。
- 经典界面中的执行按钮点击后应提示退场。
- 新文章中的历史运行输出显示为只读徽标，交付时省略。

## 6. AI 起草（需要模型）

- 首页「AI 起草」提交后，界面停留在原处，列表中出现“生成中”的文章。完成后它自动变成 AI 初稿。
- 断网或使用错误的 Key 时，应显示“生成失败”，不能显示为完成。
- 生成 B 期间继续编辑 A：不能丢稿或抢焦点。当前 UI 中，B 的生成占位页不提供正文编辑；“生成期间占位稿被另一客户端修改，结果另存不覆盖”已由后端并发用例覆盖，不能声称已走过同篇前端编辑旅程。
- 助手中的候选稿点击「存为文章」后，同一候选只会生成一篇文章。

## 7. 文章内助手（P1-01，需要模型）

- 选中段落 → 改写/扩写/压缩/改语气：结果先成提案，正文不变；勾选部分采纳后只改勾选处。
- 采纳后 Ctrl+Z 一步撤回整次采纳；“撤销本次采纳”在之后没再改时可用；版本历史出现“采纳 AI 修改前”和“采纳 AI ……（x/y 处）”。
- 提案生成期间改动对应段落：该处显示“已过期”，不能勾选，不会覆盖新稿。
- 图位建议：不需选中，插入的是待配图位，交付前仍需补图。
- 错误 Key/断网：提案显示失败原因，可重试；重启应用后“生成中”的提案显示为中断。

## 8. 参考稿与系列前情（P1-02）

- 助手面板“检索旧稿”：多个词用空格分开，结果只来自当前公众号且不含正在编辑的这篇；钉选最多 3 篇，重开文章仍在。
- 有系列的文章可勾选“带上系列前情”；提案卡上显示“参考：「…」、系列前情 N 期”。

## 9. 模型快速设置（P1）

- “模型与 Key”顶部的快速设置：选供应商 → 粘贴 Key → “保存并测试”，四步依次打勾；展开“高级设置”，文字分工全部指向该模型。
- 错误 Key：前三步打勾、测试失败；改对后再点一次通过。

## 10. 起草方式与两版对照（P1，需要模型）

- 快速生成不应再停下来提问；勾选“两个版本”后列表出现版本 A/B，编辑器“对照另一版”可看到另一版全文，“保留”后另一版进回收站。
- 引导式：跳到助手、出现提问框，答完生成候选稿，“存为文章”。

## 11. 图片与 Word 导入（P1）

- 图片“裁切/压缩”另存新图、原图不变、Ctrl+Z 可换回；“来源”可记录链接与权利说明，处理后的图继承来源。
- “Word 导入”一份含标题/列表/图片/表格/批注的 .docx：结构正确，提示列出未导入项；“版本”中可看导入报告与原件，并可切换“仅保留文字”。

## 12. 左栏“正在编辑”与主题/组件（v3.8）

- 打开文章时左栏顶部有封面卡片、保存状态和最近版本；点版本会打开编辑器的版本侧栏。
- 四个主题在编辑器和手机预览里都有变化；“简洁”的复制结果和以前一样。
- 插入“提示卡片”“多图”（2/3 列），复制到公众号后台，确认底色和并排效果被保留（需要真机）。

## 13. 批量整理、发布日历、建议管理、素材库（v3.9）

- 多选文章后，设系列、排期、移入回收站、恢复都能执行；混入不可处理的文章时整批不改。
- 日历显示计划（蓝）和已登记发布（绿）；“排期”后点某一天即可设置。
- “待处理建议”汇总各篇未处理的 AI 提案，“去处理”会直接打开助手。
- 素材库可以打标签、按标签筛选、插入正文。

## 14. 长图切片与 SVG（v3.10，需要桌面应用）

- 导出长图：新目录里有长图.png、切片/、manifest.json，切点落在段落之间。
- 插入 SVG：正文出现 PNG，来源显示“SVG 转图”。
