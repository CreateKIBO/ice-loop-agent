## 1. 构建与自动测试

在工程根使用已有依赖环境；每条命令单独运行并记录退出码，上一条失败时先处理，不把后续成功掩盖为整组通过。

```powershell
npm --prefix desktop/ui run typecheck
npm --prefix desktop/ui run build
npm --prefix desktop/ui run check:bundle
npm --prefix desktop test
python -m unittest tests.test_v3_documents tests.test_v3_assist tests.test_v3_generation tests.test_v3_images tests.test_v3_docx tests.test_v3_components tests.test_v3_ops tests.test_v3_longimage tests.test_v3_compat tests.test_v3_perf tests.test_v3_trial tests.test_v3_delete tests.test_v3_skill_packages tests.test_v3_skill_scope tests.test_v3_conversation_skills tests.test_v3_list_cache tests.test_v3_skill_files tests.test_v3_skill_conflicts tests.test_v3_field_report tests.test_v3_wechat_drafts tests.test_writing_skills
```

需要全量后端回归时使用 `python -m unittest discover -s tests -t .`，确保以 `tests` 包导入并执行测试初始化。缺 Java、字体、网络或平台能力时逐项登记，不能笼统写“全量通过”。Linux 本轮解释器为现有 `.test-tmp/cont-opt-python/bin/python`；Windows 使用本机已有环境，不照抄 Linux 路径。

历史执行回归在 `tests/__init__.py` 中显式打开 `ICE_LEGACY_CODE_EXECUTION=1`；v3 退场用例单独关闭。不要在正常启动环境设置此测试开关。缺 Electron/Windows PowerShell 的专项不可用浏览器测试替代。

## 2. 手动流程（不配置模型也能完成）

1. 启动后默认进入「文章」页。左侧导航为「文章 / 助手 / 网页」三个入口，设置在底部。
2. 新建空白文章：输入标题和正文。顶部状态应依次显示“即将自动保存”“已保存”。关闭再打开应用，内容仍在。
3. 工具栏逐项检查：标题级别、加粗、斜体、下划线、删除线、颜色、局部字号、四种对齐、列表、引用、代码块、分隔线、链接、撤销和重做。
4. 插入图片三种方式：工具栏「图片」、粘贴截图、拖入文件。检查图注、宽度（100/80/60/40%）、对齐、替换和删除。慢速读取/导入时切号或返回列表：不得向新号导入，不继续剩余批次，不向已离开的正文插图；已发出请求完成后资源仍归原号。文件选择对话框/SVG/封面替换需另做原生检查。
5. 「一键排版」（侧栏「排版」）：修改品牌色、字号、行距、段距，编辑区应立即变化。
6. 「历史版本」（侧栏「版本」）：保存一个版本，继续修改后恢复到它。确认恢复前的内容被自动保存为一个版本，可以再恢复回来。
7. 冲突：用两个窗口（或开发者工具中两个标签）编辑同一篇文章，后保存的一方应看到冲突横幅。分别测试“覆盖”和“另存为新文章”两个选项。
8. 粘贴导入：分别从公众号文章网页、普通网页和 Word 复制，用首页「粘贴导入」新建文章。核对导入报告（缺图、原件、已移除项），再测试“改为仅保留文字 / 恢复适配样式”。
   - 重开后从「版本 → 导入报告与原件」查看完整原件（作为文本展示，不执行）。从原件重建须确认，转换前的内容保留为版本。
   - 复杂模块内的图片也应列为缺图；不自动加载外链图片，不把未归档图片算成完整图文包。
9. 旧稿：首页的「旧稿件」中，打开一篇旧草稿和一篇旧任务。确认原草稿、原任务内容不变，同一篇旧稿再次打开不会重复生成新文章。

## 3. 交付与发布（含 B-05）

1. 「手机预览与交付」（侧栏「交付与发布」）：预览应与编辑区一致，问题清单中点击某条会定位到对应的块。
2. **B-05**：点击「复制到公众号」后粘贴到公众号后台编辑器。逐项记录：
   - 标题与小标题的样式、颜色、局部字号、对齐、引用、列表、代码块、表格（按 HTML 交付时）、链接
   - **图片是否随粘贴进入**；大图使用的是缩小副本
   - 手机预览效果
3. 「导出图文包」：检查目录中的 `图片/01-…`（应为原图）、`正文预览.html`、`正文.txt`、`正文.md`、`manifest.json`。按编号手动上传图片，记录后台对图片格式、大小、像素的实际限制。
4. 发布后「登记一次发布」，填写链接和时间。继续改稿，确认版本列表中已登记的版本仍标为“已登记发布”，其他版本不受影响。

## 4. 网页与收藏

- 「网页」入口：默认收藏为微信公众平台和 TapNow。
  - 在地址栏输入任意 https 网址应能打开。
  - 测试“收藏此页”、删除收藏、恢复默认收藏、在系统浏览器打开。
- 切换公众号后：收藏列表和登录状态都应独立，不共享 Cookie。
- 远程页面不能访问本地文件或应用功能（沿用 v1.1 的边界测试）。

## 5. 代码执行退场

- 打开一个含代码块的旧任务继续运行，应失败，并提示改用“复制为新文章”。
- 历史运行记录和截图仍可查看。
- 新工作台「查看原任务」是只读页，不出现正文保存、提案应用或运行按钮；旧编辑器未成版的工作草稿仍可查看、另存为文章。
- 已完成旧任务也不能通过自动队列生成新的终端截图或触发重新终检。
- 经典界面中的执行按钮点击后应提示退场。
- 新文章中的历史运行输出显示为只读徽标，交付时省略。

## 6. AI 起草（需要模型）

- 首页「AI 起草」提交后，界面停留在原处，列表中出现“生成中”的文章。完成后它自动变成 AI 初稿。
- 断网或使用错误的 Key 时，应显示“生成失败”，不能显示为完成。
- 生成 B 期间继续编辑 A：不能丢稿或抢焦点。当前 UI 中，B 的生成占位页不提供正文编辑；“生成期间占位稿被另一客户端修改，结果另存不覆盖”已由后端并发用例覆盖，不能声称已走过同篇前端编辑旅程。
- 助手中的候选稿点击「存为文章」后，同一候选只会生成一篇文章。

## 7. 文章内助手（P1-01，需要模型）

- 选中段落 → 改写/扩写/压缩/改语气：结果先成提案，正文不变；勾选部分采纳后只改勾选处。
- 采纳后 Ctrl+Z 一步撤回整次采纳；“撤销本次采纳”在之后没再改时可用；版本历史出现“采纳 AI 修改前”和“采纳 AI ……（x/y 处）”。
- 提案生成期间改动对应段落的文字、颜色、对齐或链接：未保存时也应显示“已过期”，不能勾选；图位建议锚点被改写也不能套用。旧提案无完整快照时仅有严格文字校验，不能承诺检测历史格式变化。
- 图位建议：不需选中，插入的是待配图位，交付前仍需补图。
- 错误 Key/断网：提案显示失败原因，可重试；重启应用后“生成中”的提案显示为中断。

## 8. 参考稿与系列前情（P1-02）

- 助手面板“检索旧稿”：多个词用空格分开，结果只来自当前公众号且不含正在编辑的这篇；钉选最多 3 篇，重开文章仍在。
- 有系列的文章可勾选“带上系列前情”；提案卡上显示“参考：「…」、系列前情 N 期”。

## 9. 模型快速设置（P1）

- “模型与 Key”顶部的快速设置：选供应商 → 粘贴 Key → “保存并测试”，四步依次打勾；展开“高级设置”，文字分工全部指向该模型。
- 错误 Key：前三步打勾、测试失败；改对后再点一次通过。

## 10. 起草方式与两版对照（P1，需要模型）

- 快速生成不应再停下来提问；勾选“两个版本”后列表出现版本 A/B，编辑器“对照另一版”可看到另一版全文，“保留”后另一版进回收站。
- 引导式：跳到助手、出现提问框，答完生成候选稿，“存为文章”。

## 11. 图片与 Word 导入（P1）

- 图片“裁切/压缩”另存新图、原图不变、Ctrl+Z 可换回；“来源”可记录链接与权利说明，处理后的图继承来源。
- “Word 导入”一份含标题/列表/图片/表格/批注的 .docx：结构正确，提示列出未导入项；“版本”中可看导入报告与原件，并可切换“仅保留文字”。

## 12. 左栏“正在编辑”与主题/组件（v3.8）

- 打开文章时左栏顶部有封面卡片、保存状态和最近版本；点版本会打开编辑器的版本侧栏。
- 四个主题在编辑器和手机预览里都有变化；“简洁”的复制结果和以前一样。
- 插入“提示卡片”“多图”（2/3 列），复制到公众号后台，确认底色和并排效果被保留（需要真机）。

## 13. 批量整理、发布日历、建议管理、素材库（v3.9）

- 多选文章后，设系列、排期、移入回收站、恢复都能执行；混入不可处理的文章时整批不改。
- 日历显示计划（蓝）和已登记发布（绿）；“排期”后点某一天即可设置。
- “待处理建议”汇总各篇未处理的 AI 提案，“去处理”会直接打开助手。
- 素材库可以打标签、按标签筛选、插入正文。

## 14. 长图切片与 SVG（v3.10，需要桌面应用）

- 导出长图：新目录里有长图.png、切片/、manifest.json，检查长图及所有切片边缘。算法只在目标切点附近寻找较空白行，不能保证段落/长图片完整；连续色块或高图样本须记录实际断点。长图本身不记为可用于发布登记的交付，须另行复制或导出图文包。
- 插入 SVG：正文出现 PNG，来源显示“SVG 转图”。

## 15. 讨论后写初稿与异步边界（v3.11）

- 助手“讨论”几轮后，最新回复下出现“写初稿”；点击生成候选稿。“加点要求”可补充篇幅、结构；有待回答问题时不显示。
- 选择框打开期间切到别的文章或公众号：插入图片、多图、SVG、封面都不写进新页面。
- Word 导入或 AI 起草期间切公众号：提示“已在原公众号”，当前页面不变。
- 运行 `node --test desktop/tests/draft-from-discussion.test.cjs` 与 `node desktop/tests/documents-browser.cjs`。

## 17. 作者试用记录（v3.13）

- 首页「测试与试用工具」里的“作者试用记录”→ 开始 → 走一遍新建/粘贴/AI 局部修改/复制 → 左栏状态条计数增加；随时“记卡点”。
- 结束后复制报告：包含旅程用时、步骤次数、采纳处数/提议处数、改稿比例与卡点；不含正文，标题默认不含。
- `npm run build` 不再出现 ArticleHome 静态/动态混合导入提示。

## 18. 文章删除与回收站（v3.14）

- 左栏文章行悬停出现“删除”；编辑器顶栏右侧“删除”；首页文章行“删除”。三处都是移入回收站，提示里可“撤销”（编辑中的文章撤销后重新打开）。
- 编辑中删除：先保存再离开，回收站恢复后内容不丢。
- 首页“回收站”：单篇“永久删除”、勾选后“永久删除”、“清空回收站”，都有确认框，默认焦点在“取消”。
- 已登记发布的文章不能永久删除（按钮置灰并说明；清空回收站时保留并提示原因）；在发布记录里撤回登记后可以删除。
- 永久删除后，素材库里的图片仍在；从旧稿接入的文章删除后，旧稿重新出现在“旧稿件”。

## 19. 写作技能导入、导出与版本历史（v3.15）

- 设置 → 写作技能 →「导出」：保存为 .md；再「导入技能」选这个文件，预览里名称、字数、检查规则一致，加入后「保存设置」。
- 导入一个外部 SKILL.md（带 `allowed-tools` 等前置字段）：预览提示这些声明不生效；导入含 scripts/references 的 ZIP：列出未导入文件，脚本不运行。
- 改两次指令并保存 →「版本历史」出现 v1/v2/v3；点 v1 查看、「导出 v1」、「载入 v1 到编辑区」→ 保存后成为 v4，来源显示“恢复自 v1”。
- 「复制为新技能」→ 名称带“副本”，来源显示“复制自 …”；「恢复预装技能」→ 缺少的预装可重新加入，不会自动设为主技能。
- 移除一个技能并保存后，再从「恢复预装技能」加回：版本号接着历史往下编。
- 运行 `node desktop/tests/skills-packages-browser.cjs` 与原有 `node desktop/tests/skills-settings-browser.cjs`。

## 20. 技能组合与作用域（v3.16）

- 设置 → 写作技能：编辑某技能，把“技能类型”改为“辅助技能”→ 它从主技能单选里移到“辅助技能”复选；勾选后保存。
- 两个辅助技能对同一检查规则要求不同（如 `title_max_chars` 一个 26、一个 16）同时勾选 → 保存被拒绝并说明是哪两个、哪条规则。
- 「按系列设置」→ 添加系列（下拉里有现有文章的系列名）→ 选主技能 / 辅助技能 → 保存。
- 打开属于该系列的文章：顶栏技能标签显示系列的技能；点开 →「本篇写作技能」可改为本篇专用，预览显示每项来自本篇 / 系列 / 公众号，以及被忽略的冲突规则；「恢复沿用默认」清除本篇设置。
- AI 起草对话框「为这篇选择技能」→ 生成的文章顶栏显示所选技能，点开可看到“生成初稿时使用：…”。之后对这篇用 AI 助手，按本篇技能生效。
- 移除被系列或本篇引用的技能：系列里的引用随保存去掉；本篇引用回退到上一级并提示“已移除”。
- 运行 `node desktop/tests/skills-scope-browser.cjs`，以及 `skills-settings-browser.cjs`、`skills-packages-browser.cjs`、`documents-browser.cjs` 回归。

## 21. 会话技能（v3.17）

- 助手里打开一个会话：标题下方出现技能标签（默认显示公众号的主技能）。点开 →「本会话写作技能」→ 选主技能 / 辅助技能 →「保存本会话设置」，标签变为高亮。
- 在这个会话里发消息：回复按会话技能写作。改回「恢复沿用默认」后，再发的消息按公众号设置；之前的回复与重试不变。
- 关联了期号/系列的会话：没有会话设置时，按「写作技能 → 按系列设置」里该系列的技能。
- AI 起草选「引导式」并选了技能：助手里的这个会话标签显示所选技能，回答问题后继续写作仍用它。
- 在会话里「存为文章」：文章顶栏的本篇技能与会话一致，点开能看到“生成初稿时使用：…”。
- 运行 `node desktop/tests/skills-scope-browser.cjs`（新增会话部分）与 `reading-lifecycle-browser.cjs` 回归。

## 22. 整体优化（v3.18）

- 文章较多时（可用「性能样本」或复制多篇凑到 60 篇以上）：首页先显示 60 篇，底部「再显示」「全部显示」可用；搜索或切到回收站后回到第一批。
- 编辑一篇文章后回到首页：字数、摘要、封面立即是新的。
- 可选：`python tools/perf-v3-documents.py`，结果里 `list_documents`（200 篇，缓存后）应在 10ms 量级，`list_documents_cold` 为首次统计耗时。

## 23. 技能参考资料与示例（v3.19）

- 写作技能 → 编辑某技能 →「参考资料与示例」→「添加文件」选 .md/.txt：文件名含“范文/示例/样例”的自动标为示例（只用于写作阶段），其他为参考资料（构思/写作/审阅都用）；可改类型、勾选阶段、「查看」内容、「移除」。保存后版本号 +1。
- 导出带参考文件的技能：保存为 ZIP（SKILL.md、skill.json、references/、examples/）；再导入这个 ZIP，预览里列出“一起导入的参考文件”，加入并保存后文件、类型与阶段一致。
- 导入外部技能包：references/、examples/（或 samples/）下的文字文件一起导入；图片、脚本、超过 2 万字的文件列在“未导入”。
- 用带参考文件的技能 AI 起草或在会话里“生成初稿”：示例与参考资料生效（可对比有/无示例时的语气）；讨论模式只用“构思”阶段的资料。
- 「版本历史」载入旧版本时，参考文件随版本恢复。

## 24. 技能冲突检查（v3.20）

## 26. 同步到公众号草稿箱（v3.22）

前提：一个可以使用草稿箱接口的测试公众号；在公众号后台“设置与开发 → 基本配置”取得 AppID / AppSecret，并把本机出口 IP 加入 IP 白名单。

- 手机预览与交付 →「设置公众号接口」→ 填 AppID、AppSecret →「保存并测试连接」：成功显示“连接正常”。故意不加白名单：提示里显示需要添加的 IP。
- 一篇带图、带封面（或正文第一张图）的文章 →「同步到草稿箱」：后台草稿箱出现这篇，标题、作者、摘要、封面、正文图片顺序正确，图片清晰；记录 webp / 超过 1MB 的图片是否被转换和压缩。
- 改正文后再同步：同一篇草稿被更新（不新增），提示“已更新草稿”；图片不重复上传。
- 在后台改动这篇草稿后再同步：出现“后台草稿被修改过”，选“另建一篇草稿”或“用当前版本覆盖”。
- 在后台删除草稿后再同步：自动新建并提示。
- 同步时断网：提示“结果未知”；下次同步先请你到后台核对，再“我已核对，继续同步”。
- 同步后「登记一次发布」可用；发布仍在后台完成。
- 重启应用后不必重填 AppSecret；切换到另一个公众号时，它的接口设置是独立的。

## 28. 多图文草稿（v3.24）

- 文章首页勾选 3 篇（都保存过版本）→ 批量栏「合成多图文」→ 对话框按列表顺序列出，第一篇标“头条”；用 ↑ ↓ 调整顺序 →「同步为多图文草稿」：后台草稿箱出现一篇含 3 篇文章的草稿，顺序与对话框一致。
- 只改第 2 篇并保存版本 → 同样顺序再同步：提示“已更新多图文草稿”，后台仍是同一篇；只有第 2 篇变化。
- 某篇在工作副本里有未保存成版本的修改：对话框提示“不会带上”，同步后后台是它上一个稳定版本。
- 选中一篇没有正文图片也没指定封面的文章：该行标红，同步按钮不可用；「移出」后可以同步。
- 在后台改一下多图文里某篇的正文 → 再同步：提示后台被修改，可选“另建一篇”或“用当前版本覆盖”。
- 调换顺序后同步：新建另一篇草稿（旧草稿留在后台，需要自己删除）。
- 只选 1 篇或超过 8 篇：「合成多图文」不可用。
