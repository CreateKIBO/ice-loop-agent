## 2. 手动流程（不配置模型也能完成）

1. 启动后默认进入「文章」页。左侧导航为「文章 / 助手 / 网页」三个入口，设置在底部。
2. 新建空白文章：输入标题和正文。顶部状态应依次显示“即将自动保存”“已保存”。关闭再打开应用，内容仍在。
3. 工具栏逐项检查：标题级别、加粗、斜体、下划线、删除线、颜色、局部字号、四种对齐、列表、引用、代码块、分隔线、链接、撤销和重做。
4. 插入图片三种方式：工具栏「图片」、粘贴截图、拖入文件。检查图注、宽度（100/80/60/40%）、对齐、替换和删除。
5. 「排版」：修改品牌色、字号、行距、段距，编辑区应立即变化。
6. 「版本」：保存一个版本，继续修改后恢复到它。确认恢复前的内容被自动保存为一个版本，可以再恢复回来。
7. 冲突：用两个窗口（或开发者工具中两个标签）编辑同一篇文章，后保存的一方应看到冲突横幅。分别测试“覆盖”和“另存为新文章”两个选项。
8. 粘贴导入：分别从公众号文章网页、普通网页和 Word 复制，用首页「粘贴导入」新建文章。核对导入报告（缺图、原件、已移除项），再测试“改为仅保留文字 / 恢复适配样式”。
   - 重开后从「版本 → 导入报告与原件」查看完整原件（作为文本展示，不执行）。从原件重建须确认，转换前的内容保留为版本。
   - 复杂模块内的图片也应列为缺图；不自动加载外链图片，不把未归档图片算成完整图文包。
9. 旧稿：首页的「旧稿件」中，打开一篇旧草稿和一篇旧任务。确认原草稿、原任务内容不变，同一篇旧稿再次打开不会重复生成新文章。

## 3. 交付与发布（含 B-05）

1. 「交付与发布」：预览应与编辑区一致，问题清单中点击某条会定位到对应的块。
2. **B-05**：点击「复制到公众号」后粘贴到公众号后台编辑器。逐项记录：
   - 标题与小标题的样式、颜色、局部字号、对齐、引用、列表、代码块、表格（按 HTML 交付时）、链接
   - **图片是否随粘贴进入**；大图使用的是缩小副本
   - 手机预览效果
3. 「导出图文包」：检查目录中的 `图片/01-…`（应为原图）、`正文预览.html`、`正文.txt`、`正文.md`、`manifest.json`。按编号手动上传图片，记录后台对图片格式、大小、像素的实际限制。
4. 发布后「登记一次发布」，填写链接和时间。继续改稿，确认版本列表中已登记的版本仍标为“已登记发布”，其他版本不受影响。

## 4. 网页与收藏

- 「网页」入口：默认收藏为微信公众平台和 TapNow。
  - 在地址栏输入任意 https 网址应能打开。
  - 测试“收藏此页”、删除收藏、恢复默认收藏、在系统浏览器打开。
- 切换公众号后：收藏列表和登录状态都应独立，不共享 Cookie。
- 远程页面不能访问本地文件或应用功能（沿用 v1.1 的边界测试）。

## 5. 代码执行退场

- 打开一个含代码块的旧任务继续运行，应失败，并提示改用“复制为新文章”。
- 历史运行记录和截图仍可查看。
- 新工作台「查看原任务」是只读页，不出现正文保存、提案应用或运行按钮；旧编辑器未成版的工作草稿仍可查看、另存为文章。
- 已完成旧任务也不能通过自动队列生成新的终端截图或触发重新终检。
- 经典界面中的执行按钮点击后应提示退场。
- 新文章中的历史运行输出显示为只读徽标，交付时省略。

## 6. AI 起草（需要模型）

- 首页「AI 起草」提交后，界面停留在原处，列表中出现“生成中”的文章。完成后它自动变成 AI 初稿。
- 断网或使用错误的 Key 时，应显示“生成失败”，不能显示为完成。
- 生成 B 期间继续编辑 A：不能丢稿或抢焦点。当前 UI 中，B 的生成占位页不提供正文编辑；“生成期间占位稿被另一客户端修改，结果另存不覆盖”已由后端并发用例覆盖，不能声称已走过同篇前端编辑旅程。
- 助手中的候选稿点击「存为文章」后，同一候选只会生成一篇文章。
