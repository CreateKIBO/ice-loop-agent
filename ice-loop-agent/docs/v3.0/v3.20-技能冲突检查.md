# v3.20 技能冲突检查（2026-11-08）

v3.16 只能发现**结构化检查规则**之间的冲突，比如两个辅助技能的 `title_max_chars` 不同。指令文字里互相矛盾的要求，比如一个技能要“用第一人称讲述”、另一个写“不要用第一人称”，系统看不出来；生成时模型只能二选一，结果不稳定。这一轮补上指令文字的冲突检查。

## 两种检查

| | 规则检查 | AI 深入检查 |
|---|---|---|
| 触发 | 「检查冲突」；本篇/本会话技能预览里自动显示 | 「AI 深入检查」，手动 |
| 速度与成本 | 本地、即时、不调用模型 | 调用一次写作模型（`writer` 路由，单次不重试），按模型计费 |
| 覆盖 | 明确的说法：叙述人称、语气、表情符号、段落长短、结尾引导关注、小标题编号、英文术语、开头提问、篇幅；以及指令与检查规则不一致（标题字数、字数区间、小标题编号） | 语义层面的矛盾，例如“开门见山给结论”与“先铺垫故事再揭晓” |
| 可信度 | 只认明确说法，宁可漏报也不误报；否定句（“不要用第一人称”）按否定处理 | 结果附原句；原句在技能里找不到时标注“请自行核对” |

两种检查都**只给提示**：不修改技能，也不阻止保存或生成。结构化规则冲突仍按 v3.16 的方式拒绝保存。

## 在哪里看到

- **写作技能设置**：主技能 / 辅助技能列表下方有「冲突检查」。检查的是编辑中的公众号组合（主技能 + 勾选的辅助技能），未保存的修改也算。每条冲突列出方面、各自的技能与原句，以及一句建议（例如“两个技能要求相反；建议删掉其中一处，或让主技能写明以哪条为准”）。同一技能自相矛盾时单独说明。
- **本篇 / 本会话写作技能**（文章顶栏、会话标签）：预览里有冲突时显示“指令可能冲突”，按当前选择实时计算。

预装的“通用写作”“ICE 写作方法”与它们的检查规则之间没有冲突，测试里固定了这一点，避免误报。

## 接口

| 方法 | 说明 |
|---|---|
| `skills.check_conflicts` `{skills?}` | 不传时检查已保存的公众号组合；传 `skills: [{id, name, instructions, kind, rules}]`（1–6 个，主技能在前）时检查草稿组合 |
| `skills.check_conflicts_ai` `{skills?}` | 同上，调用一次模型；在后台线程池执行，不阻塞界面 |
| `skills.resolve` | 新增 `text_conflicts` |
