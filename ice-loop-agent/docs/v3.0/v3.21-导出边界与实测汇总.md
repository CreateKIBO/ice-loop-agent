# v3.21 导出期间的切换边界与实测汇总（2026-11-08）

开发报告 §10 的下一轮四项是：真实微信交付、保存与异步操作边界、长文多图性能、真实作者试用。第 1、3、4 项需要在真机上做；第 2 项还剩“导出目录选择期间切文章、切号、关闭”没有覆盖（Codex 第 32 轮记录）。这一轮做两件事：

1. 补上剩余的异步边界：导出图文包、导出长图、恢复版本、从原件重新转换。
2. 为真机实测准备记录表和自动汇总工具，让实测结果按开发报告 §9 的证据要求留档。

## 1. 异步边界

| 操作 | 之前 | 现在 |
|---|---|---|
| 导出图文包：选目录期间离开 / 切号 | 选完目录照常导出；请求按**当时**的公众号发出 | 开始时记下文章、版本和公众号；选完目录发现已离开就不导出，并撤销这次目录批准 |
| 导出图文包：导出进行中离开 | 结果写回已卸载的面板；当前页面可能弹出“图文包已导出”，看不出是哪篇 | 请求明确带原公众号；完成后只提示“「标题」的图文包已导出”和文件位置，不写当前页面；已完成的导出保留目录批准 |
| 导出长图 | 同上 | 同上（“「标题」的长图已导出”） |
| 恢复历史版本 / 从原件重新转换 | 保存后才发请求，期间切号会按新公众号发出；完成后调用已离开编辑器的重新加载 | 保存后先确认还在原文章原公众号，再发请求（带原公众号）；完成后若已离开，只提示结果并刷新原公众号的列表 |
| 失败提示 | 离开后仍可能弹出旧操作的错误 | 离开后不再弹出旧操作的错误 |

选目录用的是系统对话框，桌面应用里打开时主窗口不可操作；上面的检查主要防住“对话框关闭的同一瞬间切换”和以后改成非模态的情况。已经发出的导出请求不会被假装取消：它会在原公众号完成，文件留在你选的目录。

## 2. 实测记录与自动汇总

- **[实测记录表](实测记录-2026-11.md)**：环境登记、自动检查、五条端到端旅程、真实微信三段记录（含逐张图片）、异步边界矩阵、性能三次测量、真实模型对 v3.4–v3.20 新功能的确认、Word 样本损失、作者访谈、问题清单与各方面结论。
- **`tools/field-report.py`**：把程序能读到的记录汇总成一份 Markdown。

```powershell
python tools/field-report.py --runtime <数据目录> --perf 结果.json --out 实测汇总.md
```

| 汇总内容 | 来源 |
|---|---|
| 源码 HEAD / 分支、系统、Python、数据库版本 | git、运行环境、`PRAGMA user_version` |
| 每个公众号的文章、回收站、AI 初稿、版本、交付、发布登记、提案数量 | 数据库 |
| 写作技能组合、版本数、参考文件数、系列设置数 | 写作技能设置 |
| 全部“微信兼容测试稿”的 18 项 × 三段结果与统计 | 侧栏“兼容记录” |
| 最近一次作者试用报告 | “作者试用记录” |
| 性能结果（可传多份对比） | `tools/perf-v3-documents.py --out` |

- 先用 SQLite 备份接口把 `app.db` 复制到临时目录，再在副本上读取。原库不会被迁移或修改，应用开着也能运行。
- 报告不含正文、密钥、提示词或模型输出。
- 没有执行的兼容项显示“未验”，不计为通过。
