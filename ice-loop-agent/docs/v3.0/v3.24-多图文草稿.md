# v3.24 多图文草稿（2026-11-08）

v3.22 的“尚未做”中的多图文：把 2–8 篇文章按顺序合成**一篇**公众号草稿，第一篇为头条。与单篇同步一样，**只写草稿箱，不发布、不群发**。

## 怎么用

文章首页勾选 2–8 篇 → 批量栏「合成多图文」→ 对话框：

- 默认按列表顺序排列，第一篇标“头条”；↑ ↓ 调整顺序，「移出」去掉某篇。
- 每行显示这篇会用哪个稳定版本；不能同步的原因（没有稳定版本、有阻断问题、没有封面、标题超长、在生成中）标红，同步按钮不可用。
- 工作副本里还有未保存成版本的修改时提示“不会带上”：多图文只用**最近的稳定版本**，不替作者保存工作副本。
- 「同步为多图文草稿」/「更新多图文草稿」。成功后每篇文章各写一条交付记录（`wechat-draft:<草稿ID>#<位置>`），之后可分别登记发布。

公众号接口在对话框里也能设置（与单篇同步共用同一份 AppID / AppSecret）。

## 一组文章怎样算“同一篇草稿”

公众号的草稿更新接口一次只能按位置改一篇，**不能增删篇目、不能调整顺序**。所以：

- 同样的文章、同样的顺序 → 更新原来那篇草稿，**只更新版本变了的位置**（选“覆盖”时每个位置都写一遍）。
- 换了顺序或增减了文章 → 新建一篇草稿。旧草稿留在后台，不需要时请作者自己删除（应用不调用删除接口）。

## 安全边界（与单篇一致）

- **后台改动**：更新前回读整篇草稿，逐个位置比对上次同步后的正文指纹；后台改过正文、或篇目数变了，就停下让作者选“另建一篇”或“用当前版本覆盖”。篇目数变了时无法按位置覆盖，“覆盖”会另建一篇并说明。
- **检查后版本变了**：对话框把检查时的版本一并提交；某篇在这之后保存了新版本，就拒绝同步并请作者重新检查，避免同步了没看过的内容。
- **结果未知**：写入前记操作日志（`group:<组标识>`）。超时等结果未知时，下次同步先请作者到后台核对。
- **中途失败**：逐篇更新时某一篇失败，已更新的位置照样记下（含回读的后台指纹），再报错说明第几篇没成功；重试时只补没成功的位置，不会把已更新的误判为后台改动。
- 同步期间锁住这一组和组内每篇文章，避免同时被单篇同步或另一组同步写入。
- 图片按“公众号 + AppID + 图片哈希”复用，多篇共用的图只上传一次。
