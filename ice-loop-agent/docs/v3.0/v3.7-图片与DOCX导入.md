# v3.7 图片裁切压缩、来源展示与 Word 文件导入（P1，2026-11-06）

对应开发报告 P1：“图片裁切/压缩增强，来源展示；DOCX 文件导入在本地转换路线评估后接入。”以及第 7 节：“图片/导入资料保存来源 URL、原始文件信息及用户提供的权利说明；来源记录不自动等于使用许可。”

## 图片

正文图片的工具条新增两项：

- **裁切/压缩**：选比例（自由、16:9、4:3、1:1、3:4、2.35:1）或在图上拖动框选；可设最大宽度（1920/1280/1080/720 或保持原尺寸）、格式（保持原格式 / JPEG / PNG）和 JPEG 质量（50–95）。点“生成并替换”后：
  - 结果另存为一张新图片并替换到正文，**原图不变**，仍在素材库；Ctrl+Z 可换回原图。
  - 透明 PNG 转 JPEG 时铺白底；读取时按 EXIF 方向摆正。
  - 新图记录“处理自哪张图、做了什么”，并继承原图的来源链接和权利说明。
- **来源**：显示获取方式（本地文件 / 剪贴板截图 / 从网页或文档粘贴 / Word 文件 / 裁切压缩生成 / 素材库）、原文件名、导入时间、处理记录和当前尺寸；可填写来源链接（仅 http/https）和权利说明（200 字内）。填写过的图片显示“来源✓”。对话框写明“来源记录不等于使用许可”。

后端：`documents.image_edit`、`documents.image_source_update`；`image_view` 返回 `source`。

## Word（.docx）导入

**路线评估**：报告指出 Tiptap 的 DOCX 转换扩展依赖订阅、JWT 和云端转换服务，不能当作纯本地导入。这里选择不引入新依赖的本地路线：用标准库读取 .docx（zip + XML），转成受限 HTML，再复用已有粘贴导入管线（同一套清洗、样式映射、图片导入和导入报告）。

- 首页新增 **Word 导入**：选 .docx 文件（≤20MB），在本机转换，不上传任何服务。
- **支持**：
  - 标题：按样式名识别 Heading/标题 1–3/Title，中文 Word 的“标题 1”也能识别。
  - 段落：对齐、首行缩进。
  - 文字样式：加粗、斜体、下划线、删除线、文字颜色、高亮/底纹。
  - 超链接：只保留 http/https/mailto。
  - 列表：按 numbering.xml 区分有序和无序；换行和制表符保留。
  - 内嵌图片：PNG/JPEG/GIF/BMP/WebP/TIFF，来源记为“Word 文件”。
  - 表格：保留为只读原件块，交付按原件处理。
- **修订**：按“接受全部修订后”的正文读取，删除的文字不会进入正文。
- **不支持**：批注、文本框、页眉页脚、脚注、公式、图表/SmartArt、EMF/WMF 矢量图。遇到时写入导入报告的“未导入”清单，导入完成的提示里也会列出。
- **原件**：原 .docx 另存在运行目录 `imports/<公众号>/<sha256>.docx`；转换出的 HTML 作为导入原件保存，可以在“版本”里查看，或切换为“仅保留文字”重新转换。
- **安全**：拒绝带 DOCTYPE/实体声明的 XML，限制解压总量（200MB）和图片数量（200 张）；旧版 .doc 会提示先另存为 .docx。
- 主进程只把 `documents.import_docx` 的请求上限放宽到 30MB（其余 documents.* 仍为 6MB）。

## 本地验收

1. 正文插入一张大图 → “裁切/压缩” → 16:9、1080px、JPEG 80 → 替换后尺寸和大小变小；Ctrl+Z 回到原图；素材库里两张都在。
2. “来源”填写链接与权利说明 → 再打开显示“来源✓”；对处理后的图打开“来源”，应显示“处理自另一张原图”并带着同样的链接。
3. 用一份带标题、列表、图片、表格、批注的 .docx 做“Word 导入”：检查结构与图片；提示里列出未导入的批注；“版本”里能看到导入报告与原件，并能切换“仅保留文字”。
4. 选一个 .doc 或改名的非 docx 文件 → 应提示格式不支持。
