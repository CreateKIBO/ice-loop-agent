# v3.3 提问框修复：讨论模式也能逐题作答（2026-11-06）

## 问题

用户测试反馈：看不到提问框；助手仍把问题一次全部列在回复里，需要下一轮自己打字回答。

## 原因

v3.1 的提问框只读取消息元数据中的结构化 `questions`，但结构化输出只在初稿/改稿/配图模式下启用。助手默认是**讨论模式**，输出纯文本，提问只是正文里的编号列表，元数据中没有 `questions`，所以提问框从不出现。

## 改动

- **讨论模式提问协议**（`creative_chat.py`）：系统提示要求模型在需要确认信息时，先用一两句说明原因，再在回复最后附一个 ```` ```ice-questions ```` 代码块。块内是 JSON 数组，格式与结构化模式相同（短标签、选项及说明、多选）。引擎收到后：
  - 把它转为结构化问题，进入等待作答状态；
  - 把代码块从正文中移除，不让用户看到 JSON；
  - 生成过程中，界面也会隐藏尚未收完的代码块。
- **兜底识别**：如果模型没有按约定输出代码块，但回复末尾是 2–4 条以问号结尾的编号问题，并且前文带有明确的提问用语（“请确认/想先了解/以下问题”等），同样转为提问框。
  - 括号或冒号后用“/”“、”“还是”分隔的内容，会识别为选项，例如“（零基础/有一定基础）”“轻松还是严肃”。
  - 普通讨论里的反问不会被误判，有测试覆盖。
- **问题只出现一次**：
  - 带问题的回复气泡只显示说明文字（`metadata.reply_intro`）。
  - 对话流中只保留一个“请在下方提问框中逐题回答”的提示按钮，点击后聚焦到提问框。
  - 问题本身只在输入框上方的提问框中出现。提问框顶部加了蓝色强调边，更容易注意到。
- **存储兼容**：消息正文仍保留问题清单，供下一轮对话的上下文使用。旧消息照常显示。

## 本地验收

1. `cd desktop\ui && npm run typecheck && npm run build`
2. 在“助手”中直接发一句信息不足的需求（讨论模式即可），例如“想写一篇 if-elif-else 的入门文章，先帮我理一下”。逐项确认：
   - 回复气泡只有一两句说明；
   - 对话中出现“请在下方提问框中逐题回答”；
   - 输入框上方出现提问框，可以逐题选择或填写，最后提交。
3. 提交后，助手应按你的回答继续。
