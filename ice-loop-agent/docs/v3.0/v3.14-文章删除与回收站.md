# v3.14 文章删除与回收站（2026-11-08）

试用反馈：“文章没有删除按钮。”原来只有首页文章行上一个半透明的“删除”，左栏和编辑器里都没有；回收站只能恢复，不能真正删掉。

## 改了什么

| 位置 | 操作 | 说明 |
|---|---|---|
| 左栏“最近文章” | 悬停行尾出现 **删除** | 移入回收站；AI 初稿生成中的文章不显示 |
| 编辑器顶栏右侧 | **删除** | 先保存当前修改，再移入回收站并回到首页 |
| 首页文章行 | **删除**（红字，常显） | 同上；生成中置灰 |
| 首页回收站 · 行 | **恢复** / **永久删除** | 已登记发布的置灰，悬停说明原因 |
| 首页回收站 · 批量栏 | 勾选后 **恢复** / **永久删除**；**清空回收站** | 都要在确认框里再点一次 |

移入回收站后，提示条里有 **撤销**：恢复文章；如果是在编辑器里删的，撤销后重新打开它。

## 永久删除的规则

后端新增 `documents.delete_forever`（渲染层白名单已加入）：参数 `document_ids`（≤200）或 `all_trashed: true`。

- 只删回收站里的文章；正常文章传进来会留在原处并返回原因。
- 一起删除：文章记录、工作副本、全部历史版本、导入原件、交付记录、AI 修改提案、已撤回的发布登记。
- **保留并说明原因**（不报错，其余照删）：
  - 已登记发布（有效发布登记）——发布历史只读保留（开发报告 §8 第 9 条）；在发布记录里撤回登记后才能删。
  - AI 初稿仍在生成、或 AI 助手仍在生成修改建议——避免后台结果写回已删除的文章。
- 不属于当前公众号的 id：整批拒绝、整批不改。
- **不删图片**：图片属于公众号素材库，可能被其他文章引用。
- 从旧稿/旧任务接入的文章删除后，旧数据本来就没动过，会重新出现在“旧稿件”里，可以再次接入。
- 试用记录里的历史事件不受影响（报告按 id 查不到标题时不显示标题）。

前端在删除成功后清掉这篇文章的本地恢复缓存和已缓存的查询，并刷新文章列表、日历、待处理建议和两版对照。
