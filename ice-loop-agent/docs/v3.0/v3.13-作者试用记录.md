# v3.13 作者试用记录（开发报告 §10 第 4 项，2026-11-08）

报告第 4 项要求：“邀请非 ICE 作者走完手动与局部 AI 链路，记录卡点与改稿成本；再决定更多模板、组合 Skills 或自动发布的范围。”这一轮在应用里加了**本地、手动开启**的试用记录，让试用结果可以量化、可以对比。

## 用法

1. 文章首页 **作者试用记录** → 填试用名称（可选）→ **开始记录**。可勾选“报告中包含文章标题”，默认不含。
2. 作者照常使用。左栏底部出现红点状态条“作者试用记录中 · N 条”，随时可点 **记卡点**，写下哪里看不懂、找不到、等太久或不得不绕路。会附带当前位置：首页、编辑器或助手。
3. 结束时点 **结束记录** → **复制报告**（Markdown）。以往的试用也能再次复制报告。

## 记录什么、不记什么

- 只有在“开始记录”之后、“结束记录”之前才记录，按公众号隔离，只保存在本机数据库（迁移 v25：`trial_sessions`、`trial_events`）。
- 自动记录这些步骤的**类型、时间和数量**：
  - 新建文章、粘贴导入（含编辑器内粘贴）、Word 导入
  - AI 起草（快速 / 引导，两版数）
  - AI 局部修改的发起、采纳（采纳几处 / 共几处 / 过期几处）、放弃、撤销
  - 保存版本、恢复历史版本、复制到公众号或纯文本、导出图文包、登记发布
- **不记**正文、提示词、模型输出或图片。事件里只允许数字、布尔值和短标识。标题只在勾选后才进入报告。
- 记录是旁路：写入失败不会影响正常操作。

## 报告内容

| 部分 | 说明 |
|---|---|
| 关键旅程 | 开始到第一篇文章、到第一次交付（复制/导出）、到登记发布、总时长（分钟） |
| 各步骤次数 | 上面每类步骤的次数 |
| AI 局部修改 | 发起、采纳、放弃、撤销次数，以及“采纳处数 / 提议处数” |
| AI 初稿到交付的改稿量 | 对出现过 AI 生成内容的文章：取最早的 AI 版本，和最近一次交付的版本比较（没交付时和当前稿比较）。按段落对齐，给出保留段落数、改动字数 ÷ AI 字数、改稿比例（上限 100%）。只统计数量，不保存文字 |
| 卡点 | 时间、位置和作者写的说明 |

说明：只用过 AI 局部修改的文章，“最早的 AI 版本”是第一次采纳后的版本，里面已经有作者自己的内容，因此只能近似反映采纳之后又改了多少。

## 其他改动

- **修复构建提示“ArticleHome 静态/动态混合导入”**（Codex 第 31/32 轮记录）：左栏、发布日历、待处理建议、两版对照原来都静态引用文章首页模块，使它没法按需加载。现在共用的 `openDocument` / `createBlankDocument` 移到了 `features/documents/documentNav.ts`。为兼容旧引用，`ArticleHome` 仍转出这两个函数。

## 验证

- `python -m unittest tests.test_v3_trial`：5 项通过，覆盖：
  - 未开始不记录、开始后各步骤入账、结束后不再记录；
  - 报告不含正文；标题默认不含、勾选后才含；
  - AI 改稿量（4 段 AI 文本改为 3 段，保留 2 段）、采纳数提取；
  - 参数校验与公众号隔离。
- 迁移夹具与恢复点测试已同步到 v25。全部相关后端模块共 199 项，唯一失败的是需要真实网络的 `test_real_compatible_http_stream…`，这次改动前就会失败；没有未关闭连接告警。
- `workbench-boundaries`、`doc-perf`、`draft-from-discussion` 的 Node 测试通过；改动文件做了桩类型检查、esbuild 语法检查和表单可访问名称检查。
- 构建提示是否消失，需要在本机 `npm run build` 确认。

## 本地验收

1. 首页“作者试用记录”→ 开始 → 新建一篇、粘贴一段、发起一次 AI 改写并只采纳一部分、复制到公众号 → 左栏状态条计数增加。
2. 随时“记卡点”写一句 → 结束记录 → 复制报告：报告里应有旅程用时、次数、“采纳处数/提议处数”和卡点，**不应**出现正文。
3. `cd desktop/ui && npm run build`：不再出现 ArticleHome 静态/动态混合导入的提示。
