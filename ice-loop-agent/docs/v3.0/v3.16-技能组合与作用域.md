# v3.16 写作技能组合与作用域（2026-11-08）

继续开发报告 §6 SK-00 与《可插拔技能系统》方案 §3、§6：

- “基础写作方法、主要文风与辅助能力可以组合；两个互相排斥的主要文风应提示选择。”
- “默认选择顺序：本次明确选择 → 本篇绑定 → 栏目绑定 → 公众号绑定。”
- “结构化字段按明确作用域解析，同层冲突展示来源/值供用户裁定；不能仅按导入时间最后一项覆盖。”
- “文章页面显示‘本篇使用：…’。”

## 两种技能

| 类型 | 用途 | 每篇可用 |
|---|---|---|
| 主技能 | 完整的写作方法（读者、结构、语气、检查规则） | 一个，或不用 |
| 辅助技能 | 可叠加的局部方法，例如标题策略、审阅清单、品牌排版说明 | 最多 5 个 |

在“写作技能”里编辑某个技能，用“技能类型”切换。已有技能都是主技能。导出的 Markdown 带 `kind: main|addon`，再导入时保留类型。

## 三层作用域

按 **本篇 → 系列 → 公众号** 逐项解析，主技能和辅助技能分开计算。例如系列只改了主技能，辅助技能仍沿用公众号设置。

| 层 | 在哪里设置 | 存在哪里 |
|---|---|---|
| 公众号 | 写作技能：主技能单选 + 辅助技能复选 | `writing_skill_settings`（`active_skill_id`、`active_addon_ids`） |
| 系列 | 写作技能 →「按系列设置」，系列名可从现有文章里选 | 同上（`series_bindings`） |
| 本篇 | 编辑器顶栏的技能标签 → 「本篇写作技能」；或 AI 起草时「为这篇选择技能」 | 文章 `meta.skill_binding` |

每一层都可以选“沿用上一级”或“不使用主技能”。被引用的技能移除后：

- 系列和公众号里的引用在保存时自动去掉。
- 本篇的引用在解析时回退上一级，并在预览里提示“已移除”。

## 检查规则怎么合并

- 主技能的规则优先。辅助技能只补上主技能没有设置的规则，补上的规则同样进入程序化检查（例如主技能没限制标题长度，“标题策略”的 `title_max_chars: 26` 就会生效）。
- 辅助技能与主技能要求不同：按主技能，预览里列出“忽略了哪一项”。
- 两个辅助技能对同一规则要求不同：**保存被拒绝**（公众号、系列、本篇都一样），并说明是哪两个技能、哪条规则，由你取舍。只有在设置之后又修改了技能规则、旧的本篇绑定因此冲突时，才按勾选顺序取先到的，并在预览里列出。
- 提示词里一并给出主技能和辅助技能，并注明“主技能优先；辅助技能只补充主技能没有规定的方面”。没有辅助技能时，提示词与之前完全一样。

## 生效范围

| 场景 | 按什么解析 |
|---|---|
| AI 起草（快速 / 两版 / 引导） | 对话框里选的技能；没选按公众号默认。选择会存成这篇的本篇设置 |
| 文章内 AI 助手（改写、扩写、图位建议…） | 这篇文章：本篇 → 所属系列 → 公众号 |
| 助手里的普通对话 | 公众号默认（会话级选择留到后续） |
| 重试、追问后继续 | 原请求的技能快照，不受之后的修改影响 |

AI 初稿开始生成时，从会话请求快照里记下实际使用的技能名称与版本（`meta.generated_skills`，不含正文）。“本篇写作技能”对话框里显示为“生成初稿时使用：…”。

## RPC

| 方法 | 说明 |
|---|---|
| `skills.resolve` `{document_id}` 或 `{series, binding}`；可另带 `binding` 预览未保存的选择 | 生效的主技能、辅助技能、各自来自哪一层、规则数、冲突、提示 |
| `documents.skill_binding` `{document_id, binding \| null}` | 设置或清除本篇技能，返回解析结果 |
| `skills.save` 新增 `active_addon_ids`、`series_bindings`，技能新增 `kind` | 不传这两项时沿用已保存值（兼容旧界面） |
| `documents.ai_draft_start` / `ai_guided_start` 新增 `skill_binding` | 校验后用于本次生成 |
| `chat.send` 新增 `skill_selection` `{series?, binding?}` | 只影响本次写作与检查 |

数据库没有新迁移，新字段都在原有的 JSON 里。
