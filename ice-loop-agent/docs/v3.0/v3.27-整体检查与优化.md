# v3.27 整体检查与优化（2026-11-10）

这一轮没有新功能。做法是：在开发环境里把真实界面组件跑起来（见文末“这轮怎么查的”），对着渲染结果和项目自带的守护测试逐项检查，修掉发现的问题，并顺手做了几处界面整理。

## 修复的缺陷

| 问题 | 影响 | 来源 | 处理 |
|---|---|---|---|
| 正文“多图并排”的样式被覆盖 | 图组失去下方段距、布局被改成单列网格 | v3.24：多图文对话框的列表也叫 `.ice-doc-group` | 对话框的类改名为 `.ice-wxgroup*` |
| 交付侧栏横向溢出 | 380px 的侧栏里，手机预览（375px）把整列撑宽，“同步到草稿箱”按钮、预览、发布登记被裁掉一截，出现横向滚动 | v3 早期就有；v3.22 加了草稿箱一栏后更明显 | `.ice-doc-form` 的列改为 `minmax(0, 1fr)` |
| 多图文对话框里“不能同步的原因”不是红色 | 标红只有边框，原因文字是灰的，不显眼 | v3.24：`.ice-doc-danger-text` 只对按钮生效 | 原因文字单独加样式，整行浅红底 |
| 3 个表单控件没通过可访问性守护测试 | `node --test desktop/tests/ui-a11y.test.cjs` 失败 | v3.16 / v3.17 的技能选择框与“固定结尾标题” | 补上与可见文字一致的 `aria-label` |

| 微信网关 5xx 被当成确定失败 | 网关超时时草稿可能已经写入，再同步会多建一篇 | v3.22 | 5xx 与断网一样记为“结果未知”，下次同步先请作者核对；4xx 仍是确定失败 |

另外：读取图片文件后没有及时关闭文件句柄（`prepare_image`），已改。

## 界面整理

**文章首页**
- “微信兼容测试稿 / 性能样本 / 作者试用记录”收进一行“测试与试用工具”，默认收起，展开状态记在本机。原来它们占了整整一行卡片，和四种新建方式并排。
- 窄窗口（≤760px）下，新建方式从单列改成两列并收紧。原来 7 张卡片竖排约 600px 高，文章列表被挤到第一屏之外。
- 批量栏里的日期框换成和其他输入框一致的样式。
- 文章行新增 **“已同步草稿箱”** 标记：同步过草稿箱（单篇或多图文）且还没登记发布时显示。列表查询多一个 `EXISTS` 子查询，走已有索引。

**文章设置**
- 封面的两个操作放到封面图下方一行（原来挤在右侧，“改回正文第一张图”折成两行）。
- 封面裁切：标签不再带“（默认居中）”（会折行、让两个滑块错位），改为下方一句说明；调整后说明变为“已调整… 恢复默认居中”。

**草稿箱**
- 编辑器里“所在的多图文”从两三行长句改为每组一张小卡片：第几篇/共几篇、同组文章（单行省略，悬停看全）、同步时间、是否最新（绿/黄），“打开这组”在右侧。
- 多图文对话框：每行写“稳定版本 今天 10:06”；同步按钮禁用时有原因提示；说明文字之间的空隙收紧。

## 没有改的

- 配色、字号、圆角等设计变量没有动；这轮只修不一致和布局问题。深色模式没有做（界面变量已集中在 `tokens.css`，但正文区域要保持白底、几处阴影写死，需要单独一轮并在真机上看）。
- 编辑器本体（正文输入、工具栏行为）没有改：开发环境加载不了编辑器，这部分仍然只能靠你本机的 `documents-browser.cjs` 和手测。

## 这轮怎么查的

开发环境没有项目的前端依赖。这轮给 `@tanstack/react-query`、`@radix-ui/*`、`motion` 写了最小替身（只放在开发沙箱里，**不在项目里**），于是除编辑器（TipTap）以外的真实组件可以打包、在 Chromium 里运行和截图。由此：

- `wechat-browser.cjs`（v3.25 写的，当时没运行过）第一次实际运行，通过；`skills-settings`、`skills-packages`、`skills-scope` 三个浏览器测试也通过。
- 新增 `layout-browser.cjs`，覆盖这轮修的布局问题。已确认它在修复前的样式下会失败（侧栏溢出、图组样式）。
- 跑了 `desktop/tests/*.test.cjs` 里不依赖主进程文件的源码守护测试，发现并修复了 `ui-a11y` 的失败。

**局限**：替身不是真实的库，对话框焦点、动画、查询缓存的细节与真实行为有差别；这些结果不能替代你本机的运行。`documents-browser.cjs` 这轮仍未运行。
