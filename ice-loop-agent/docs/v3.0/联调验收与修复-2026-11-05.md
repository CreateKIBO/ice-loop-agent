## 已复现并修复

| 问题 | 原失败证据/影响 | 修复 |
| --- | --- | --- |
| StrictMode 保存状态不结束 | 引擎已保存，界面仍为“正在保存” | effect 每次挂载恢复 mounted 状态 |
| 返回列表绕过防抖保存 | 输入后立即返回，工作副本仍是旧标题 | 导航先 flush；保存失败/冲突保留在原页 |
| 保存中继续输入 | 导航须等待后续输入落盘 | 同一保存链持续写到当前序列；缓存修订同步更新 |
| 交付预览循环请求 | 内联回调变化触发 effect，再保存/再渲染 | 稳定 flush/revision 回调；冲突不进入交付 |
| 旧修订恢复缓存被忽略 | 上一笔保存已回执时可能遗漏下一笔未确认输入 | 缓存仍可查看/恢复；旧基线进入冲突，不覆盖新稿 |
| 标题单独修改未成版 | 交付沿用旧标题；恢复前的新标题丢失 | 未成版、检查点和恢复判断同时比较标题与正文 hash |
| 同图多次引用 | 导出预览的前图引用了最后一次编号 | 按文章块 id 映射每次图片出现，不按资源 id 合并 |
| 原件不可读/报告重开不可见 | 原始 HTML 虽留库，界面只显示 Markdown 版本 | 新增按账号与文章校验的只读原件接口；版本侧栏显示报告与完整原文；重建整篇先确认并留版本 |
| 复杂模块内图片漏报 | 原件内 img 不计数，交付可能热链并误报完整 | 计入缺图；编辑预览不加载外链；交付去除未归档图片并报告阻断项 |
| AI 重试重复建稿 | 相同 request_id 产生多篇文章 | 请求绑定唯一来源映射，重试复用；不同需求拒绝复用相同标识 |
| AI 启动竞态 | chat 受理与绑定之间的轮询误标失败 | 有界两分钟受理窗口，超时仍明确失败 |
| 版本/发布操作缺口 | 最新版本不能恢复未成版编辑；旧交付让新预览错误显示可登记 | 允许恢复最新稳定版；按当前预览 version_id 判断已交付 |
| 原任务仍能直接编辑 | 新工作台“查看原任务”仍挂载旧编辑器 | 新增只读 LegacyArticleView，保留历史输出及旧工作草稿查看/另存入口 |
| 退场仍留下截图队列 | 已完成旧任务可能被自动截图和重新终检 | 拒绝新终端截图/context/finish；队列跳过；有代码的旧任务不再接续，历史 state/图片文件保留 |
| 窄窗口与表单名称 | 420px 顶栏横向溢出；两处 select 未过守护检查 | 顶栏换行、侧栏/链接面板限宽、明确控件名称 |

## 文档决定与剩余验收

JSON 规范值沿用 Claude 的本期方案。DOC-00 证据只支持“当前未扩展的 Markdown 往返会丢失样式”；并未实现受控扩展路线，因此已修正文档，不能将其解释为 Markdown 扩展不可实现。真实稿件、复杂模块和性能证据仍不完整。

下一步按[本地验收清单](本地验收清单.md)推进：

1. Windows/Electron：首次启动、切号、关闭/重开恢复、文件选择/粘贴/拖图、系统剪贴板回读与按冻结版本登记交付。
2. B-05：真实微信后台粘贴→保存→手机预览；记录图片是否接受、实际样式与手动上传限制，不能以本地截图代替。
3. 真实模型：AI 起草完成/取消/失败、重试、后台编辑与跨号晚到结果；不得使用个人 Key 自动补测。
4. 旧账号实际副本：普通草稿/任务映射、图片和历史审批/截图可读；Windows 备份/恢复及升级路径另验。
5. 1万字/30图性能样本：先登记参照机和预算；本轮未测，不宣称达标。真实作者场景和完整 DOC-00 扩展路线比较仍未完成。
6. P1 文章内 Agent 的局部修改/提案/撤销尚未实施，不能将整个“一体化 Agent”宣传为完成。
