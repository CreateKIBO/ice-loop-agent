# v3 后续迭代规划（2026-11-08）

> 作用：在 v3.26 这个时间点，梳理“已经有什么、还缺什么证据、接下来按什么顺序做”。范围仍以[开发报告](../上线准备/工作台优先转向-开发报告-2026-11-05.md)为准：本地制作、人工发布；自动发布、群发、云端多租户另立需求。本文是建议，不是已承诺的排期。

## 2. 建议顺序

### 第一阶段：验收与稳定（建议先做，1–2 轮）

不加功能，把已有链路的证据补齐。

1. **跑完全部自动检查并登记**：`本地验收清单` 里的 Python 测试与 5 个浏览器测试（含新写、尚未运行的 `wechat-browser.cjs`），结果写进《实测记录》§1。失败的先修。
2. **真实公众号草稿箱**（v3.22–v3.25）：一篇约 2000 字 / 4 图的稿件走单篇同步；3 篇走多图文；在后台核对正文、图片、封面裁切、留言、顺序；故意在后台改一处再同步，看冲突提示。
3. **B-05 真实微信粘贴**：复制 → 后台保存 → 手机预览，逐项记录降级。
4. **长文多图性能**：用 `tools/perf-v3-documents.py` 的 1 万字 / 30 图样本在 Windows 参照机测首次可编辑、输入延迟、保存、峰值内存。v3.26 去掉了两处按键开销，正好对比。
5. **用 `tools/field-report.py` 生成一份汇总**，作为这一阶段的结论。

完成标准：《实测记录》§0–§5 填完，问题清单里没有未分级的问题。

### 第二阶段：依据实测修问题（按结果决定）

可能的方向，**只在实测指向时做**：

- 输入或保存慢 → 先看 `docPerf` 读数。可能的手段：大文档的图片节点延迟解码、正文虚拟化、保存改为增量。
- 微信粘贴降级多 → 调整交付 HTML 的样式映射；把降级写进兼容测试稿。
- 草稿接口报错 → 补错误码说明、调整图片压缩阈值。
- 作者试用卡点 → 按《作者试用记录》排序。

### 第三阶段：发布（需要你先决定）

前提：第一阶段的草稿箱真机验证通过，并且你回复了[发布授权边界草案](../上线准备/发布授权边界-方案草案-2026-11-08.md) §4 的 6 个问题。

建议第一期只做“提交发布 + 结果对账 + 自动登记”，账号开关默认关闭，每次确认绑定冻结版本。群发和定时不做。实现前先按草案 §5 核实接口事实。

### 第四阶段：设计与运营增强（P2 延续）

在前三阶段稳定后再评估，按作者试用反馈挑选：

- 更多排版主题与组件（卡片、多图并排、引用样式）；模板从“作者用过的文章”生成，而不是预制大量模板。
- 素材库跨文章管理（现在只在编辑器抽屉与首页标签里）。
- 发布日历与多图文结合：按日期组合一期多图文。
- 写作技能在真实模型下的效果评估：同一主题、不同技能组合的出稿对比。

## 3. 技术债（可穿插在任何一轮）

| 项 | 现状 | 建议 |
|---|---|---|
| `DocumentEditor.tsx` | v3.26 拆出工具栏、文章设置、粘贴报告；主体约 620 行 | 再把自动保存（`useAutosave`）、粘贴（`usePasteImport`）抽成 hook，各配单元测试 |
| `desktop_service.py` | 约 1960 行，多数路由已迁到 `application/` | 把剩余的旧路由迁走，主类只保留生命周期、调度和密钥 |
| `creative_chat.py`、`documents/service.py` | 1100–1400 行 | 按“起草 / 交付渲染 / 导入”分模块；先补测试再拆 |
| 前端类型检查 | 开发环境只能用桩类型做 `tsc`，有大量与桩相关的误报 | 在本机加一条 `npm run typecheck` 的完整检查并记录结果；开发环境只看改动文件 |
| 浏览器测试 | 5 个脚本，需本机 Chrome 与依赖 | 合并成一个入口（如 `node desktop/tests/run-browser.cjs`），一次跑完并汇总 |
| 环境相关失败 | Python 全量里 6 项依赖本机环境（Java、真实 HTTP、契约导出目录等） | 在《实测记录》§1 写清每项的原因，避免和真问题混在一起 |
| 迁移链 | 已到 v30，每次升级要改 3 个测试文件 | 把“降级到 v19 的夹具”改成按迁移元数据自动删表，减少手工维护 |
| 草稿同步的锁 | 进程内锁，只防同一进程内并发 | 单机单进程足够；若以后多窗口或多进程，需要改为数据库层的租约 |
| 备份与密钥 | 备份排除凭据文件（正确）；恢复后需重新填 AppSecret | 恢复向导里提示“公众号接口需要重新保存密钥” |

## 4. 每轮的工作约定（保持不变）

- 不自动发布、不群发；不安装依赖、不打包、不改版本号。
- 未经真机验证的不写“已完成”；文档里“未运行”“待核实”如实标出。
- 每轮：功能文档 `v3.x-*.md` + 验收清单新增一节 + README 索引；Python 全量通过（环境相关项除外）。
- 写进你工作目录前核对设备上的版本，避免覆盖你的改动。
