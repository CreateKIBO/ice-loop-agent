# v3.4 文章内助手：局部修改提案链与参考稿（P1-01/P1-02，2026-11-06）

对应开发报告 P1“Agent 深入编辑”前四条：编辑器内助手抽屉（含钉选稿与技能上下文）；局部改写、扩写、压缩、改语气、图位建议进入同一提案链；部分接受、一次撤销、过期提案保留查看；当前公众号历史检索与可选系列上下文。设计决定见 `DECISIONS.md` ADR-023。

## 用法

1. 打开文章，点右下角 **✎ AI 助手**（或侧栏“AI 助手”页签）。
2. 在正文里选中要改的段落（把光标放进某一段也可以，只改这一段），选一个操作：
   - 改写、扩写、压缩、改语气（更口语/更正式/更犀利/更温和/更有趣）、按我的要求；
   - **图位建议**不需要选中：通读全文，建议在哪些段落后插入“待配图位”。
3. 可在输入框写补充要求，点按钮（或 Ctrl+Enter）。结果作为**提案**出现在下方，生成期间可以继续编辑。
4. 每处修改显示删改对比（红色删除、绿色新增），可“定位”到正文。勾选要的，点 **采纳所选**。
5. 撤销：Ctrl+Z 一步撤回整次采纳；或在提案卡上点 **撤销本次采纳**（采纳后没再改时可用）。版本历史里也有“采纳 AI 修改前”和“采纳 AI ×× （x/y 处）”两个版本。

## 参考稿与系列前情（P1-02）

- 助手面板“参考”区点 **检索旧稿**：在当前公众号所有文章的标题和正文里检索（多个词用空格分开，需同时出现），结果显示片段、系列与是否已发布。
- 点 **钉选** 把旧稿作为参考（最多 3 篇，每篇取前 1500 字）。钉选按文章记在本机，下次打开仍在。
- 文章设置了系列时，可勾选 **带上系列前情**：附带同系列最近 5 期（优先当前期之前）的标题和 200 字摘要。
- 参考内容只读，提示模型只用于对齐文风、术语和前情衔接，不得照抄；提案卡的上下文记录里会写明用了哪些参考稿。
- 检索直接扫描现有文章存储，没有另建全文索引（报告要求“先复用/评估已有检索，不默认重建”）。文章数到数千篇时再评估 SQLite FTS。

## 规则

- 只改选中的段落、标题、列表、引用；图片、代码块、原件块不会被改写。一次最多 12 段、8000 字。
- 提案生成后如果你又改了对应段落，那一处会标为 **已过期**：仍可查看，不能勾选，采纳时也会被跳过。
- 加粗、斜体、链接会保留；文字颜色、字号、高亮等行内样式在改写后需要重新设置。
- 模型密钥错误、断网、取消、应用重启都会如实显示为失败/已取消，可以点“重试”。

## 本地验收

1. `python -m unittest tests.test_v3_assist tests.test_v3_documents`
2. `cd desktop && node --test tests/workbench-boundaries.test.cjs`
3. `cd desktop\ui && npm run typecheck && npm run build`
4. 在应用中（需已配置模型）：
   - 选中两段 → 改写 → 只勾选一处采纳 → 确认另一段未变；Ctrl+Z 一步回退。
   - 再发起一次改写，生成期间改动其中一段 → 该处显示“已过期”，采纳时被跳过。
   - 压缩三段为一段；扩写一段为多段；图位建议插入待配图位。
   - 填错模型 Key → 提案显示失败原因，可重试。
   - 检索旧稿 → 钉选 1–3 篇 → 改写，提案卡上下文记录应列出参考稿；有系列的文章勾选“带上系列前情”。
