# v3.17 会话技能（2026-11-08）

v3.16 留下的第一项：“助手里的普通对话仍按公众号默认（会话级选择留到后续）”。《可插拔技能系统》方案 §6 的选择顺序本来就是“本次明确选择 → 本篇/会话绑定 → 栏目绑定 → 公众号绑定”。这一轮把会话这一层补上。

## 用法

助手会话标题下方新增技能标签，与文章编辑器顶栏的一样。

- 默认显示当前生效的技能。设成会话专用后，标签变成蓝色。
- 点开「本会话写作技能」：选主技能（沿用 / 不使用 / 某个主技能）和辅助技能，预览里显示每项来自本会话、系列还是公众号。
- 「保存本会话设置」：之后在这个会话里发出的消息按此写作。「恢复沿用默认」：清除会话设置。
- 已有回复、进行中的回复、重试和追问后继续，都保留发出时的技能快照，不受影响。

## 解析顺序

| 优先级 | 来源 |
|---|---|
| 1 | 本次请求明确带的选择（文章 AI 起草） |
| 2 | 会话设置（新表 `conversation_skill_bindings`） |
| 3 | 会话所属系列（会话关联期号时的系列）在“按系列设置”里的技能 |
| 4 | 公众号设置 |

没有会话设置、会话也没有系列时，行为和之前完全一样（快照里不额外记作用域）。

## 与文章的衔接

- AI 起草选「引导式」并选了技能：除了用于第一条消息，还记为这个会话的会话技能，所以回答问题后继续写作、改稿时仍用它。
- 在会话里「存为文章」：
  - 会话技能带到文章上，成为本篇技能。之后对这篇文章用 AI 助手，按同样的技能。
  - 从生成这版候选稿的消息快照里读出实际使用的技能名称与版本，记为 `generated_skills`。文章的「本篇写作技能」里显示“生成初稿时使用：…”。

## 接口与数据

| 方法 | 说明 |
|---|---|
| `skills.conversation_binding` `{conversation_id, binding \| null}` | 设置或清除会话技能；会话必须属于当前公众号；校验规则与本篇相同（技能存在、类型正确、辅助技能之间规则不冲突） |
| `skills.resolve` `{conversation_id, binding?}` | 会话的生效技能预览，`context: "conversation"` |
| `chat.send` | 没带 `skill_selection` 时，按会话设置与会话系列解析 |

迁移 v27：`conversation_skill_bindings(account_id, conversation_id, binding_json, updated_at)`。会话移入回收站或恢复不影响会话设置。
