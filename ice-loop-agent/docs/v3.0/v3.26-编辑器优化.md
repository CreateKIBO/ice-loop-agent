# v3.26 编辑器优化与封面裁切保存修复（2026-11-08）

这一轮不加新功能：修一个 v3.23 的缺陷，整理最大的前端文件，并去掉编辑器每次按键时的两处多余开销。

## 缺陷修复：封面裁切没有被保存

编辑器保存时会过滤文章设置，原先**只保留非空字符串**。v3.23 新增的封面裁切（`coverCrop`）是对象，因此在编辑器里调整后会在下一次保存时被丢掉。滑块在当前会话里看起来正常，重新打开文章就回到“默认居中”，同步到草稿箱时也不会带上裁切。

后端测试直接写入设置，没有经过编辑器的这一步，所以没有发现。现在过滤规则改为：字符串去掉空值，对象型设置原样交给引擎校验（引擎的 `normalize_info` 本来就会拒绝非法值）。

> 如果你已经在 v3.23 里调过某篇的裁切，需要重新调一次。

## 优化

**工具栏按钮不再每次按键都重新挂载**。工具栏随编辑器每次变化重绘（用于更新加粗、对齐等按钮状态），原先按钮组件 `T` 和色板 `Swatches` 定义在工具栏函数内部，每次重绘都是“新组件”，React 会把约 30 个按钮全部卸载再挂载。现在移到组件外，重绘只更新属性。

**本地暂存不再每次按键都序列化整篇正文**。为崩溃恢复，编辑器把未保存的正文写进本地存储；原先每次按键都要 `getJSON()` 整篇文档再 `JSON.stringify` 写入，长文里这是按键延迟的主要来源之一。现在输入停顿 250ms 后写一次，并且：

- 页面隐藏/关闭、离开编辑器时立即补写；
- 自动保存失败时先确保暂存已写入；
- 保存成功后取消待写的暂存，避免把已保存的内容又当成“未保存的修改”提示恢复。

暂存仍早于 800ms 的自动保存，崩溃恢复的保护范围基本不变（只差输入后最初的 0.25 秒）。

**封面缩略图与裁切预览共用一次图片读取**。两者原先各自请求 `documents.image_view`；现在缩略图也走查询缓存。

## 拆分 DocumentEditor.tsx

原文件约 54KB、830 行。拆成：

| 文件 | 内容 |
|---|---|
| `DocumentEditor.tsx`（约 620 行） | 加载、编辑器实例、自动保存、粘贴、冲突、侧栏 |
| `EditorToolbar.tsx`（新） | 正文格式工具栏、按钮、色板 |
| `ArticleSettings.tsx`（新） | 文章设置（封面与裁切、摘要、原文链接、留言）、封面缩略图 |
| `PasteReportBar.tsx`（新） | 粘贴导入报告条 |
| `documentImages.ts`（新） | 选图导入 `pickDocumentImage`（编辑器与文章设置共用；`DocumentEditor` 仍导出它，旧引用不受影响） |

纯移动，没有改界面文字和交互。`LoadedEditor` 里的自动保存、粘贴逻辑还可以继续拆成 hook，见[后续迭代规划](后续迭代规划-2026-11-08.md) §3。
